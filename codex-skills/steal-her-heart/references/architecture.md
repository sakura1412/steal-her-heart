# 最高级架构原则

本文件是本项目架构规范的最高约束，适用于入口 Prompt、角色职责、扩展包、连接器、分析方法及报告模板；不替代宿主指令、用户授权或证据铁律。当前交付为 Codex Agent 的指令和资料契约，不自带执行服务。

## 原则一：核心引擎永远不绑定行业

任何可复用行业知识通过 IndustryPack 扩展。核心 Prompt 只负责理解问题、身份与范围、调度、证据与质量规则，不内置某个行业的字段、流程、专业判断或方法选择。

按实际对象及用户目标生成研究框架，IndustryPack 提供候选定义、指标、来源和专业方法约束。没有适用包时可以建立通用问题并取证；需要专业知识时，根据实际材料建立任务内候选包并记录来源、适用边界与校验，不把模型常识直接写成行业规则。尚不能支持的专业结论保留缺口，不强迫用户安装包或填写行业问卷。

新增行业只增加包资源与校验材料，不在主控增加“如果行业是某类就执行固定流程”的分支。通用实体类型、任务类型、来源日期和权限规则不是行业知识，不需要按行业复制。

## 原则二：数据采集永远不绑定平台

任何平台数据通过 Connector Interface 和 Platform Adapter 接入；Research 只提出对象、问题、所需数据与约束，消费统一结果，不直接依赖具体网站页面结构、选择器或专有字段。

当前 Codex 工具由适配条目绑定；适配可以是明确的读取策略，不要求新增程序。通用公开读取与 User Upload 也有对应的适配方式。平台专有定位和解析规则只在 Adapter 中维护，变化时报告失配，不将异常变成空结果。

统一链为 Connector Interface → Platform Adapter → Raw Data → Normalizer → 待核验 Evidence。Normalizer 保留来源、原值、实体和转换依据，Validator 决定能否采用。包配置不创建工具或扩大授权，平台接入范围须由实际调用证明。

## 原则三：分析方法永远不绑定研究流程

流程不固定执行 SWOT、五力或其他模型。研究前 Planner 可以提出候选方法及输入需求，用来规划取证，但不是强制执行清单。

Research 完成后先进行证据核查、覆盖评估和缺口分析；满足研究质量条件后，Planner 根据研究目的、实际可用数据与决策问题，从 Analysis Method Registry 选择最少且足够的方法，记录采用／不采用理由和版本，再交 Analysis 执行。

方法的必需输入不够时，返回明确缺口并按范围与投入补证；不能以换方法掩盖用户必需问题。简单问题可直接做有证据的综合判断，不为展示模型而强套框架。方法本身不改变状态、权限或范围，不自行采集；新增事实需求回到 Planner。

## 三类扩展的分工

| 资源 | 负责 | 不负责 |
|---|---|---|
| IndustryPack | 行业语义、候选问题、指标与专业约束；引用方法及来源能力 | 固定主控流程、平台访问授权 |
| Connector Adapter | 平台访问、定位、原始结果和失败语义 | 自定研究目标、把原始资料判为已验证 |
| Analysis Method | 适用问题、输入、执行规则和输出条件 | 自主扩范围、直接取证、代替质量检查 |

Comparison Engine 是涉及跨对象比较时的通用可比性与计算契约，不是对所有任务强制执行的分析模型。Market Intelligence 等研究类型决定问题范围，不创建独立引擎。新增专业方法有命名空间和版本，行业包引用它，不维护不同内容的同名副本。

## 统一执行路径

研究请求 → Competitive Intelligence Subject／范围 → 身份与动态框架 → 选用行业包与连接器 → Research → Evidence Validation → Coverage／Gap Assessment → 必要补研 → Planner 方法选择 → 需要时 Comparison Engine 准入 → Analysis → Claim 核查 → Reporter → Report QA。

发现缺口可回到相应步骤，但不丢原授权、版本、投入与成果。变更行业包、连接器或方法后检查受影响输入与结论，不能只换显示版本。未来实现技术不限，但必须保持这些边界。

## 架构验收

新增行业无需编辑核心行业分支；站点结构变化只改适配说明及对应校验；新增分析方法无需改变固定研究阶段。以上是验收要求，不能仅凭文件分开就宣称已验证。文档、实例与真实调用的完成状态分别报告。
