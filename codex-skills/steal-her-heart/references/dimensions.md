# 全行业竞品研究维度库

版本：4；2026-11-04。供 Codex 按研究对象选择维度，也可用于可选项目初始化。这是研究设计素材，不是竞品事实来源；Python 尚不自动加载本 Markdown 库。核心字段ID与 [BASE_FIELDS](https://github.com/sakura1412/steal-her-heart/blob/main/src/steal_her_heart/collection_template.py) 对齐，正式模板仍须通过现有 Schema 校验。SaaS／工具类另提供可选的 [采集指南](saas.md) 和 [机器可读推荐配置](saas.json)，Python 可显式读取该 JSON 预设，不等于自动理解或采集。

## 选择方式

默认只需竞品名，依据本次检索确认的对象、客户任务与产品／服务交付方式选择维度。用户附带目的或读者时一并采用，未提供则按通用概览研究，不要求 profile。下面组合都是建议，没有行业白名单；多业态可组合，没有匹配项可定义字段。默认单对象的常规维度无需另设确认，实质扩范围或可选项目评审才询问。

不要把所有字段一股脑加入每个项目。先选能回答分析目的的核心子集，再加专项模块；销售对照只在有我方背景且目标需要时加入。同一比较中的对象使用一致字段、定义、单位和时间范围；可选项目沿用其已确认配置。

## 分级与行业包目标（待实现）

本页 21 项是核心候选目录，15 个模块是扩展素材，不是每次必填清单。按开发仓库 `docs/product-design.md` 中的产品规则区分用户明确要求／回答目的必要的必选、相关的推荐、额外专项可选；目录推荐级别与本轮 requirement、是否选中、适用性分别记录。P0／P1／P2 排程不是必选等级。所选字段仍完整记录状态，必选缺口不能因难找降级，不适用须有依据；未选择的可选项不进入模板或触发采集。

行业包以维度、工具能力、分析规则及类型扩展组成，软件与消费品设计样例位于开发仓库 `docs/industry-pack-examples.yaml`（不包含在独立运行技能内）。同一比较口径一致，不同业态字段可不同；组合冲突先解析再锁定。Python 已可显式选择核心子集，但省略子集仍默认 21 项；本次不改变 API，也没有实现通用行业包加载器或动态推荐。

## 核心字段

| ID | 模块 | 字段 | 类型／约束 |
|---|---|---|---|
| positioning | 基本盘 | 定位 | 事实；注明官方宣称或第三方定位 |
| target_customers | 基本盘 | 目标客户／用户与使用场景 | 事实 |
| scale | 基本盘 | 规模 | 事实；口径、地区和日期要明确 |
| background | 基本盘 | 主体背景／发展历程 | 事实 |
| reference_customers | 基本盘 | 代表客户／典型使用者 | 事实；允许有理由的不适用 |
| core_offering | 产品与服务 | 核心产品、能力或服务内容 | 事实 |
| delivery_usage | 产品与服务 | 交付、使用或服务方式 | 事实 |
| offer_variants | 价格与商业模式 | 产品／服务／版本划分 | 事实 |
| prices | 价格与商业模式 | 价格／报价 | 事实；允许有理由的不适用；保留币种、地区、计费单位等条件 |
| billing | 价格与商业模式 | 计费／交易与商业模式 | 事实 |
| trial_experience | 价格与商业模式 | 试用／体验／售后政策 | 事实；允许有理由的不适用 |
| value_proposition | 竞争与市场表现 | 差异化卖点／价值主张 | 事实；官方宣称不等于效果已验证 |
| public_messaging | 竞争与市场表现 | 公开宣传／传播表述 | 事实 |
| limitations | 竞争与市场表现 | 局限与适用边界 | 推断；需有依据，未提及不等于不支持 |
| positive_reviews | 用户口碑 | 好评点 | 用户反馈；保留样本和来源边界 |
| negative_reviews | 用户口碑 | 差评点 | 用户反馈；保留样本和来源边界 |
| recurring_complaints | 用户口碑 | 高频抱怨 | 用户反馈；注明样本量和重复口径，不能由一条评价推整体 |
| recent_changes | 近期动态 | 产品／服务／经营变化 | 事实；必须约定时间窗口 |
| recent_funding | 近期动态 | 融资／资本动态 | 事实；必须约定时间窗口；可有理由不适用 |
| recent_partnerships | 近期动态 | 合作 | 事实；必须约定时间窗口 |
| recent_campaigns | 近期动态 | 营销活动 | 事实；必须约定时间窗口 |

默认单对象可从定位、目标客群、核心供给、交付方式、价格／交易模式起步，按对象加入口碑、近期动态等；简述选择后继续，不将它固定成必填列表或强制确认节点。

## 扩展模块

这些是可选模块定义，字段均可继续拆分。ID不得与核心字段重复；名称相近但口径相同的字段应去重，避免不同竞品填成不同含义。

| ID | 模块与定义 | 适用条件／比较口径 |
|---|---|---|
| workflow_coverage | 任务覆盖：客户关键任务及可完成的步骤 | 软件、服务、设备均可；按用户任务拆分，不能仅比功能数量 |
| deployment_integration | 部署、数据交换与集成方式 | 需要系统连接、实施或数据协同的项目；API只是可能子项 |
| automation_ai | 自动化或AI能力及人工边界 | 仅当客户任务与分析目的相关；声明与实际验证分开 |
| specification_performance | 规格、性能及测试条件 | 设备、硬件、材料及实体商品；单位、测试环境和型号一致 |
| quality_reliability | 质量、可靠性、维修与生命周期 | 产品或服务；说明测试、用户反馈与推断各自依据 |
| supply_availability | 供给、库存、产能或交付可用性 | 实物、制造、供应链及预约服务；注明地区、时间、口径 |
| service_coverage | 服务地区、网点与可达性 | 本地生活、零售、专业服务及售后；不要把门店数直接等同服务能力 |
| service_journey | 获客、咨询、购买、履约与售后体验 | 以服务链路为主的项目；公开流程与实际体验分开 |
| channel_distribution | 获客渠道、销售渠道与分销方式 | 消费品牌、B2B、平台或服务；没有渠道份额证据时不编比例 |
| content_campaigns | 内容主题、活动形式与促销机制 | 运营与增长目标；必须给观察时间与公开样本 |
| onboarding_retention | 新手引导、持续服务与复购动作 | 需要持续使用或重复购买的项目；不能把观察到的动作等同留存效果 |
| ecosystem_network | 供需两侧、伙伴生态与网络机制 | 平台、市场、工具生态；区分公开规模与推断的网络效应 |
| switching_cost | 替换、迁移、学习和不行动的成本 | 必须覆盖替代方案／现状路径；事实依据与分析判断分开 |
| applicable_requirements | 准入、认证或适用要求 | 仅当行业和市场相关；核对适用地区、主体、版本与原始来源 |
| financial_business_model | 收入结构、单位经济与经营模式 | 投资或商业决策；未公开数据写缺口，不用估计冒充事实 |

扩展字段默认是待定义的研究问题。生成 dimensions.md 时分别指定 fact、review 或 inference；同一模块同时有事实和判断时拆为不同字段，并保留来源引用关系。

## 按业态推荐的起点

| 业态／目标线索 | 可推荐的扩展组合 | 需要解释的取舍 |
|---|---|---|
| 软件、数字工具或企业系统 | workflow_coverage、deployment_integration、onboarding_retention；适用时采用 [SaaS 推荐组合](saas.md) | 预设提供优先级、采集问题和源提示；AI、移动端和API按任务需要选，不自动成为所有项目必填 |
| 设备、硬件、工业品、实体商品 | specification_performance、quality_reliability、supply_availability | 同型号／工况比较，避免只看宣传参数 |
| 零售、消费品牌或电商 | channel_distribution、content_campaigns、quality_reliability | 商品与渠道可以分层，价格注明规格与促销条件 |
| 本地生活、门店或专业服务 | service_coverage、service_journey、onboarding_retention | 服务流程、可达性与履约体验，不套软件版本功能表 |
| 平台、市场或生态型产品 | ecosystem_network、channel_distribution、switching_cost | 用户侧与供给侧分别定义，不能只看一侧 |
| 投资、经营判断或陌生行业 | financial_business_model＋与交付方式相关的模块 | 先明确对象和问题；不能为了凑财务表推测未公开数值 |
| 多业态或其他行业 | 相关模块组合或自定义 | 保留用户行业描述，说明新字段定义，不改内核即可扩展 |

以上都可加 applicable_requirements；只有与项目有关时加入。对销售话术目标，可另外定义我方对照、赢输场景和客户探测问题，标为需要双方证据或真实样本的分析字段，不能从未验证的核心优势直接得出胜出结论。

SaaS 推荐组合补充功能广度／任务深度、API／生态成熟度、免费与升级路径、迁移／数据锁定、版本迭代窗口和 G2／Capterra 评价采样。P0／P1／P2只表示该建议配置中的采集顺序，具体问题、比较口径与源清单见其指南；没有对应产品或无法访问评价站时保留缺口。不得把该组合应用为全行业默认，或将样本覆盖完整当作事实已经核验。

## 比较口径与可选项目确认

研究设计记录每个字段的ID、名称、定义、信息类型、适用条件和优先级；可选项目将它们写入 dimensions.md。根据字段需要补地区／单位／计费／版本／时间窗，比较条件不明确则列缺口。来源链接、获取日期、来源类型、置信度及理由逐条附着；用户反馈记录样本边界，推断引用事实依据。

用户主动选择项目模式的竞品发现时，维度草案与名单分别评审；新候选需要改字段则展示并重审受影响版本。项目草案确认不等于 Python dimensions.lock.json，现有受信评审API的名单绑定与锁检查不变。默认单对象不自动发现一批候选，也不为继续研究而伪造这些项目文件或批准。
