# 动态生成研究框架

本文件提供生成方法，不提供行业字段表或固定维度组合。每次从研究对象的实际属性和用户问题出发，形成当前任务的研究框架；行业标签只是线索，不能直接决定问题清单。

## 先理解对象，再设计问题

1. 提取用户明确给出的对象、目的、关注点、读者及约束；保留原话和未知项。未给目的时采用“理解该对象的价值与适用边界”的临时目标，不强制访谈。
2. 按 [实体管理](entities.md) 明确分析层级及稳定标识，区分公司、品牌、产品与具体版本／规格；只核验当前问题必要的市场、渠道与归属关系。通过少量实际材料核验身份，理解它解决什么问题、面向谁、如何交付价值、客户如何选择，以及哪些行业条件会改变判断。这里只探索足够支撑规划的信息，不提前全量采集。
3. 将目标转成具体决策问题：用户做完研究后需要理解或判断什么？什么证据可以改变答案？哪些差异在当前场景中有意义？
4. 从这些问题推导维度及子问题，说明必要性、比较对象与范围。维度名称、数量和深度均随任务变化，不强制覆盖固定模块。
5. 检查是否遗漏行业特有的购买、使用、履约或约束因素，是否把不相关字段带进来，是否只有容易取得的宣传信息。缺少关键背景且会改变问题解释时再追问。

行业不明确不等于必须填问卷。能够使用已知材料形成有边界的问题时继续；无法判断的前提标假设，不能把模型联想写成行业事实。

## 方法候选与最终选择

本阶段可以按问题提出 [方法候选](analysis-methods.md) 及取证需求，不能预先规定一定执行某模型。Research QA 后由 Planner 结合实际数据确定方法；涉及对比时 [可比组检查](comparison.md) 是准入条件。任务类型按 [Subject](subjects.md) 识别，市场或行业请求不强求产品名。

## 可选行业包：提供知识与方法，不替代框架

需要专业定义、指标、方法或报告结构时，按 [IndustryPack](industry-packs.md) 和 [目录](industry-pack-registry.yaml) 选择相关包。核验适用边界、版本、兼容性与依赖，再将六部分资源中的相关内容转为本次问题。记录采用／拒绝理由，允许新建包中没有的问题；不得因为存在行业包就按名称全量套入。

包内定义和方法可帮助规划，包内行业事实、基准或规则的当前适用性仍须本次取证。没有合适的包时继续动态框架，专业依据不足保留缺口。包内容或指标口径变化时更新影响记录，不默改已确认范围。

## 本次框架需要记录什么

| 框架记录项 | 作用 |
|---|---|
| 决策问题 | 明确要回答什么，关联用户目标或默认概览目标 |
| 维度／子问题 | 为本次对象生成，不能只是通用标题或关键词 |
| 选择理由 | 说明为何影响本次决策、对应哪些实际对象属性 |
| 要求等级 | 必选／推荐／可选，记录来自用户指定还是规划判断 |
| 适用性与边界 | 对哪些对象、使用端、地区、时期或情境成立；未知保持未知；所选端分别取证 |
| 观察项与比较口径 | 定义需要观察什么，必要时确定单位、类型与可比条件 |
| 证据要求 | 什么材料支持判断，如何区分宣称、反馈和效果 |
| 资料策略 | 按问题提出来源类型及当前可用能力，不默认固定站点 |
| 完成条件 | 如何判断问题已回答，缺哪些材料会阻止结论 |
| 分析与产物 | 事实如何转为判断，回应哪个读者问题或输出部分 |

这些是研究设计的共同元信息，不是每个行业都要研究的业务字段。事实、反馈和推断分开定义，工具返回格式不决定研究维度。

用户明确要求的适用维度为必选。推荐项须说明是否采用；未采用的可选项不触发采集。证据难找不是降级必选项的理由。数量由问题、模式和投入决定，不设全行业统一的字段数量。

## 对比与行业差异

多对象比较先判断是否服务于同一决策、处于明确且可比较的实体层级。引用实体及关系版本，不把公司规模当作某产品规模，不将品牌全部口碑归给某个版本。为可比对象生成共同问题和一致口径，同时保留有依据的对象专属子问题。不同交付方式可比较其对同一客户任务的影响，不强迫填同一种产品功能表，也不把不可比指标直接排名。

框架必须说明哪些比较成立、哪些只能分别分析。不同任务即使研究同一个对象，也可能生成不同维度；研究目的相同也不意味着所有行业可以套用相同问题。不得按行业名称维护自动套入的固定模板或专属 Agent。

## 框架是可修订的研究假设

范围确认统一遵循 [report-delivery.md](report-delivery.md#范围确认的触发)，保留具体范围与变更依据。

采集与 QA 发现重要因素、错误前提或缺失关系时，先区分“原问题缺证据”与“原框架缺问题”。前者补证，后者形成新框架版本，记录理由、影响问题、已有资料可复用部分及新增任务。同范围细化可继续；实质扩展范围依真实用户授权，歧义才追问。

不能删除难以回答的问题以提高覆盖率，不能用新框架掩盖旧缺口。版本变化后重新检查完整必需问题和受影响结论；纯呈现变化不重新采集。

## 框架质量自检

- 每个维度能说明它服务的决策问题吗？
- 选择理由基于本次材料或用户明确要求吗？
- 是否有只是因为“这个行业通常这样”而机械加入的字段？
- 是否遗漏会改变本次判断的行业属性或替代路径？
- 是否能说明需要什么证据、哪些情况无法得出结论？
- 是否保留用户明确关注点，并区分未知、不适用和未找到？

自检不通过先修订框架，不能把空标题清单当作完成规划。
