# 报告偏好与文件交付

本文件是汇报角色、报告详略和文件交付的单源。适用于首次分析报告与新报告请求；简短事实追问沿用当前偏好，不反复启动问卷。

编制草稿和执行 Report QA 时，按[八类报告产物](report-artifacts.md)交付并核对本次选定的图、表与建议。详略决定呈现篇幅，用户明确要求的成果保留在交付清单中。

## 一次可选提问，不阻塞研究

先判断对象或研究主题是否已给。未给时只问对象，并在同一条消息附上偏好默认值：

> 你想研究哪个产品、企业或主题？有具体要做的决定，也可以一起说。报告先按通用读者、一般版准备。

没有对象不能编造研究目标；收到对象后直接采用已说明的默认偏好继续，不再启动两轮问卷。非交互请求缺对象时返回 `missing_subject` 及需要补充的字段，不等待、不编目标。对象已给则复用已给偏好，只对缺失项发出一次可选提示：

> 这份分析要帮你做什么决定？例如选供应商、调整定价，或判断哪项能力值得投入。我先用通用读者、一般版开始。你也可以指定产品经理、销售、运营、管理层或其他读者，以及简单、一般或详细版。

按已知信息裁剪这次提示。只有名称时，优先问决定，同轮附上读者和详略默认值；只给了读者和详略时，仍可选问决定。已说“评估是否采购”就直接研究采购条件，可顺带说明采用选型视角。无需另问用户的职位。同一任务最多一次可选提示，用户要求直接开始时跳过。没有回复就按“了解对象的价值与适用边界”继续轻扫、规划和交付；非交互也使用该目标。

将用户明确的决定或临时目标写入 `research_objective`，在临时目标中注明默认依据。优先采用指定读者和详略。决策能明确提示读者视角时可将其作为工作默认值，在 `audiences.reason` 说明推断依据（如“决定下一季度优先开发什么，暂按产品规划视角”），`basis` 记为 `default`。多种角色都可能做该决定时保留通用读者，把决定直接转为研究问题。角色选项见[读者与交付](audiences.md)。

使用异步问答能力时，提出问题后即开展不依赖偏好的实体消歧和轻量扫描；预算计入本次研究。优先呈现带来源与日期的身份、已核实发现及缺口，不为展示进度编造事实。没有异步能力时，不调用会无限阻塞的问答工具；在回复中给出上述可选问题和默认值后继续。缺少研究主题必须先补主题；同名无法消歧时隔离候选并询问必要信息，不能以偏好默认替代实体确认。

| 场景 | 执行动作 |
|---|---|
| 对象已给，可交互 | 在提示默认偏好的同一轮开始取证；读者或详略未回复时采用默认值；额外竞品按下文的范围选择处理 |
| 已知非交互任务（包括调用方声明的自动化或 codex exec） | 直接采用缺失偏好的默认值，不调用等待回答的工具；对象缺失按前述 missing_subject 返回具体缺口 |
| 无异步问答能力 | 用一条可选提示说明默认值，继续执行，不发阻塞式偏好问答 |
| 用户明确要求“等我选好再开始” | 暂停依赖该偏好选择的工作；按用户实际指定的等待方式执行，不由任务配置悄悄恢复旧的强制问卷 |

默认偏好从开始即有效，`preference_timeout_seconds` 默认记录 0，未实际等待时 `deadline_at` 为 null；不声称触发过超时。显式用户值优先于任务配置，任务配置优先于缺省值。默认值是 Agent 的运行选择，不记为用户明确回答，也不代表新增对象、权限、付费或访问授权。未指定研究投入采用 Standard，与报告详略分开记录。

迟到回复仍需接纳：只改排版则复用事实重排；角色改变决策问题则评估已有证据，需要时在剩余预算和范围内补研。保留旧报告，生成新修订；不全量重采、不重置预算，也不保证未经核验的新问题立即有答案。

记录 `audiences`、`report_detail`、各自取值依据（explicit_user／task_config／default）、`interaction_mode`、`preference_timeout_seconds`、提问与实际截止时间、默认原因、`output_format`（默认 PDF）及 `ppt_requested`。没有实际计时不得伪造时间；持久化格式见 [研究台账](research-ledger.md)。

## 三种报告类型

综合报告采用[标准目录：十二章与证据附录](report-outline.md)。依照下表调整展开程度；用户指定章节或专项成果时，按其决策问题组织。

| 类型 | 内容组织 | 展开程度 |
|---|---|---|
| 简单 | 核心结论、最重要的事实／差异、关键建议、限制与来源 | 快速阅读；精简背景和过程，涉及比较时保留关键对比 |
| 一般 | 摘要、对象与范围、按目标组织的分析、相关对比、机会／风险、建议、限制与来源 | 系统说明核心问题与判断依据，适合常规业务讨论 |
| 详细 | 一般版内容，加上适用的方法与口径、逐维度依据、必要的计算／假设／反例、冲突和缺口、建议的条件与验证步骤、证据附录 | 对必要判断展开推导和可追溯材料，适合深入评审 |

内容按本次目标和证据动态组织，不固定页数、不凑字数，不为详细版强行执行所有分析模型。简单版也不得省略用户必需问题、引用、获取日期、关键比较条件、冲突或重要缺口；可用简明注释和来源附录控制篇幅。无我方背景不编我方策略。

报告详略与 Quick／Standard／Deep 研究投入独立：简版不降低核验标准，详细版不自动扩大对象、研究范围或工具预算。只有证据需求变化才安排必要补研；仅从详细改简单或改版式时复用同一事实与分析版本。

## 默认 PDF

未指定文件格式时，生成实际 PDF 文件，通常保存为 `research/<安全对象标识>/<版本>/report.pdf`。无需另问是否要 PDF。用户明确要求仅聊天、Markdown 或其他格式时遵从，不强制额外 PDF。格式明确不代表角色和类型已明确。

正式导出前按 [RULES](../RULES.md) 完成内容 QA。生成 PDF 时读取[包内 PDF 模块](../modules/pdf/SKILL.md)，使用随技能安装的导出器。使用支持中文的字体，保留可辨认的来源链接、获取日期、比较条件和证据编号。不能把 Markdown 文件改扩展名冒充 PDF。

导出后重新打开文件，核对正文、表格、来源和页数；渲染各页并检查中文字体、分页、表格截断、文字重叠及链接可读性。修复后再交付，聊天中给简短摘要及真实文件链接。只有完成内容与文件检查的报告才能标记已交付。

缺工具、保存失败或导出／渲染检查失败时，说明具体阻碍，保留已核验正文并明确“PDF 未完成”；可给可用文本作为临时内容，但不静默替代默认 PDF 或宣称文件交付成功。研究本身只得到有限结果时，PDF 同样明确标为有限结果及缺口，不能包装成完整研究报告。

报告渲染并与段落映射逐项核对后，执行[交付前校验](research-ledger.md#交付前校验)。校验失败或无法运行时保留草稿，记录未完成的检查。

## PPT 询问与生成

PDF 交付后主动询问：

> 是否需要基于这份报告再生成一份 PPT？可选：需要／不需要。

该问题不得阻塞 PDF 交付。用户已要求 PPT 时直接生成，无须重问；已明确拒绝则不重复询问。交互场景未回复时记录待回复，不阻塞完成、不默认同意或自动生成；非交互场景未显式要求 PPT 时不生成，交付说明可另行请求，不等待回应。用户明确改用其他主格式时，在该报告交付后同样询问，除非已给出 PPT 偏好。

需要 PPT 时，生成真实 `.pptx` 文件，通常为同一版本目录下的 `report.pptx`；读取[包内 PowerPoint 模块](../modules/pptx/SKILL.md)，使用随技能安装的导出器。不把逐页提纲或 PDF 改名当作 PPT。按相同角色与详略提炼内容，引用与条件可放页脚或来源页，但关键限制不能只藏在备注中。

PDF 和 PPT 必须分别从同一份已锁定版本的 [证据与结论台账](research-ledger.md) 生成，不能互相转写或从聊天记忆重新拼事实；不为转格式重新采集或新增未经核验的结论。新增问题才触发影响分析与必要补研；有事实变化同时更新相关报告版本。打开／渲染检查幻灯片完整性、中文字体、图表、引用和溢出，核对与 PDF 的结论和数字一致；失败如实报告，不影响已完成 PDF 的可用性。

## 范围确认的触发

用户明确点名的一个或多个对象及问题，就是已授权范围。简述框架后继续，不因对象数量再问一次名单确认，名单明确后，按[比较角度选择](#选择比较角度)确定用户关心的问题。单产品研究中发现有依据的竞品时，按下述步骤把候选交给用户选择。身份歧义、授权不足或范围确实不完整时问具体缺口，不发通用“是否继续”。长期项目也复用当前明确指令，只确认尚未授权的新增对象、实质范围变化或未决事项。

### 选择比较产品

1. 用户只给产品名或说“分析一下这个产品”时，在轻扫中按目标客户、用途或替代方式识别少量相关对象。已有可靠候选就立即发起选择，同一轮写明每项的产品名、与原产品的关系、入选理由，附本次核查的链接和日期。用稳定编号对应已消歧的实体。有几项展示几项。若无可靠候选，说明缺口并继续原产品分析。若用户明确只研究原产品、已指定比较名单，或只追问某项事实，直接执行已有范围。
2. **让用户能当场选。** 提问为“这次把哪些产品放进对比？”宿主有多选控件时，直接展示产品选项并支持多选。只有单选问答（如当前会话可用的 `request_user_input_async`）时，给出可点的选项，例如“比较 1 和 2（显示两款产品名）”“只比较 1（显示产品名）”“只分析原产品”，并提示可在自由输入框回复其他组合或产品名。只有一项候选时仅展示实际可选范围。没有问答控件时在对话中显示带编号的同一张选择单，给出“回复 1、3 / 全部 / 只分析原产品”的用法。不能只列品牌后结束。
3. **等待的是名单选择。** 在对话或当前检查点保留原对象、编号与实体的对应关系、决策问题和已有材料。交互中可以继续核实原对象，等待时保留待选状态；如果独立工作已完成，停在这张可回复的选择单，保持研究可续接。预选项、未回复或超时都不算提交。已知非交互场景，使用指令或配置中明确指定的名单；没有名单就完成原产品分析，在结果中附可供下次选择的候选。
4. 收到有效选择后，用原产品和所选实体更新范围，复用已核实材料，多产品比较进入下方的角度选择。“只分析原产品”直接继续单产品研究。无需用户再发“开始分析”或重填读者与详略。自填产品名按明确新增对象处理；编号越界、名称歧义或选择矛盾时只澄清该项，保留其他已选项。

### 选择比较角度

用户直接点名多个产品，或从候选中选出了对照产品时，在 Plan 阶段先看原请求和本轮回复。已给出具体角度（如“只比价格与售后”）就复用这些角度，进入具体内容选择；只说明决策目标（如“用于采购”）时，结合该目标和产品特点，按[动态框架](dimensions.md)生成一张简短、有稳定编号的角度清单。当前问题应当明确显示所比的产品名。

- **发起一次可多选的提问。** 问“这次想从哪些角度比较 A 和 B？可多选。”列出本次每个角度的名称和它回答的问题，并单独提供 **全部选中**。有多选控件时逐项勾选；只有单选加自由输入时，列出完整编号清单，提供可点的“全部选中”，同时提示用户在自由输入框一次提交任意组合，如 `1、3` 或角度名称。纯文本界面使用同一份编号清单，接受编号、名称或“全部选中”。
- **按当前这张清单解释回复。** 保留待选步骤、产品名单和编号映射。上一轮产品选择中的“全部”只指产品。当前的“全部选中”选取所有已展示角度，合并重复项；用户也可以补充清单外的角度。空回复或预选不算提交，无法识别的编号只澄清该项。等待期间可复用初扫材料，正式比较等待用户选择。
- **提交角度后转入内容选择。** 保留已选角度，随即发出下方的研究重点选择单。角度清单上的“全部选中”只作用于角度。非交互调用或用户明确委托 Agent 选择时，按已有指令、配置或决策目标选定角度与内容，说明采用依据后继续。

### 从研究重点选择具体内容

1. 进入“本次研究重点”时，问“这次要对比哪些内容？可多选，也可以全部选中。”读取[12 个核心比较维度](core-dimensions.md)表格第一列，按原编号 01–12 和中文名称逐项完整显示，再单列 **全部选中（12 项）**。即使上一步只选了一个角度，也展示完整菜单。上一轮选过的角度用于指导后续取证，保持本轮选项的名称、数量与顺序稳定。
2. 宿主支持多选时展示可逐项勾选的维度和全选项。仅支持单选加自由输入时，在提问中列全 12 项，提供可点的“全部选中（12 项）”，提示可一次输入任意编号组合（如 `04、07、10`）或维度名称。纯文本宿主显示同一菜单。保存当前步骤和所选产品、角度，等待提交；本轮“全部”“全选”“全部选中”均对应 01–12，上一轮的全选只作用于上一轮。
3. 接受单项、多项或全选，合并重复项，仅对无效项澄清。选定后结合上一步角度，将所选维度细化成本次对象可观察的研究问题；按既有预算规则继续分析，无需再选子问题。每个已选维度均交代结果、证据缺口或有依据的不适用说明。用户已明确指定本轮维度时直接采用；非交互或明确委托时沿用上文默认规则。
