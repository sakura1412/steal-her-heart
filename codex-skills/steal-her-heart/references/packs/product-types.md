# 按产品类型选择分析重点

## 适用范围

本包用于设计产品研究问题，覆盖七种可重叠的业务属性。先从本次资料确认客户是谁、购买什么、怎样得到价值，再判断下表哪一行、哪一个问题会影响当前决定。用户点名的关注点优先。对象同时具备多种属性时，只合并与本次目标有关的条目；没有匹配项时按对象实际情况新建维度。表中标识与表头共同定位包内条目，例如 `agent/研究问题`。

## 候选问题与取证

| 标识与适用线索 | 研究问题 | 推荐材料与边界 |
|---|---|---|
| saas · 客户订阅持续交付的软件服务 | 核心功能能否走完目标工作流？角色权限、集成依赖、部署条件如何限制使用？按实际席位和用量要买哪个版本？ | 用同版本产品文档、角色配置、集成测试、部署说明和报价核对。区分有 API 与目标系统已经接通。 |
| agent · 产品能围绕目标决定并执行下一步 | 哪些决定由系统自主作出，哪些需要人批准？能否拆任务、调用工具并处理失败？跨轮记忆保存什么，执行状态如何记录？中断后从哪里恢复，会不会重复产生副作用？ | 同一任务保存计划、工具调用与结果、人工介入、状态检查点及恢复日志。可在获准的隔离环境模拟工具超时；只有演示资料时，将恢复能力标为厂商宣称或待测。 |
| commerce · 平台连接供需并组织交易和履约 | 商品结构、供货与库存怎样影响可买性？从发现商品、支付到物流、退换货，用户在哪里退出？交接点由平台、商家还是承运方负责？ | 对齐商品规格、渠道与地区，用交易规则、履约记录及获准的漏斗数据取证。浏览量或平台交易总额无法单独说明购买转化率。 |
| social · 用户关系或内容互动驱动使用 | 用户从哪里增长？关注、好友或群组关系怎样形成？内容如何分发，这些机制与不同客群的留存有何关系？ | 对照实际关系建立路径、分发规则、获客与分群回访数据；观察到推荐结果只能说明该次曝光。留存变化的归因还要检验渠道、活动等替代解释。 |
| finance · 用户进行价值转移或承担金融风险 | 交易何时鉴权、拦截、复核、清算或撤销？风控如何处理异常及误拦？资金与数据的安全边界是什么，谁承担合规责任？ | 按产品、法律主体、辖区和有效期核许可、公示、交易条款及可验证控制。安全宣传不足以证明具体资质或风控效果。 |
| enterprise · 组织中的多角色协作与管理 | 组织层级如何映射到业务流程、权限继承和数据范围？跨部门交接、授权变更、审计及数据管理会影响哪些角色？ | 用配置说明、角色—操作—数据范围表及获准的测试账号验证。同一操作分别查管理员和普通成员，保留实际组织配置。 |
| consumer · 个人购买并在日常场景使用 | 使用体验、品牌认知、规格和价格怎样影响选择？线上线下渠道、售后和反复出现的口碑差异，对哪类买家最重要？ | 按具体规格、地区和购买渠道核价格及售后；区分品牌主张、实物观察与去重后的用户反馈，评价结论限定样本范围。 |

## 指标口径

只为当前问题选择有输入的指标。例如 `commerce/购买转化率` 可定义为同渠道同观察期内支付成功的去重访客数除以符合条件的去重访客数；`social/第七日留存率` 可定义为注册同期群第七日有约定活跃行为的人数除以已完整经历七天观察期的同期群人数。两项均以百分比表示，记录分子、分母、时间边界与排除规则。分母缺失或为零时保留缺口。对自主执行任务，可先描述故障前后的状态和副作用；要统计恢复成功率，须定义成功条件并保留全部可比故障试次。

## 方法与交付

沿客户任务比较履约、操作或交接，可候选 `customer_journey@1.0.0` 并输出旅程及异常节点。比较同一目标能力，可候选 `feature_matrix@1.0.0` 并输出带使用条件的矩阵。比较实际支付，可候选 `price_analysis@1.0.0` 并输出场景总成本。由 Planner 在取证 QA 后按输入决定。图表单元格记录对象、条件、依据或缺口。若行业条目只帮助澄清背景，报告可仅引用有关发现。

## 混合对象示例

一家面向企业、按席位收费的软件还提供自主报销助手。若问题是“断线后会不会重复付款”，优先查 Agent 的任务恢复和工具幂等性、企业软件的付款授权和审计。用模拟付款观察恢复后是否产生第二笔交易，同时核对操作者权限。仅有厂商“自动重试”的说明时，可确认其宣称，重复付款风险仍待验证。若同一产品的问题改为“200 名员工部署一年多少钱”，改查 SaaS 版本、席位定义、最低承诺和集成部署费用。两次采用同一对象身份，各自形成问题和证据要求。
