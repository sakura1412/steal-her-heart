# Comparison Engine（P0）

跨对象、指标和价格比较的前置契约。由 Codex 按实际证据执行分组、口径校验和可复算计算，不是已部署的独立计算服务。维度来自动态框架，不预设行业字段；数字计算须用实际可用的确定性计算工具并保留输入与过程，工具不可用时不报未经核算的结果。

## Comparable Group：先分组，再比较

定义 group_id、group_version、研究问题、基准范围、对象 entity_id／版本、纳入与排除依据、共同维度及目标口径。逐项检查：目标客户、产品定位、市场区域、配置／服务范围、计价周期。还须核对实体层级、时期、使用端和适用条件。

每项记录 match、可解释的可对齐条件、mismatch 或 unknown。关键条件未知时不能默认可比；不同定位或服务范围的对象作为 reference_only，不能进入直接排名。用户明确要求比较不代表已经证明可比，可以交付差异与限制并说明为何不能排名。

一家企业有高低端产品而另一家只有高端产品时，先选择实际对应的产品／版本或服务方案，不拿公司均价与高端产品价格比较。需要公司层比较时另定义可比业务范围，不将产品层结论上推为全公司优劣。

组资格分 direct、scenario_comparable、reference_only、unresolved。scenario_comparable 仅在明确且相同的使用／购买情景下比较，结论限定该情景，不能泛化为无条件领先。对象可以在不同情景属于不同组；结果不能跨组直接排名。

## 十项能力与交接

| 能力 | 执行要求 |
|---|---|
| 维度匹配 | 按语义、用户任务、实体层级与条件提出映射，名称相同不等于同义；未确认映射不进入计算 |
| 指标定义识别 | 绑定指标标识、定义、版本、测量方式与聚合口径；缺定义先标未知 |
| 单位标准化 | 保留原值，转换公式、条件、参数及来源；标准化展示不能抹去购买限制 |
| 比较口径校验 | 客户、定位、区域、配置／服务范围、周期及多端条件共同检查 |
| 缺失值处理 | 未采集、未找到、不可访问、冲突、未知分别保留，不填零，不当劣势 |
| 不适用处理 | 有依据且符合定义才标 N/A，不因难找豁免；不适用项不参与排名 |
| 权重计算 | 先定义目标、共同指标、方向、尺度、权重来源及敏感性，不默认“客观权重” |
| 可视化结构 | 输出表格／图形所需数据、单位、状态、范围与引用，不把缺失绘成零值 |
| 评分解释 | 解释每项得分、权重贡献、覆盖和变动敏感性；不跨组宣称总冠军 |
| 追溯 | 结果 → 指标／公式／权重／组版本 → 原始值与条件 → Evidence／Source |

## 从差异到选择

用户要比较竞品时，围绕会改变选择的问题组织正文。先用一张矩阵对齐已指定的对象：行是本次决策维度，列是对象及具体版本，每格写在共同条件下可核验的表现及引用，缺资料的格子保留实际状态。三个及以上对象先看全组，再展开真正影响选择的对象对。逐对比较是用户的明确要求时，逐对给结论或缺口。

针对每项重要差异，写清相对谁、差在哪里、谁在什么场景下受益，以及选择这一方要接受的成本或限制。先陈述各方已核实的事实，再把“这对某类用户意味着什么”标为分析判断，并关联支撑各方的 Claim。判断实际成效需要对应的成效证据，仅有功能说明时，把预期收益和验证办法写清楚。

从各对象的角度检查取舍：条件改变后，另一个对象何时更合适？双方同样满足需求时写“该项持平”。反向优势、代价或领先程度缺少证据时说明缺口。在一方资料缺失时只陈述另一方已证实的表现。摘要优先呈现最能改变决策的差异，简单版也保留选择条件。报告 QA 抽查关键判断，确认读者能从结论找到比较对象、场景、双方证据以及可能改变选择的条件。

## 标准化记录

每个比较单元记录 entity_id、使用端、dimension_id／metric_version、group_id、raw_value／raw_unit、目标单位、normalized_value、conversion_rule／version、输入引用、地区／时期／规格／渠道、状态和限制。原始数据只追加，不被标准化值覆盖。

报价按 seat、usage、item、project 等真实计价基础保留，不能只把币种换算后直接排序。月付与年付可展示月均摊，但年付承诺、预付、续费、取消条件仍保留。用量费需明确工作量、阶梯、最低消费与超额费用；按件需规格和数量；按项目需明确交付范围、工期及附加费用。

共同使用情景可记录人数、数量／用量、期限、服务范围、地区、税费、折扣和一次性费用。确有证据支持时计算该情景总成本，再按清楚的周期展示。无法确定情景或关键条款时不换算；不会因用户要求低价排序而猜用量、折扣、税率或汇率。

货币转换保留原币种、实际汇率来源与时点；名义／实际价格、含税／不含税、标价／成交价、GMV／收入、配置档位和评分量表不能无依据混合。聚合口径不同先说明，不通过简单单位换算掩盖语义差异。

## 缺失、不适用与评分

先给可核查的比较表。只有用户问题需要评分／排序，且可比组、共同评分指标、规则和输入充分时才计算。权重可来自用户或有理由的任务情景；未指定不自动等权。Agent 提议的权重明确标分析假设，结果只作该情景判断；假设不能用于补造输入事实。

设固定共同评分集合 J，w_j ≥ 0，Σw_j = 1；先声明高好／低好方向与锚定尺度，再计算 S_i = Σ(w_j × s_ij)。分项评分必须有透明映射，不凭模型自由打分。避免同一能力多个别名重复加权，证据置信度不能冒充产品表现得分。

任何对象缺少 J 中必需输入，或该项对部分对象不适用时，不给该对象缺项填零、不对各行分别重分配权重，也不发布伪完整排名。可以显示共同可比子集的局部比较，但重新定义组／评分集合、披露排除项及对原问题的限制；原必需目标仍缺失时不能称总体排名。N/A 不加分、不扣分。

定性判断如没有证据支持的评分尺度，只作描述；不能强转数值。记录权重敏感性，排名随合理权重或情景改变时说明不稳健。并列、不确定或不可排名都是合法结果。仅比较样本内最优不等于全市场最优。

## 输出与质量检查

输出 ComparisonResult：group_version、included／reference_only／unresolved 对象、metric_definitions、cells、normalization_records、weight_spec（可空）、scores／ranks（可空）、coverage／limitations、trace_refs。

可视化描述包含 chart_type、轴定义与单位、series／points、value_status、group_id、scope／as_of、证据引用及解释。不生成误导性“全市场”饼图，不把部分样本补成 100%，不连接缺失趋势点；跨组数据用分组呈现，不共享隐含排名。

QA 核对每项身份、端、时期、定义、换算、缺失状态和排名资格；数字复算后才采用。组成员、指标口径、权重或情景变化，创建新版本并重算受影响结果，旧结果不覆盖。原数据失效则相关结论失效，不能只刷新图表日期。
