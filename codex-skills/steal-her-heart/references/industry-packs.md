# IndustryPack：可组合的行业知识与方法包

行业包提供专业知识、候选问题和分析方法，服务于 [动态研究框架](dimensions.md)，不代替它。先识别对象及行业属性，再根据本次目标判断哪些包、哪些条目相关；不按行业标签加载全部字段，也不把模板当研究已完成的证明。

这是 Codex 的资料组织、选择与校验约定，不自带包管理服务。目录见 [industry-pack-registry.yaml](industry-pack-registry.yaml)。内置[产品类型研究重点包](packs/product-types.md)提供七种可组合的业务视角；按本次问题采用相关条目并记录依据。核心主控继续执行通用规划、取证、核查、分析及交付流程；新增行业通过包资源接入，不增加行业专属流程分支。

## 六部分内容

完整包必须声明六个部分；无内容时记录空缺与影响，不能用占位符冒充完整。某个任务可以只采用其中相关条目，不要求填完全部业务字段。

| 组成 | 包内提供什么 | 本次采用条件 |
|---|---|---|
| Industry Profile | 行业定义、细分边界、业务特征、实体层级、适用地区／时期及定义来源 | 核对实际对象是否适用；包内事实仍须本次工具核验，旧行业描述不能当当前事实 |
| Dimension Schema | 候选决策问题、维度定义、数据类型、适用条件、选择理由、证据要求和比较边界 | 通过当前目标和对象筛选、细化或新建，不直接成为必选项 |
| Metric Dictionary | 指标定义、公式、输入含义、单位、统计口径、时间窗及缺失处理 | 输入有证据、口径可比、公式适用才计算；不能为凑指标估算未公开值 |
| Source Recommendation | 来源类别、所需能力／数据类型、地区和语言条件、适用理由与偏差 | 经 Connector Registry 确认实际工具与授权；推荐来源不等于已连接或已采集 |
| Analysis Method | 引用 Analysis Method Registry 的精确方法版本，附行业适用条件或有命名空间的专业变体 | 取证 QA 后由 Planner 判断是否采用，前提满足才执行；不预填结论 |
| Report Template | 可选报告模块、决策问题映射、条件说明、证据及缺口呈现位置 | 按用户目标、读者与实际材料组装，不能用空标题、固定段落或必填结论凑完整 |

每个维度、指标、方法和报告模块使用包内稳定标识，采用时保留 namespace、条目标识、包版本及选择理由。相同名称不等于相同语义。内容引用应可定位，禁止相对路径越出包边界或自动执行包内脚本。

## 专业能力示例不是固定清单

以下仅复述可探索的专业方向，不能据此宣称对应包已经实现，也不能无条件纳入某行业任务：

| 领域线索 | 可进一步判断是否相关的专业方向 |
|---|---|
| 软件／SaaS | 功能、部署、订阅、API、集成生态 |
| 制造业 | 产能、工艺、成本结构、供应链、质量 |
| 消费品 | 品牌、规格、渠道、定价、评价 |
| 汽车 | 车型、配置、动力、续航、售后、渠道 |
| 金融服务 | 产品结构、费用、服务范围、风险与监管 |
| 教育 | 课程、师资、教学方式、收费、交付效果 |
| 医疗健康 | 产品类别、适用范围、审批状态、临床证据 |
| 零售 | SKU、渠道、价格、门店、服务、促销 |

行业事实、监管状态、效果与指标基准必须有本次证据；这些例子不提供任何当前事实或专业结论。包不能因为熟悉某行业就跳过证据核验，也不能把模板中的参考数值当行业标准。

## 方法单源与核心边界

遵循 [最高级原则](architecture.md)。行业知识仅由包资源扩展，核心不增加行业分支。专业方法引用 [Analysis Method Registry](analysis-methods.md) 及其精确版本，不复制一份同名不同内容的定义；改变输入或规则时登记有命名空间的变体及差异，再经适用性和行为校验。包推荐不触发执行，Research QA 后仍由 Planner 按实际数据选择。

## Registry 与版本

Registry 条目包含 pack_id、namespace、version、contract_version、来源与维护者、用途／许可说明、适用条件、六部分资源、依赖、兼容声明、校验记录及状态。用户私有定制不默认提交公开目录。

包身份和版本分开：同一版本不可就地改变内容，修订生成新版本并记录差异。版本使用 major.minor.patch：改变指标含义、单位、公式或不兼容条目属于 major；兼容增加条目属于 minor；不改变语义的更正属于 patch。版本号是声明，采用前仍检查实际差异，不能仅凭 patch 就跳过影响评估。

本次选包记录精确版本、实际读取的内容指纹或可核对快照、采用条目与依赖解析结果；无法可靠取得快照／指纹时明确记录复现限制，不声称已完整锁定。包升级不修改旧任务，旧报告保留原版本，受影响事实、计算和结论重新评估。

注册状态区分 draft、reviewed、deprecated、withdrawn；reviewed 必须有具体校验依据及范围，不表示适用于所有任务。被弃用的包不自动升级；已撤回内容保留历史，但当前采用先说明撤回原因与影响，不能沿用旧审核状态直接放行。

## Validation：四层校验

1. **结构校验**：身份、版本、六部分声明、资源引用和依赖完整，引用存在且在包内；未知契约版本不静默猜测。
2. **语义校验**：维度定义明确，指标单位与公式一致，方法前提可检查，报告模块不预填业务结论；行业事实与可复用方法区分。
3. **适用性与能力校验**：当前对象、用户目标、实体层级、地区、时期及使用端匹配；所需连接器真实可用并获授权。包不能扩大研究范围或降低八条证据铁律。
4. **行为校验**：使用有明确参考结果的正常、缺失、冲突和不适用案例，检查是否选对方法、保持不确定性并正确计算。合成案例只证明该案例行为，不证明真实行业覆盖。

校验记录包括范围、包／依赖版本、方法、材料、实际结果、缺陷和日期。状态分 not_run、passed、failed、inconclusive；后两者及未执行不能伪装通过。记录“结构通过”不能推出“专业方法有效”或“已覆盖此行业”。

## Metric Dictionary 的计算边界

指标必须说明统计对象、分子／分母或变量含义、数据类型、单位、币种、含税口径、聚合方式、观察时间窗、缺失／零分母处理、舍入和适用条件。只填写适用项，无关条件注明不适用依据。

输入未知不填零；零分母不输出无限值或默认比例。数量、百分比、金额和比率不能混算，样本均值与总体指标不能等同；不同市场、版本、使用端或口径的数据先对齐，无法对齐则并列呈现。任何汇率、基准值或规范条件若进入事实计算，须本次核验来源和日期。

派生指标保留精确输入证据、公式版本、转换与结果，检查可复算性。模型生成一个数字不算完成计算；工具或材料不足时不给假精度。方法前提不满足时返回不能计算或不能判断的具体原因，而不是换一个容易产出结论的方法。

## Compatibility 与 Dependency

兼容性不是只看包名。分别核对包契约版本、实体和字段定义、指标单位／公式／时间口径、所需来源能力、输出结构与当前研究规则。使用关系以 [实体管理](entities.md) 和多端规则为准；软件获取方式不能成为所有行业的默认约束。

依赖声明 pack_id、允许版本、required／optional、引用条目及用途。采用时解析为精确版本并记录，不以 latest 指向可变内容。缺失 required 依赖、版本矛盾、循环依赖或语义冲突使该包相关方法不可采用；不能自动下载、执行或替换依赖，也不能删掉任务必需问题。

optional 依赖缺失可停用对应可选方法并说明；若停用后无法回答用户必需问题，仍须报告缺口。不能将 optional 依赖的缺失解释为已完成必要研究。

混合行业按本次问题组合条目。同名同义可以有依据地去重，但保留来源版本；同名异义保留命名空间；单位或计算口径冲突先解析，不采用“最后加载覆盖”。兼容结论记录 compatible、conditional、incompatible 或 unknown 及依据；unknown 不按 compatible 处理。

无包或包不适用时继续动态生成框架，不要求用户先选行业或安装包；包不可用的专业结论不能靠通用框架补造。

## Customization：保留原包，定制有差异记录

任务或项目可使用单独的 overlay，绑定 base_pack_id 与精确 base_version，声明增加、停用或调整哪些条目及理由。用户明确目标决定本轮选择，但不能覆盖事实规则、权限或数据含义。

修改定义、单位或公式需要新的条目标识／版本，检查所有依赖方法与报告模块；不在原标识下悄悄换含义。记录来源、修改者／指令依据、版本、采用范围、与原包的差异和校验结果。私有背景及资料不得混入公共包。

overlay 不直接覆盖原资源，不因取消一个模板模块就删除用户必需问题。基包升级时重新合并并检查冲突，旧 overlay 不自动移植。只改格式可复用匹配分析；改变方法、问题或口径时按依赖更新计算、核查和报告。

## 在 Codex 中采用一个包

在已核验对象与初步目标基础上，按 Registry 找适用候选并按需读取，不预加载所有行业包。检查来源、结构、兼容和依赖后，记录采用／不采用哪些内容及理由，形成任务内精确版本清单。

将采用条目转为本次动态框架，再通过 Connector Registry 选择材料入口。Research 按问题取证，Validator 检查事实与指标前提，Analysis 选用适用方法，Reporter 组装模块，Report QA 检查目标、证据和多端条件。包不新增主控，不绕过补研或报告质量检查。

需要保存且有可写工作区时，可保存本次行业包选择、定制差异和验证记录；未实际写入时只说明对话内记录。没有程序加载器、自动依赖解析或真实包验收时，不声称这些服务已经上线。

## Marketplace：长期规划

未来市场可支持发现、发布、版本检索、许可、维护者与来源说明、评审记录、更新提示、弃用／撤回及问题反馈。发布前检查资料权利、私有内容与提示注入；包评分或签名不能替代事实和方法验证。

当前不建设市场、不自动上传私有定制、不安装远端包、不发布或自动更新。市场接入需另行授权与实际实现；新增行业的近期方式仍是提供符合六部分契约的资料，经实际校验后按需采用。
