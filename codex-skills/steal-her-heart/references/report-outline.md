# 竞品分析报告标准目录

综合竞品报告默认按以下顺序组稿。先写有证据支撑的正文和建议，再提炼第一章，让只读摘要的人也能判断应采取什么行动、结论在哪些条件下成立。[研究维度](core-dimensions.md)用于取证，[图表与其他成果](report-artifacts.md)放在最能解释决策的章节。同一张表在主章节展开，其他章节引用其发现。

| 章次 | 章节 | 内容与成果 |
|---|---|---|
| 第一章 | 执行摘要 | 交代分析背景、目的、对象与范围。先回答原始决策问题，再用最重要的发现支撑核心结论。点出核心竞争机会、建议的第一步，以及可能改变判断的限制。 |
| 第二章 | 市场与行业分析 | 说明行业现状、趋势和市场格局。用市场格局图或竞品分类图解释玩家、替代路径和比较范围。 |
| 第三章 | 竞品基本情况 | 介绍竞品及所属公司的相关背景，用定位对比表列出各自的目标客户、使用场景与核心价值。有用户材料时补充画像。 |
| 第四章 | 竞品产品能力分析 | 展示产品架构、功能模块和依赖，围绕用户目标拆解核心功能。用功能对比矩阵标明版本、可用条件及未知项。 |
| 第五章 | 核心业务流程分析 | 选取同一典型场景，并排呈现各家完成任务的关键流程与操作路径，标出交接、异常、恢复方式及流程差异。 |
| 第六章 | 用户体验分析 | 围绕典型任务比较 UI/UX、交互设计、操作效率和易用性。用真实截图或观察记录定位体验问题，说明影响、复现条件和待验证项。 |
| 第七章 | 商业模式分析 | 解释谁付费、如何收费以及各产品版本的定价策略。以同一购买条件对齐报价，再用获客、续费或增购材料评估商业化能力。 |
| 第八章 | 用户评价分析 | 在明确的样本范围内归纳好评、差评、高频痛点与用户需求，交代样本数、时段、来源及反例。把反馈对应到前文的功能或旅程节点。 |
| 第九章 | 技术能力分析 | 介绍可证实的技术架构、集成能力、部署方式、安全性和扩展性。说明这些条件如何影响采用、交付或维护，未公开的实现保留为未知。 |
| 第十章 | 竞争优势分析 | 综合前文证据比较优势、劣势、差异化能力与竞争壁垒。给出受益者、适用场景与代价。战略问题需要且输入充分时用 SWOT 归纳。 |
| 第十一章 | 产品发展趋势 | 用时间线梳理版本迭代、产品战略变化与新技术应用。分别标记已发布、官方计划和分析预测，并说明未来方向的判断依据。 |
| 第十二章 | 竞争机会与建议 | 将市场机会追溯到未满足的需求与能力差距。给出功能优化或其他行动建议、优先级及理由；产品路线图列出验证、试点、扩大投入的条件。涉及我方资源时写明依据，背景不足时给条件式方案。 |
| 附录 | 原始资料与证据 | 索引本次采用的官方网站、产品文档、获准展示的截图、用户评价来源和版本记录。逐项附资料链接或授权文件标识、原文定位、采集时间、适用条件和可信度理由，让读者从正文的结论查回证据。 |

一般版可以压缩相邻章节，简单版可以浓缩为摘要、关键对比和行动建议。详细综合报告按标准章次展开。专项报告优先回答指定问题，例如只比较定价时可用“执行摘要 → 同口径定价表 → 选择建议 → 证据附录”。用户明确指定目录或交付物时按其要求组织。遇到必需章节缺证据，交代已核实部分、缺口及其对结论的影响。跨行业研究按实际交付方式调整术语，例如线下服务的能力、流程和体验可通过服务项目、履约路径与现场观察呈现。

交付前核对三处：摘要中的判断在正文有依据，第十二章的优先事项能回指前文发现，正文引用能在附录中找到对应版本的材料。若获准制作隐藏来源的公开展示副本，核验版保留完整引用映射，展示版仍保留时点、适用条件和关键限制。
