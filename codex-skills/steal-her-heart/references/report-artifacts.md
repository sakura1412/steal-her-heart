# 按决策问题选择报告产物

规划时把选中的[研究维度](core-dimensions.md)落实到具体成果：谁会用这张图或表做什么决定，哪些证据到位才能完成。用户点名的成果逐项安排；其余按问题选取，可在一份报告内合并呈现。技术、趋势、口碑等维度的发现应进入最能解释其影响的成果。

| 分析方向 | 核心产物 | 读者可以从中看出什么 |
|---|---|---|
| 市场分析 | 市场格局图、竞品分类图 | 在指定市场和时点，哪些玩家服务同一细分需求，哪些构成直接竞争、替代或潜在进入。标注分组理由；采用坐标图时解释两轴，使用气泡大小表示份额时须有同口径分母。 |
| 产品定位 | 产品定位对比表、用户画像 | 在同一购买或使用场景中，各家面向谁、承诺什么、用户为何选择它。画像注明购买者与使用者、任务、约束及资料依据。仅有定位文案时，标为厂商目标画像，实际购买动机列待验证。 |
| 功能分析 | 功能架构图、功能对比矩阵 | 用层级或依赖图展现用户可见的模块如何支撑核心任务；矩阵逐格给出版本、条件、状态和依据。功能架构描述产品组织方式，内部技术实现另行取证。 |
| 流程分析 | 核心业务流程图、用户旅程图 | 流程图从同一起点画到相同完成标准，按角色呈现操作、交接、异常与回退；旅程图从用户视角对齐阶段、目标、接触点、反馈与摩擦。用户感受标明观察或反馈依据。 |
| 体验分析 | 页面截图、交互对比、体验问题清单 | 同一任务、同一步骤并排展示各端实际画面，标注版本、观察时间及截图性质。问题清单写复现条件、预期与实际结果、对任务的影响。缺页面访问或截图授权时，提交可核实的交互说明和待测步骤，说明截图缺口。 |
| 商业分析 | 定价对比表、商业模式分析 | 在同地区、周期和用量下展示总价、计费条件及限制；说明谁买单、通过什么渠道成交、持续收费或增购的触发条件。续费率、利润或支付意愿分别需要对应证据。 |
| 竞争分析 | 竞争优势对比矩阵、SWOT | 矩阵对应具体场景，写明相对谁有优势、受益者、代价与反例。要研判竞争战略且输入充分时选 SWOT，注明主体，把内部优劣与外部机会威胁分开；四格中的判断引用相应 Claim。 |
| 战略分析 | 机会点清单、产品建议、优先级路线图 | 每项机会关联客户问题、竞品差距和证据。建议说明行动、优先理由、依赖、第一步与验收信号；路线图表达验证、试点和扩大投入的次序及转换条件。我方能力和资源未知时，标为条件式方案。 |

## 研究投入优先看哪里

综合分析优先把时间用于五处：用**产品定位**解释竞品为什么存在，用**功能与业务流程**解释它具体怎样解决问题，用**用户反馈**检验实际表现，用**商业模式**解释谁愿付费及交易如何持续，用**竞争机会**把前面的发现落实为可验证的决策。具体投入取决于用户目的、已有证据和剩余预算。若用户只关心收费，优先核同口径账单和条款；若关键假设是用户因交接困难而流失，就优先查任务记录、用户反馈和其他可能原因。

用户反馈可以贯穿多项成果。按[口碑采样规则](review-method.md)保留主题、去重样本数、时间窗、来源、反例和偏差。将同一反馈主题关联到旅程节点、体验问题和机会项，让读者能从建议查回反馈原文与样本范围。单条投诉只能支撑个案，声称某问题导致流失还须核对退出原因。

## 报告验收

对照规划和用户点名的成果检查实际报告：图表是否已生成且可读，能否回答原决策问题，图例、状态和适用条件是否清楚，关键节点、单元格及建议是否能回查同一版证据与结论。若资料只够说明部分流程，就标出已核实步骤和未知环节。资料或工具限制影响交付时，逐项列明已完成部分、缺口及对判断的影响。
