# 竞品分析的 12 个核心维度

用[五个核心问题](questions-hypotheses.md#竞品分析的五个核心问题)确定报告要回答什么，用下表检查哪些角度能帮助回答。综合研究在规划时浏览全表，专项研究直接定位相关行。按[动态框架](dimensions.md)把选中的角度改写为本项目可观察的问题，并记录范围、优先级、证据要求和完成条件。一个问题可以调用多个维度，一条证据可以支持多个问题。

| 维度 | 具体研究什么 | 证据与有用的输出 |
|---|---|---|
| 01 市场与行业分析（Market Analysis） | 市场处于什么发展阶段？哪些细分领域在增长，主要玩家、潜在进入者和替代方案如何影响格局？政策、技术及外部变化通过什么路径影响需求？ | 说明地区、品类和时间窗口。将规模、增长、趋势与判断依据放在一起，按[市场数值规则](market-intelligence.md)说明统计口径和估算假设。 |
| 02 竞品识别与分类（Competitor Mapping） | 在同一次客户决策里，谁以相近方案直接争夺订单？谁用不同机制间接竞争？客户还能选择什么替代办法？哪些企业有进入迹象，哪些对象只用于对标？ | 绘制候选名单或关系表，列对象、所属公司、成熟度依据和入选理由。间接竞品可以同时是替代方案；人工、自建、维持现状也可能替代购买。按实体去重，保留多标签及合作、供应等关系。 |
| 03 产品定位与商业战略（Product Positioning） | 谁购买、谁使用？他们在什么场景遇到什么痛点？产品承诺何种价值，靠怎样的差异化定位、品牌表达与市场宣传吸引目标人群？ | 对照厂商定位、典型案例与实际购买或使用动机。写出“哪类用户在什么情况下为什么选它”，交代样本与反例。 |
| 04 产品功能分析（Feature Analysis） | 为完成研究目标，需要哪些核心模块？功能架构、覆盖深度、依赖、使用门槛和迭代如何影响任务？所谓独有功能在哪些对象和版本间成立？ | 按任务制作[可比矩阵](comparison.md)：行是可验收的能力，列是对象及版本。每格记录状态、限制与依据。易用性和实际价值交由流程或体验证据判断。 |
| 05 业务流程与使用场景分析（Workflow Analysis） | 对同一业务目标，从相同起点到相同完成标准，各家经过哪些节点？谁操作、谁交接，何处自动执行，出错后谁恢复，完成后还有哪些动作？ | 并排记录“前置条件 → 路径 → 异常与人工介入 → 最终结果”。指出哪一步被省去、转移给其他角色或转移到事前配置，以及谁因此受益。 |
| 06 用户体验与交互分析（UX/UI Analysis） | 用典型任务观察入口与导航、视觉布局、学习门槛、操作步骤、反馈、错误恢复、无障碍与多端适配。 | 在获准的使用端实际操作，记录版本、起止状态和可复现的步骤，适合时附真实截图。将观察到的摩擦与用户感受分开。只有演示素材时标为厂商演示，耗时及满意度留待验证。 |
| 07 商业模式与定价分析（Business Model） | 谁付费、按什么收费？如何获客并销售？免费、各付费版本与增值服务怎样分层，哪些需求触发续费或增购？ | 用同地区、人数或数量及周期列出实际购买条件、总成本和限制。客户支付意愿与支付能力需要买方材料；挂牌价格只支持报价结论。 |
| 08 用户评价与市场口碑（Customer Feedback） | 哪些好评、投诉、功能需求、流失原因在相似用户中反复出现？客户案例、社区讨论与评分随时间如何变化？ | 按[口碑采样规范](review-method.md)交代平台、样本数、时间窗、去重及偏差。给出反复出现的主题、样本内频次和反例，标明客户案例的发布者。 |
| 09 技术能力与产品架构分析（Technical Analysis） | 哪些实现约束会改变选择？按对象核查架构、部署、集成/API、兼容性、扩展性、安全隐私、性能稳定性及 AI 或自动化能力。 | 标明能力适用的版本、部署环境与验证方式。同条件测量才比较性能。内部实现无法核实时记“未知”；值得追查的推测列为假设，说明验证所需材料。 |
| 10 竞争优势与劣势分析（Competitive Strengths） | 功能、体验、品牌、客户、渠道、资源或生态上的差异，在哪个场景构成优势、短板、壁垒、机会或威胁？ | 将判断追到双方同口径事实，给出受益者、代价、可能逆转选择的条件。需要综合内外部因素且输入充分时可选 SWOT；评分须有可复算依据。 |
| 11 产品发展与战略趋势（Product Roadmap） | 哪些功能新增、调整或下线？迭代节奏、市场拓展、AI 应用和公司动态说明哪些战略变化？ | 用时间线区分“已发布”“官方宣布计划”“分析预测”。分别记录发布日期与适用版本、公告日期与承诺边界、预测依据与反证信号；分批上线标注覆盖范围。 |
| 12 竞争机会与产品建议（Strategic Recommendations） | 哪些需求或场景尚未满足？哪些能力值得借鉴或补齐，哪些设计值得避免？我方有条件在哪个细分场景形成差异？ | 从客户问题与竞品表现推导机会。结合已知我方目标、资源、依赖和影响确定优先级，按需安排短期验证、中期试点、长期投入。每项写出第一步及继续或停止的判断标准。背景不足时给条件式选项。 |

**功能矩阵的四种状态。** “支持”表示在声明条件下达到该行完成标准。“部分支持”写清已完成和仍需人工完成或受限的环节。“不支持”需要明确排除说明，或能排除配置、权限等干扰的适用验证。“未知”保留未采集、查找后未找到、访问受限或证据冲突的具体原因。不适用的比较单元单列并说明理由。

**选取示例。** 若采购方只问两家维保商“夜间故障多久能恢复”，可从流程、技术或履约能力、客户反馈中选取派单、到场、备件和修复记录。合同只承诺“两小时响应”时，响应承诺可填，恢复耗时仍为未知。若用户明确要求逐项研究全部 12 个维度，则逐项给出结果、缺口或有依据的不适用说明。
