# 维护者验收目录

仅用于开发、评审与验收；普通研究运行不加载 tests/ 或 validation/。测试场景以运行规则为准，本目录不定义另一套交互默认值。执行时记录实际输入、工具、产物与未完成项，未执行不得标通过。

## 新研究能力与架构验收

| IND-14 | 扩展与市场 | 新行业通过资料契约接入通用流程；目录为空不冒充已交付行业能力，市场不自动安装／发布／更新 |

## 八条证据规则验收

| ID | 场景 | 应观察到的行为 |
|---|---|---|
| EVI-01 | 记忆／旧报告与本次事实 | 每条事实关联本次真实工具结果、来源链接和获取日期；旧快照读取不冒充当前来源核查 |
| EVI-02 | 来源性质 | 官方宣称、第三方、用户反馈、分析判断明确区分；自述不自动变外部事实 |
| EVI-03 | 价格／版本／评分 | 地区、版本、时间和必要条件明确；评分量表／平台／样本未知就注明，不强做比较 |
| EVI-04 | 缺失状态 | 未采集、查找后未找到、不适用区分；访问失败另列，未提及不当不支持 |
| EVI-05 | 证据冲突 | 原冲突双方可追溯，处理依据明确，未决冲突不静默改成唯一答案 |
| EVI-06 | 无我方背景 | 不编我方优势、赢输原因或建议，需要判断时只补必要背景 |
| EVI-07 | 多端 | Web 有证据而 App 未查时逐端分别标注；小程序、桌面、线下同理，不跨端继承结论 |
| EVI-08 | 多端共同来源 | 来源明确覆盖多个端才复用并逐端核查；浏览器读取 App 文档不标为 Web 功能证据 |
| EVI-09 | 部分工具失败 | 只交付已核实部分并列对象／端／问题缺口；全无已核实事实时不产事实性报告 |

## 实体管理验收

详见 [实体管理与消歧](../references/entities.md)。以下为实际任务的验收要求；文档结构检查不能证明身份判定已经正确。

| ID | 场景 | 应观察到的行为 |
|---|---|---|
| ENT-01 | 同名跨行业／地区 | 保留不同候选，用身份材料或必要澄清分辨，不混合资料 |
| ENT-02 | 别名与多语言 | 有依据才映射同一 ID；音译或自动翻译仅作线索，旧名带时期 |
| ENT-03 | 公司／品牌／产品同名 | 分清实体层级，发布者与描述对象分开，关系有证据 |
| ENT-04 | 品牌下多产品 | 记录已核验产品关联及完整性限制，不自动研究全部产品 |
| ENT-05 | 产品版本与 SKU | 版本／规格绑定母产品，SKU 编码带命名空间，不跨商家误合并 |
| ENT-06 | 跨国家或渠道定价 | 保留各报价条件和日期，不覆盖为一个价格，不误报为同条件冲突 |
| ENT-07 | 供应／合作／竞争并存 | 分别记录方向、范围、时间与证据，不强选一个角色 |
| ENT-08 | 关系变化与未知时间 | 保留关系版本，获取日期不当生效日期，旧材料不证明当前关系 |
| ENT-09 | 正确合并与错误合并 | 仅合并同一身份重复记录，保留映射；不能合并品牌与所有者或集团与子公司 |
| ENT-10 | 混合实体拆分 | 逐条分配事实与关系，无法归属留待消歧，不复制给全部新实体 |
| ENT-11 | 纠错与报告追溯 | 定位受影响证据／结论，重做相关检查；历史报告和旧引用保留 |
| ENT-12 | Company／Organization 及扩展类型 | 同一组织不因类型细化重复建节点；扩展类型明确语义，无证据不凑节点 |
| ENT-13 | Person、Market、Industry、Channel | 人物限定必要公开角色；其他类型有边界定义，不仅凭标签相同合并 |
| ENT-14 | 来源冲突或证据不足 | 身份／关系保持未决并限制结论，不以结构齐全宣布消歧成功 |

## 验收场景

以下需用实际任务观察，不以格式检查代替行为验证。

| 场景 | 应观察到的行为 |
|---|---|
| 只给名称 | 按 report-delivery.md 的 RPT-01 验收 |
| 名称不明确 | 只补身份缺口，未确认前不混合不同对象资料 |
| 不同业态 | 维度选择有本次对象与目标依据，不按行业标签套固定表，共同保留证据要求 |
| 同对象不同目标 | 框架能随决策问题变化，而不只改变标题和输出语气 |
| 框架遗漏 | 区分缺问题与缺证据，保留原要求并说明修订与影响 |
| 工具与站点 | 使用真实可用能力，受限停止，解析失败不当无结果；摘要不直接成为证据 |
| 明确专项 | 保留用户必需问题，不因模式或预设删掉 |
| 资料能力不足 | 说明限制，使用已提供材料或给缺口，不用记忆编事实 |
| 价格缺证 | 不猜数，不以未找到认定免费或没有某版本 |
| 失败与空结果 | 失败、未查、未找到、不适用分别记录 |
| 只有第三方推测的目标客户 | 识别不足并补证，未解决时不写确定性客群结论 |
| 来源冲突或过期 | 明确冲突和时效影响，核查后才能采用 |
| 同一候选多标签 | 保留逐标签依据、实体去重，避免重复研究 |
| 我方优势／销售回应 | 要求相关双方证据；不足标缺口，不凑三个优势 |
| 变更读者 | 改分析问题但共用事实；仅改格式不重采 |
| 新增对象或维度 | 说明影响，只做相关补研，保留旧成果与版本 |
| 即时周报 | 明确内容窗口，不创建周期任务 |
| 报告检查失败 | 返回相应步骤修正，不能直接交付为完整报告 |
| 保存或恢复失败 | 明确实际结果，不给不存在的文件或承诺已恢复 |

## 质量与恢复验收

| ID | 场景 | 应观察到的行为 |
|---|---|---|
| QUA-01 | 价格／部署／功能已证实，客群仅推测 | 4 个必选单元只覆盖 3 个，75%，不得判充分；有额度补研，耗尽列缺口 |
| QUA-02 | 不适用与缺失 | 不适用须有依据；未知／未找到不计覆盖；分母为零时 null 并重新审视问题 |
| QUA-03 | 转载与关键判断 | 同稿多站只算一个独立组；关键判断不足两个独立组不通过；官方价格单来源仅支持归因事实 |
| QUA-04 | 价格与历史事件 | 48 小时前价格超 24 小时窗口；成立事件可作历史事实但本次核原始记录，不刷新旧内容时点 |
| QUA-05 | 临界预算与并行 | 达调用／文档上限前拒绝超额任务，子任务先预留，全局计重试及轻扫，不按 Worker 重置 |
| QUA-06 | 补研无进展或返工耗尽 | 一轮补研无改善停止；返工分类与全局同时计数，停止后不交付有误的完整报告 |
| QUA-07 | 三态与目的 | 100% 覆盖仍有关键冲突不能充分；只核实名称不足以回答定价问题，判不足而非有限完成 |
| LED-01 | 台账结构 | 正例通过 Schema，缺少原文／来源时间、非法状态或缺 manifest 文件哈希被拒绝 |
| LED-02 | 语义守卫 | 悬空引用、重复 ID 版本、来源副本不一致、空支持的 supported Claim 即使结构可过也拒绝接纳 |
| LED-03 | 时间与实体变更 | 合并／拆分保留旧 ID 和版本及依据，未归属材料不强分配，重查受影响覆盖和报告 |
| LED-04 | 恢复与重复执行 | 按 manifest 哈希及 task/event 恢复；只加载有关记录，不重复完成操作，不丢预算 |
| LED-05 | 损坏或结果不明 | 保留损坏文件和诊断，从完整检查点恢复；不静默截尾，不盲目重放未明操作 |
| LED-06 | 双格式生成 | PDF/PPT 分别引用相同输入快照与哈希；段落到 Claim 到 Evidence 到原文双向可追溯，不互相转写 |
| LED-07 | 新事实与导出 | 无台账事实禁止直接写正文；事实变化产生新快照，格式变化保留原快照但不覆盖旧产物 |

以上是待真实任务执行的验收契约，结构正反例通过不等于跨记录守卫或报告生成已自动实现。

| SRC-02 | 官方宣传与效果 | 按主张确定来源级别，不因官网身份就把效果宣称当实测结论 |
| REV-01 | 少量或受限评论 | 按采样窗口记录数量和局限，个案不推总体；预算不足不强凑目标 |
| REV-02 | 重复与疑似操纵 | 保留去重依据和敏感性结果；疑似信号不写成已认定刷评 |
| REV-03 | 不同评分量表 | 分平台呈现；转换尺度不代表可直接平均或排名 |
| VAL-01 | 空实例目录 | 记录零实例及未运行原因，不标全部验证通过 |
| VAL-02 | 受控案例 | 标合成输入、同任务评审和实际计算范围，不冒充独立真实业务验收 |

## 维护检查

修改技能后检查入口元信息、包内引用、展示信息与规则一致性；确认完整技能包独立可读。真实行为验收注明实际工具、材料、产物与未完成项。没有执行真实任务时，仅报告结构检查结果。
