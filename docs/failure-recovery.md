# 外部工具失败、延迟执行与恢复协议

版本：0.29.0；2026-11-04。本文是待实现的统一协议，覆盖搜索、网页、API、模型、解析与子 Agent。本轮不修改运行代码、持久化 Schema 或状态机，不宣布自动重试、人工挂起或恢复已接通。模块分工见 [模块契约](module-contracts.md)，来源层见 [采集设计](data-collection.md)。


状态目标以 [状态机 v2](state-machine-v2.md) 及其迁移目录为准：独立缺口／补研／报告 QA、两个确认等待及 CANCELLED 替代此前内部阶段安排。本文标为当前或迁移前的 v1 边界继续描述未变更源码；新状态与恢复须先实现迁移和守卫后启用。

## 三种情况不能混为一谈

任务失败、未找到资料、暂时无法执行分别属于执行结果、资料发现结果和调度状态。一次调用失败不必导致整个研究失败；某查询正常返回零结果也不表示该竞品没有相关能力。统一协议必须保留这几个独立维度，禁止用空列表、null、空字符串或“未找到”吞掉异常。

| 情况 | 含义 | 用户可见说明示例 | 对研究完成的影响 |
|---|---|---|---|
| 执行失败 | 已尝试但未完成约定操作，或结果无效 | “页面解析失败，尚未取得可核验正文” | 保留失败及缺口，按策略恢复；不计为已查无资料 |
| 未找到资料 | 指定查询／来源读取与解析完成，确实没有匹配信息 | “在本次查询与已读取范围内未找到公开价格” | 不是不存在的证明；必需问题仍可能未满足 |
| 暂时无法执行 | 有明确阻塞条件或未来执行条件，当前尚不能继续 | “服务暂不可用，等待恢复；本轮尚未完成该项” | 保留未完成状态及恢复条件，不伪装失败终态或成功空结果 |
| 结果不明 | 请求可能已在远端执行，但本地没有确认结果 | “调用超时，需先核对执行记录” | 先对账，不自动重发，不能判断为未执行 |

“未找到”只描述记录过的查询、时间、来源与读取覆盖范围。单页 404 是该 URL 不存在；HTTP 200 是传输成功；搜索无命中是该查询无命中，三者都不能单独证明某项业务事实不存在。资料获取成功也不表示 Evidence 已通过验证。

## 分层结果契约（待实现）

以下字段和枚举是目标设计，不能直接填入当前 ToolResult 或 TaskResult。一次尝试记录不可变，新尝试另记；操作汇总与研究单元状态由记录派生。

| 层级 | 目标表达 | 约束 |
|---|---|---|
| AttemptRecord | attempt_id、operation_id、parent／work_item、task／research_revision、plan／policy_hash、工具／提供方／Adapter 版本、参数指纹、起止时间、预算预占及实耗、工件／错误引用 | 尝试结果为 succeeded／failed／cancelled／unknown；未派发不伪造一次网络尝试 |
| OperationResult | execution=succeeded／partial／failed／deferred／cancelled／unknown；discovery=found／empty／partial／not_evaluated；子项覆盖、成功工件、未完成项、原因 | failed／deferred／cancelled／unknown 的操作级 discovery 必为 not_evaluated；partial 的成功子项可各自 found／empty，父级不得空结果成功 |
| FailureRecord | 稳定 code、category、发生层、脱敏说明、实际影响、诊断依据、provider／resource 范围、可恢复条件、结果确定性及原始错误安全引用 | retryable 是有上下文的策略判断，不靠模型或异常文案自行赋权 |
| RecoveryDecision | retry／fallback／skip_optional／defer／request_input／stop；原因、责任方、策略版本、关联操作、范围、剩余额度、最早执行时间、截止时间、验收条件 | 只有 Orchestrator 可批准并执行；决定不等于已经完成动作 |
| ExecutionCheckpoint | 当前技术阶段、执行处置、未完成单元、依赖、重试时间／人工事项、租约、版本、预算、已接纳工件与迟到结果规则 | 恢复不能只读取 latest state 后从头重跑 |

语义提取器完成扫描但没有候选可记局部 empty；全文未读完、解析失败、内容被截断时不得记全局 empty。已有工件与错误分开保存：当前 ToolResult 的 error 禁止携带 data，未来若允许部分成功需显式新增契约，不能塞进旧 data 或只返回成功子集。

研究单元另记 not_started／in_progress／deferred／needs_input／collected／not_found／failed／not_applicable 等采集视图，证据充分性由 Research QA 单独判定。not_found 只能由成功且覆盖明确的查找过程得到；not_applicable 需要问题适用性依据，不能用于包装失败或省预算。

## 七类故障与默认处置

| 场景 | 分类及诊断要求 | 允许的目标处置 | 禁止的解释或动作 |
|---|---|---|---|
| 搜索接口不可用 | 区分暂时网络／服务错误、解析格式变化、访问受限、合法零命中 | 符合可信重试策略的暂时故障可有界恢复；格式变化修 Adapter；无可用来源则保存缺口 | 把接口错误当零命中、换搜索入口绕验证码／限流 |
| 网站无法访问 | 记录 DNS／连接／HTTP／证书／权限原因；404、5xx、403 不能同类处理 | 暂时服务故障按策略；URL 错误交 Planner 查证；限制停止该资源路径 | 关闭证书验证、绕地址限制、把 404 当产品能力不存在 |
| 网页只有动态内容 | 静态壳／正文不足时 content_insufficient；有明确迹象才标 dynamic_content_required，不仅凭文字少推断 | 有已授权、已实现且符合相同边界的渲染能力才可转用；否则说明不支持，考虑已授权独立公开材料或用户文档 | 空正文当未找到；假称已有浏览器采集器；换渲染器绕访问限制 |
| API 超时 | transport_timeout 或 execution_unknown；本地超时不证明远端未处理 | 先查收据／幂等记录；确定安全后才有界重试或延后 | 每次换 ID 重发、自动认定取消成功、漏记远端可能费用 |
| 模型调用失败 | 暂时服务错误、凭据／配额、输出结构错误、拒绝、语义不合格分别记录 | 暂时错误有界恢复；结构错误可受控修复；配置问题请求可行动的协助；语义问题走质量返工 | 空回答当无事实、绕模型拒绝反复改提示、换模型自评 PASS、用记忆填缺口 |
| 资料解析失败 | unsupported_format／parse_error／content_incomplete／artifact_corrupt，保留原工件与解析版本 | 对完整原件可用已注册兼容解析器重解析，或用户提供可读版本；损坏快照先诊断 | 同解析器无限重复、丢页面后声称完整、损坏快照静默联网补抓 |
| 子 Agent 执行失败 | 子任务异常、超时、失联、无效输出分别记；租约失效不证明子调用已停止 | 父级保留其他成果；对账后重派未完成工作或有界拆分；新结果仍须完整核查 | 子代理和父级各重试一套、重派全部对象、把失联对象填空后继续报告 |

权限不足、未注册能力、非法参数、地址不安全及内容超限不是暂时服务故障。修正参数须形成可追溯的新操作；工具／策略不支持时不能反复重试。凭据等配置通过受控配置渠道处理，不在聊天、日志或报告中索要或输出密钥。

## 重试：集中决策、有界执行

重试由 Orchestrator 的可信策略统一控制，Registry 执行，Adapter 上报诊断。SDK、Adapter、子代理默认关闭隐藏重试；若提供方客户端内部无法关闭，必须能枚举并计入每次实际尝试，否则不宣称预算受控。Planner 只规划新查询／替代工作，不独自启动失败重试。

当前公开搜索与抓取保持原有单次尝试、无自动重试；验证码、限流、登录墙、403／429 等访问限制立即停止受影响路径，不轮询、不换入口／代理／账户绕过。新协议不改变这条用户约束。限制作用到相关 provider、凭据、域或资源的真实边界，不能故意缩小为单 URL；无关且独立获授权的工作可由主控继续，保留受限项缺口。

未来针对明确允许恢复的服务／本地操作，可采用初始策略：每 operation 最多 2 次真实尝试（首次加 1 次重试），按有上限的指数退避加抖动安排，例如基础 1 秒、退避上限 8 秒；数值是待评测配置，不是当前行为。实际延迟不早于可信服务的 Retry-After（若适用），但不能突破总截止时间，也不能把这个头解释为可绕过访问限制。超过等待期限则延后或停止，而不是缩短服务要求抢跑。

是否重试需同时满足：错误属于可信允许类别、操作可安全重做／远端结果已对账、权限与版本仍有效、未触及受限停止规则、有剩余尝试和资源预算且未超截止时间。未知异常默认保守处理并诊断，不自动归 transient。已知取消由用户要求触发时停止派发，不自动重新启动。

对模型结构错误可另设最多一次修复调用，保留原输出与错误；该调用计入同一恢复额度、模型预算与总期限，不能与传输重试相乘形成循环。修复只约束输出结构，不能填造事实、删限制或替代语义 QA。拒绝／安全拦截不通过重复改写绕过。

## 降级、跳过与人工介入

降级是执行方法变化，不是降低问题和证据标准。替代路径须真实可用、已授权、保留来源与元信息、满足当前问题及预算，并记录旧路径失败原因。可接受例：完整 PDF 已保存，兼容解析器重读原件；不可接受例：全文抓取失败后把搜索摘要当正文事实。模型切换另核对已配置提供方、数据传输权限、费用、能力与输出契约，不能把资料偷偷发往新提供方。

访问受限后的替代不用于重试该受限服务。独立公开来源若属于既有授权、并非规避限制且能回答同一问题，可由 Planner 在合法边界规划；官方价格缺失时第三方转述仍须保留归属，不自动替代“官方当前标价”。模式不因故障自动从 Deep 改 Quick，质量门槛不因预算紧张降低。

只允许跳过预先可选且不影响必需问题／依赖的工作，保留 skipped_optional、原因、未研究范围及预算记录。必需工作即使受限、超时或找不到，也不能改成可选／不适用或从覆盖分母删除。某个来源失败但其他证据已满足该单元标准时，可以结束该失败来源分支；记录仍保留，这不等于跳过必需问题。

仅在用户能提供具体帮助时发起人工事项，例如补充正确官网、提供可读原件、修正获授权服务配置、决定是否缩小明确范围或增加有限预算。说明已完成什么、卡在哪、需要什么、解决后恢复哪些工作；不能笼统问“是否继续”，不能要求用户证明资料存在，也不能指导绕 CAPTCHA 或权限。

人工输入绑定 operation／research_revision／policy_hash 和具体问题；沉默不是授权，超时也不是自动批准。用户资料保留 user_provided 与获取方式，经常规解析与 QA 后才能成为依据。明确范围变更按现有授权／项目锁处理，不能用人工标注把失败直接改成 verified。

## 延后与恢复：业务等待不冒充范围确认

目标采用状态机 v2 的 15 个 ResearchState 阶段，另加持久化 execution_disposition=active／deferred／needs_input 等执行处置及 RecoveryDecision／Checkpoint；不使用 WAIT_CONFIRM 冒充 API 恢复或配置修复。现有 WAIT_CONFIRM 只用于绑定实体／范围确认，新增处置、对外 deferred／needs_input 结果及恢复协议必须显式迁移 TaskResult、StateContext／Memory 和入口后才能启用。

未来 deferred 对应未完成的非终态，附阻塞条件、not_before、截止时间及恢复方式，不返回最终 report_path；needs_input 另绑定待答事项。当前 pending_module 只表示能力未实现，不能充当服务暂不可用。v2 的 FAILED／COMPLETED／CANCELLED 终态均不可重开，失败后需要关联新执行且保留错误原因和预算谱系。

当前代码没有持久化延后、人工运维等待或定时唤醒能力。上线前不能声称“稍后自动继续”；需要终止的调用仍返回现有错误及诊断。未来延后优先保存并退出执行槽位，由明确恢复入口检查就绪；没有已授权调度服务则由用户主动恢复，不擅自创建后台定时任务。超过截止时间仍不可执行时保存停止原因，不无限等待。

恢复依次核对：当前授权／项目锁、研究修订与策略、工件散列、已用及预占预算、操作账本、远端收据、阻塞条件、依赖与租约。未满足条件仍延后或明确停止；不得直接重新执行整份计划。跨模块重规划走合法边界，RESEARCHING 不偷偷跳 PLANNING；来源替代若需新业务工作项须待合法规划路径，无法衔接则按现有失败与关联执行协议处理。

同一 operation 的新尝试具有新 attempt_id，但关联相同参数指纹和恢复授权；相同 attempt 重放只读账本，已记录失败不会因重放变成新请求。当前搜索 request_id 重放返回旧结果／错误，reserved 拒绝重发；未来 attempt 到 request_id 的映射及预算必须独立迁移，不能通过随机 ID 规避这条约束。

失联／取消／超时后可能存在远端运行；先查询可用收据或等明确结束。确实无法确认时保持 unknown，已预占费用与调用不擅自退还；只有可信策略允许幂等安全重做且保留潜在重复费用时才开新尝试。不承诺跨网络 exactly-once。

子 Agent 使用父级分配、心跳／租约和幂等工作项接纳。替代执行前核对旧子任务及其工具账本；迟到结果只归原修订并按版本接纳，不能重复计证据或覆盖新结果。无依赖的其他工作可继续；权限、全局预算、存储完整性等共享故障则停止相关全局派发。多个代理共享提供方故障冷却，避免每个代理独立尝试造成重试风暴；访问受限不做自动半开探测。

## QA、报告与用户反馈

Research QA 分别接收采集完成情况、发现结果和证据支持记录：failed／deferred／unknown／not_found 均不能自动算合格单元。成功子项可保存复用，但依赖未满足的分析不执行；必需缺口仍走定向补研或停止。完整流程保留 [Research QA 与 Report QA](report-qa.md)，不能把系统故障归为内容不存在。

可选来源失败但其他材料满足全部要求时，允许报告注明方法限制并交付；必需维度未满足则不得交付伪完整报告。当前没有部分成功的 TaskResult，不用失败路径返回最终报告。诊断清单与草稿不是成功交付，旧成功报告保持原时点且不冒充本轮成果。

对外至少展示：受影响问题、当前处置、可理解原因、已完成／未完成范围、尝试次数与剩余条件、是否需要用户动作及如何恢复。示例分别为“该查询执行完成但未命中”“抓取失败，未评估页面内容”“服务暂不可用，本项已延后，尚未找到与未找到均未判定”；不统一显示“暂无数据”。

日志保留层级 code、操作／尝试关联、时间、策略决策与预算；不包含凭据或未脱敏异常。恢复动作失败也要记录，不覆盖根因。存储不可写时明确无法保证检查点持久化，不假称可恢复或已保存诊断。

## 当前基线与实施顺序

当前 [ToolRegistry](../src/steal_her_heart/tools.py) 对工具权限、参数、输出、超时和执行错误给出结构化 code；ToolResult 只有 ok／error，ToolError 只有 code／message。Registry 超时提示执行可能不完整，未提供统一可重试分类或恢复执行器。

[搜索解析](../src/steal_her_heart/search_html.py) 仅明确的无结果页可返回空元组；格式不识别、链接不可用和访问受限均报错。[调用账本](../src/steal_her_heart/search_ledger.py) 保存预占／成功／失败，重放失败不重发，未完成预占拒绝重发。搜索和抓取当前单次尝试，错误消耗已发起额度；没有通用恢复调度、模型提供方、动态渲染或子 Agent 执行器。

现有工具、HTTP 边界、账本及超时测试只能证明对应已有能力，不能证明新协议或生产研究恢复。新统一类型须保留历史 code／message、未知错误及原工件；不能把旧 failed 迁移成 empty 或把无类别旧错误推定可重试。

按单模块实施并分别验收：①结果分类和旧错误映射；②统一恢复策略与预算；③持久化延后／人工事项、恢复入口和租约；④Adapter／模型／子 Agent 接入；⑤Research QA、报告与故障注入端到端验收。当前公开工具的无自动重试与受限停止规则保持，其他服务的重试需单独实现和验收。
