# P0／P1／P2 开发路线

版本：0.30.0；2026-11-04。

按用户提出的优先级推进，每次只开发一个模块并完成对应验收。本页按实际代码区分已有子模块与尚未打通的产品链路；文件、Schema、配置、测试替身或一份示例报告不算能力完成。

**当前仍不能从生产入口自动生成完整、有证据支撑的竞品报告。** 已有 P0 第 4 项的本地终端范围确认与最终锁定子模块；本轮补充产品规则；已有 [分层状态机 v2](state-machine-v2.md) 及 [逐边迁移目录](state-machine-v2.yaml)，保留 [Research Task／Worker 调度设计](task-scheduling.md)，保留 [Agent 十项标准契约](agent-contracts.md) 与 [YAML 目录](agent-contracts.yaml)，保留 [外部故障与统一恢复设计](failure-recovery.md)，保留 [三种研究模式与共享策略设计](research-modes.md)，保留 [Report QA 与定向返工设计](report-qa.md)，并同步 [模块职责与验收](module-contracts.md)，运行代码和状态机没有变化。多轮修订、分析、证据管理、统一采集、Discovery 与 Research QA 约束保留。Codex 聊天用户消息来源认证及自动桥接仍待接入。默认只输入产品名的路径不要求创建项目或执行两次项目确认。

## 产品规则修订的接入顺序

0.30 增加 [八项产品规则](product-design.md) 和 [行业包设计样例](industry-pack-examples.yaml)，不是新的研究执行器。先单独实现行业配置校验与目的驱动的维度解析，验证不同业态、混合业态、字段分级及冲突处理；再随 Planner／范围版本接入，以已通过的模块为基线。渐进访谈、多标签候选、读者决策和即时简报路由分别迁移验收，不一次实现所有模块。行业工具及分析方法按任务需求追加；定时监测单独设计，不自动进入研究 MVP。

## 研究模式接入顺序（待实现）

[Quick／Standard／Deep](research-modes.md) 是跨模块策略，不是新增三套执行器。先在需求／Planner 模块落地版本化模式选择、策略解析和可行性；再随 Orchestrator／Research 落地共享预算、预留和任务调度；随后由 Validator、Analysis、Reporter／Report QA 消费同一策略，最后验证切换模式的增量链路。每一步完成对应验收后继续，不要求在研究基础尚未接通时一次实现三条完整链路。

当前无 mode 字段、模式 CLI 参数或自动选择器。默认 Standard、不强制提问；Quick 不降低事实质量，Deep 不自动扩范围。全部模式保留完整 QA，参数参考与验收见研究模式设计，不在各模块复制独立的数字预设。

## 失败恢复接入顺序（待实现）

[统一恢复协议](failure-recovery.md) 先实现结果分类和旧错误映射，再实现主控恢复策略／共享预算，随后迁移持久化延后、人工事项、恢复入口和租约，按能力接入 Adapter／模型／子代理，最后验证 QA 与实际交付的故障链。每模块独立验收；不能先开放自动重试，再补幂等和预算。

现有工具有结构化错误、合法零结果识别和调用账本，无统一恢复。公开搜索／抓取仍不自动重试，受限明确停止；未来可恢复服务须独立配置和验收。暂不可执行不能与 failed、未找到或 pending_module 混用，目标 deferred／needs_input 须显式迁移，不伪装现有状态已支持。

## Agent 契约接入（待实现）

[八个 Agent 定义](agent-contracts.yaml) 是开发依据，不是新的运行注册表。随各模块先实现共同信封／版本校验与该角色输入输出，再接工具／服务权限守卫、实际执行和错误映射，最后验证消费者准入及恢复。当前接口需逐个显式迁移，不因 YAML 已有字段就把全部模块标为完成。

验收必须能拒绝越权调用、失配结果与伪造 PASS，区分采集完成、证据充分、草稿生成和最终交付；仅结构夹具或 Prompt 自评不足以证明 Agent 正确。原有一个模块实现并验收后再继续的顺序不变。

## Worker 调度接入（待实现）

[任务调度](task-scheduling.md) 按任务／结果契约与旧项目映射 → Planner 问题拆分／依赖 → 主控持久队列、能力匹配、预算和租约 → Worker 执行／结果接纳 → Validator 屏障、定向补研及恢复推进。每模块单独验收；先有界顺序／并行，不要求先建设分布式队列。

竞品与 Worker 不固定一一对应。已有 CollectionJob 仍是对象范围快照；ResearchWorkItem 的 depends_on 不代表已有调度执行器。重点任务不改变已确认的完整 QA 范围，实际模式预算和受限停止条件不因增加 Worker 放宽。

## 状态机 v2 接入（待实现）

按 [状态机 v2](state-machine-v2.md) 先实现纯状态／迁移守卫，再接持久事件、确认绑定、取消与旧快照迁移，随后接子任务队列／租约／幂等恢复，最后逐执行器接入与端到端验收。15 个任务状态与 14 个子任务状态分别保存；新增枚举不等于真实研究已运行。

本设计替代此前缺口分析／报告 QA 的内部阶段和三条 REPORTING 回边方案，改为独立 GAP_ANALYSIS／SUPPLEMENTING／REPORT_QA。确认阶段仍可按实际授权跳过；取消独立于失败，完成与取消竞争提交，旧快照缺依据不自动续跑或升级 QA。

## 按依赖实施

P0 的产品目标保持优先；沿用已有范围确认机制，依次交付：统一采集契约并适配已有搜索／抓取 → 最小 Source／Evidence／Claim 对象、版本及关系存储 → 最小模型提供方 → 动态 Planner → 自动结构化提取与 Research 执行器 → Validator 内的 Research QA 及补证闭环 → Analysis 与 Claim 支持核查 → Reporter／Report QA、报告追溯与受控交付。每次仍只实现其中一个模块并完成验收。Orchestrator 随模块接入依赖调度、预算、恢复和终止决策，不另写业务规划或站点解析。独立搜索／抓取的真实来源验收随可访问渠道单列推进。

证据管理分批接入：先做数据完整性和精确版本引用，再接核验／时效／冲突／评级记录，最后接报告双向索引。记录可存不代表语义判定已可用，反向索引可查不代表报告已生成。Research QA 通过不能自动证明之后生成的 Claim；Analysis 交付前还需检查关系语义，Reporter 转述后再核对措辞与版本映射。当前任务的证据基础可提前实现；跨任务自动检索、刷新和增量复用继续属于 Phase 6。

Analysis 继续按单模块拆批：先实现绑定范围／计划／QA 的比较基础与引用校验；再逐项实现定位、功能、定价、客户、商业模式和有场景依据的优劣势；最后实现机会、威胁与差异化决策建议，并核对 Claim 支持后交 Reporter。代码负责可复验的单位／条件归一与计算，模型负责有依据的解释和假设；不能用模板字符串或固定 fixture 冒充执行器。具体验收以分析引擎设计为准。

Phase 5 增加交付必需的 Report QA：先做输入／问题清单／版本绑定和可确定的检查，再接语义评估及独立参考案例；随后独立实现 ReworkTicket、v2 的 GENERATING_REPORT／REPORT_QA 分阶段与根因回边、持久化与恢复；最后接修复后完整重检及实际文件发布。呈现返工从 REPORT_QA 回 GENERATING_REPORT 后重新完整 QA，不用状态自循环掩盖重试。每个模块测试通过再继续，不能只加允许边就启用返工。

返工共享全局预算、访问限制和无进展规则，轮次单独计数；补证须重新 Research QA，新 Claim 须核查，新草稿须完整 Report QA。当前没有这些回边和完成守卫，未升级时仍按现有失败路径停止；未来可修复缺陷应定向返工，无法修复、预算耗尽或持续无进展才失败，不为出报告降低质量标准。

决策建议必须对应用户问题，说明证据／反证、适用前提、影响机制、候选行动、取舍和验证办法。无我方背景仍可研究单对象并提出条件性启示；只有用户要求我方建议才补必要背景，保留 user_provided 来源，不能强制项目初始化或把配置当核验事实。目标／资源变化只使受影响建议重新评估，不自动重采所有事实；若实际范围变化仍遵守现有确认与锁规则。

Phase 6 的多轮增量研究按“业务修订与变更基线 → 依赖影响集 → 资产准入及差量计划 → 运行中变更／预算协调 → 增量分析与报告发布”逐模块实现；每项先验收。对象、维度和依赖标识需在前置模块设计时保留，不等到报告完成才靠文本猜关系；这不代表提前接通整个跨任务复用链。

只重跑受影响任务不等于只核查新增字段：当前范围的必需单元、冲突和版本绑定仍要汇总出新 QA。新增 C 可影响全局排名／摘要，但不必重抓 A、B 的无关字段；全体新增同一维度只补该维度缺口，局部加深则保留明确对象范围。终态不重开，新执行关联旧修订并延续适用预算和访问限制；项目已有锁不能直接覆盖，修订评审协议仍需独立实现。

基础 Adapter 与来源关联不需要等待模型；自动选择片段、结构化改写和语义核查依赖真实模型及评测。最小闭环先面向已可访问的静态来源，随后按研究需要加入有限官网遍历，再逐个接文档、新闻和评论能力；顺序可随实际缺口调整。八类能力均有契约，不等于要求先实现全部工具，更不以批量开发平台爬虫作为开工前提。

QA 是 P0 的分析准入条件：先实现证据核查，再实现固定分母的逐格覆盖与缺口评估，随后接补证调度并验证回到 QA；每个子模块单独验收。仅构造 PASS 或跑通结构替身不能进入 Analysis 的实装验收。质量阶段位于现有 VALIDATING 内，不新增顶层状态；实际补证路径为 VALIDATING → PLANNING → RESEARCHING → VALIDATING。

Discovery 是显式发现请求的前置分支，不插入默认单对象路径。它依赖共享搜索／抓取、语义提取与候选依据核查，按“种子识别与四路发现 → 实体消歧去重 → 分类与可解释评分 → 用户修订及当前名单确认”逐模块实现并验收，之后接正式研究计划与完整 QA。项目模式再复用有效名单批准和最终维度锁；非项目请求与空名单结果需独立协议。现有 review-project 只能消费已准备的提案，不能视为 Discovery 已完成。

模型接入虽然出现在 P2 清单，但现有精确摘录工具不会自动选择相关片段、判断对象与维度，也不改写主张。通用 Research 需要先有可运行的语义提取提供方；不能用测试中的 `fixture_semantic_adapter` 填这个缺口。每次仍只交付一个模块，测试通过后再进入下一项。

搜索继续优先使用无需密钥的公开来源，访问受限时明确停止。此前受限的公开搜索探测不因新增代码或优先级清单被记为通过；不换入口、代理或重试绕过限制。每个平台的实际可访问性、静态正文和取证质量分别验收，不承诺通用 URL 抓取可以采到所有评价站与动态页面。

## 已有本地范围桥接

已有项目和准备好的提案后，在用户自己的交互终端运行：

```bash
steal-her-heart --project-name my-product review-project --review-file /path/to/review.json
```

提案结构以 [ProjectReviewRequest](../src/steal_her_heart/project_review.py) 为准：

| 字段 | 内容及来源 |
|---|---|
| discovery | 绑定当前项目背景摘要的 DiscoveryProposal，包含候选、分类、依据、来源与缺口；导入不证明联网已发生 |
| selected_ids | 本次建议纳入研究的候选 ID；终端展示后由用户确认，必须来自该提案 |
| library | 显式的版本化 DimensionLibrary，不自动读 Markdown 并假装已推荐 |
| core_field_ids／extension_ids | 选择的核心子集和库内扩展；省略核心子集时沿用底层 API 的默认行为 |
| selection_rationale | 本次字段选择依据，最终维度稿向用户展示 |
| readers | 可选读者配置；已有项目读者沿用并校验，未配置时须提供满足契约的读者 |

输入不能携带 approval、lock、approved_by、reply 或用户自填的批准时间。确认来自本次可信本地交互回调，不从提案正文或网页读取。终端展示候选和选择后，用户输入当次 token；名单批准保存后生成最终维度稿，再由用户输入新的 token。任一次拒绝、旧回复、项目或文件变化，都不能变成同意。

只有最终以实际落盘的名单、批准、维度提案、Markdown 和锁通过 `prepare_collection_jobs` 回读，结果才能标 `scope_locked=true`。`research_ready=false`，不会联网、启动 subagent、创建 Evidence 或报告。审计记录在项目 `.state/reviews/<review_id>/`；它便于定位结果，不能代表已实现任意中断恢复或跨资源原子事务。存储失败时 record_path 只是预期位置，不保证文件已写成。已有评审与锁不会被自动覆盖。

CLI 要求 stdin 和 stderr 都是 TTY，没有 `--yes` 或管道式批准。TTY 是本地交互边界，不证明人类身份或 Codex 用户来源；模型和脚本不能通过 PTY 代用户确认。未来 Codex 自动桥接必须从可信宿主消息接口验证回复来源，再接同样的摘要、持久化与回读链，不能信任 JSON 中的 `role=user`。

已有范围桥接检查与实现散列见 [项目评审验收](../validation/project-review.json)。已有测试层次和真实生产 E2E 缺口见 [验收说明](acceptance.md)；历史阶段记录不替代当前回归，也不自动证明研究结论准确。
