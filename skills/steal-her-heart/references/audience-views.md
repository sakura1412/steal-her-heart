# 配置读者与四类常用视图预设

版本：2；日期：2026-11-03。来源：用户指定四类读者及内容重点。适用于所有行业与系统品类；角色是输出视角，不是产品所属行业，也不是四个独立 Agent。

## 一份研究资产，多种决策输出

所有视图引用同一份已验证 Source／Evidence／Analysis。角色选择决定重点、术语、深度和篇幅，不改变事实、置信度或时间口径。角色来自项目配置，用户可以选一种或多种预设，也可定义投资人等角色；不强制输出四份。未完成结构化配置时保留阶段0原答并在阶段2提案中明确，不静默默认四类。若新增视图需要新数据，Planner 提出对应补证任务并继续遵守范围确认规则。

Reporter 从已有结论中选择并组织内容，不能为话术更有说服力而重新编造事实。公开资料足以支持行业观察，不足以证明真实成交原因、私有价格空间或用户实际说过什么。

## 产品经理：支持产品决策

必备内容：

1. 能力／功能对比矩阵：分别记录“我方有／没有／未知／不适用”和“领先／持平／落后／未知”。具有某功能不等于领先；官网未提及不等于没有。
2. 差距分析与机会点：区分已证实差距、场景取舍和待验证机会；引用原始证据。
3. AI 等趋势能力：仅跟进与该品类、目标用户相关的趋势，不把 AI 强加给全部行业，也不把宣传等同已上线。
4. 路线图建议：包含建议、对应用户问题、证据、影响范围、依赖与下一步验证。建议不是已批准需求或版本承诺，不虚构研发工期。

软件比较功能，硬件比较性能／可靠性，服务比较流程／体验等。未提供我方产品时，可以保留竞品事实，但我方状态、相对位置和路线图结论须列缺口。

## 销售领导：支持竞争与资源决策

必备内容：市场格局和近期动向；可比条件下的定价与我方价格空间；赢单／丢单原因归纳；优先竞争对象及应避开的场景。

价格比较须对齐产品／服务范围、币种、地区、计费单位、周期和折扣条件。私有报价、成本、毛利、授权底价未知时，不计算虚假“可降价空间”。

真实赢输归因需要授权成交／丢单记录、访谈等，说明样本数、时间窗和偏差；公开评价只能生成竞争假设。没有这些数据时输出“待验证原因”，不能冒称内部复盘结论。“打谁／避开谁”必须说明客群、需求和适用边界，不给无条件结论。

## 普通销售：核心交付为一页 Battlecard

每个竞品一张卡，结构固定：

| 区块 | 内容与要求 |
|---|---|
| 页眉 | 竞品、我方产品、适用客群／场景、更新时间、草稿／就绪状态 |
| 对方三个主要卖点 | 每点关联证据，配客户可能怎么说、我方回应；假设客户表达明确标“可能”，实际引语关联记录 |
| 我方三个差异化优势 | 对应具体需求与适用条件，引用双方证据，不写无法证明的“唯一／绝对领先” |
| 探测问题 | 用开放、中性问题了解客户流程、需求、约束与评价标准；不要在问题里预埋未经证实的短板 |
| 不能说的话 | 错误／过时／超出适用范围／证据不足的表述、原因及更稳妥的替代表达 |
| 页脚 | 简短来源编号、资料缺口与使用限制；完整证据留在共享研究资产 |

“三个”是完整卡的目标，不是编造额度。证据不足时只保留有依据的项目，状态为 draft 并列具体缺口，不能用重复引用凑数。未提供我方产品及定位时不能捏造优势或反驳。

一页是交付要求：正文短句、便于现场扫描；详细论证移至来源附件。当前 Schema 的 one_page 只记录版式目标，不证明已排成一页。Phase 5 必须在明确打印／导出版式后检查一页、文字不溢出、可读且来源可追溯，不能只看 Markdown 行数。

## 运营：支持增长实验

必备内容：获客渠道、内容与活动打法；促销和定价策略变化；新手引导、客户成功动作；可借鉴的增长玩法。

渠道与活动记录可观察事实、受众、时间、入口和来源；没有可核验数据不能声称转化率、获客成本或渠道贡献。价格变化需前后可比版本，不能只凭当前价格推断调价。

新手引导与客户成功按品类转译为开通／首次使用／购买后指导／售后服务等。借鉴玩法写为可验证实验：假设、对象、执行动作、观察指标、停止条件；没有真实实验不能承诺增长效果。

## 契约与完成门槛

[audience_views.py](../../../src/steal_her_heart/audience_views.py) 定义常用 ReaderViewSpec 预设与可配置 audience 的 Battlecard；ReaderProfile 配置见 schemas.py。卡片直接引用共享 Analysis 内的 evidence_id／claim_id；未知引用、他方卖点混入、重复凑数、无我方证据的优势和无依据真实客户引语都会被拒绝。

Battlecard 的 ready 仅表示结构与引用关系达到门槛，不表示语义正确、授权对客使用或一页排版已通过。语义、时效、客户记录来源、双方可比性与版式由后续 Validator／Reporter 验收。草稿可无 Analysis，但不得填无依据内容。

四类内容已定义契约，当前没有生成报告或自动选择角色的执行代码。已有通用八章节可作为底稿／附录，角色交付采用本页结构，不强迫所有视图使用相同篇幅。任务状态与数据库协议不因角色视图而改变。
