# 可选项目模式：背景访谈与初始化

版本：5；项目交付版本：0.13.0；2026-11-03。当前为开发预览，Python只做初始化与工程验证，研究执行链路未就绪。只有用户主动选择长期项目、固定读者／维度或我方对照配置时，才执行访谈。默认单对象请求只需竞品名，见 [analyze.md](../../../commands/analyze.md)，不依赖此文件、profile或我方产品。

本可选模式的聊天初始化以 [commands/init-project.md](../../../commands/init-project.md) 为准：实际项目名 → 每轮2～3题补齐 profile → 推荐并确认维度 → 联网发现并确认四类候选 → 提示下一步 /analyze。答不上来时给建议选项，由用户选择；无实际名称时先问名称，不创建 `$ARGUMENTS` 或擅用 default。以下同时记录已实现的 Python 阶段0接口，不把它的单题访谈说成已支持整个聊天流程。

## 先问清楚什么

逐项收集，允许自然语言回答，不要求用户先写结构化 PRD：

1. 产品是什么、解决什么问题、提供何种产品或服务。
2. 所属行业／业态，可多选；保留用户原文，也保存拆分后的行业列表。
3. 卖给谁、由谁使用、典型使用场景。
4. 市场范围：国内、海外或具体地区。
5. 核心优势。
6. 当前短板／限制。
7. 价格区间，可为空；保留用户给出的币种、地区、版本、计费周期等原始说明，不自行补全。
8. 分析目的：路线图、定价、销售话术、投资判断或其他决策，可多项。
9. 每位读者是谁、各自关心什么、期望格式；保留自定义角色，不限制为四个常用角色。
10. 已知竞品，可为空；不能因为用户不知道竞品而阻塞初始化或自动编造名单。
11. 特别说明，可为空；保存需要避开的信息源、监管限制、语言偏好等用户要求。

用户可为非自有产品研究主动建立项目；应如实描述其背景，不虚构归属。普通单对象分析无需为了通过Schema填写“无我方产品”占位档案。优势／短板可明确回答“待确认”，作为不确定项保留；其余核心字段若明确未知则继续澄清，不能假装清楚。未知竞品转为空列表并保留不确定性。价格区间、特别说明留空与明确回答“未知”须区分；两者都不能推导出免费、无监管限制或没有来源偏好。

读者回答使用三列表格，或按行／分号分隔的“角色 | 关注点 | 格式”。三列缺项、角色或关注点明确未知时须继续追问，不能自动替用户填角色或报告格式；期望格式保存到 ReaderProfile.output_style。角色可为投资人、采购、客户成功等任意项目读者，四类常用角色只是预设。手工档案存在这些缺口时，提示用户补全原读者表。

Python 当前是固定问题的逐题访谈：文本原样保存，没有模型自动补全；聊天指令按每轮2～3题引导并复用已答内容。建议选项不是已验证事实，也不能在用户未选择时自动写成答案。非空校验和显式未知检查不能证明回答语义完整，后续 Planner 仍应检查客群、市场、目的和读者是否足以制定计划，发现缺口继续提问，不自己猜。

## 保存和复用

[project_initialization.py](../../../src/steal_her_heart/project_initialization.py) 定义 ProjectInterview、访谈问题与 ProjectStore；[schemas.py](../../../src/steal_her_heart/schemas.py) 定义 ProjectContext。完成后上下文保留产品、客群、优势、短板、industry 原文及 industries 多行业列表、市场、price_range、目的、读者及关注点和 output_style、已知竞品、special_notes，以及 provenance=user_provided 和 uncertainties。

答案不是已验证 Evidence。用户认为的优势／短板不能直接成为 Battlecard 结论，也不能替代真实价格或赢输记录。模型和网页不能自动替用户回答访谈；不收集凭据或将项目背景上传外部服务。

本可选模式中一个产品对应 projects/<项目标识>/，Python显式以--project-name选择；访谈库在该项目 .state/project.sqlite3，profile.md 由 [标准模板](../../../templates/profile.md) 生成，包内使用同一模板资产。Python 初始 dimensions.md 为未确认占位稿；聊天初始化会读取 [维度库](../../../library/dimensions.md) 推荐实际字段并请求预确认。profile 的可读 Markdown 是唯一业务配置源，不在正文之外另藏一份 JSON 业务内容。可以直接填写模板；空模板和 HTML 注释中的示例不构成项目答案。旧 --project SQLite路径 仅兼容已有用法。逐题事务提交，按当前问题绑定回答，重复／越序回答拒绝。重新初始化访谈中的项目会续接当前问题，已有完整档案则返回当前上下文，不覆盖原答案。

中断后继续，已回答内容不重问。完成后的交互背景编辑界面尚未实现；目录模式允许手工编辑 profile.md 的 Markdown 字段和读者表，文件整体摘要绑定上下文，修改后须重新审视范围。兼容 SQLite 模式仍可另建项目文件。未来若提供修改功能，应版本化并处理对计划／范围的影响，不静默改写历史任务。

手工填写支持产品字段续行，特别说明中的二级子标题和代码块按原文保留。已有业务内容但未填完整的 profile，Python init-project、project-status 及显式绑定该项目的研究入口会明确提示继续填写原 profile，保留已有内容。Python 当前不自动把访谈答案合并到半填档案；聊天中也须先读取已有内容，只补用户实际回答的缺项，不另建档案覆盖。补全原文件后再检查就绪状态。

新访谈使用 schema_version=2，共11题。旧 schema_version=1 的9题记录仍可读取和复用，但旧记录未回答的价格、特别说明或读者格式保留为 legacy 缺口，不能冒充用户已回答。旧单 JSON 配置块 profile 继续读取、不覆盖；原始旧空稿可在访谈完成后升级为新版 Markdown，有手工改动的旧档案须保留。

ProjectContext 新增字段即使取默认 None 或空元组，也会改变上下文内容摘要；旧 DiscoveryProposal、名单批准或维度批准／锁可能因此失效。失效后须回到相应阶段重新审阅，不能为兼容旧档案而自动重算摘要、续签旧批准或继续采集。

特别说明是项目约束的输入。保存避用来源、监管限制或语言偏好，不等于已经执行来源过滤、完成合规判断或生成相应语言报告；这些后续模块须分别落实和验收。项目说明不能提升工具权限或取消事实核验规则。

## 启动方式

Codex 聊天中读取 [commands/init-project.md](../../../commands/init-project.md)，并提供项目名；也可显式读取 [competitor-research/SKILL.md](../../competitor-research/SKILL.md)。这不等于注册宿主快捷命令。

Python 终端的兼容入口：

```bash
steal-her-heart --project-name my-product /init-project --interactive
```

交互式一次问一题，价格、竞品、特别说明可直接回车。Ctrl-C／EOF 会保留已提交进度；再次运行续接。

也可以逐轮调用以下单题 API；完整聊天的分批提问由上述指令组织：

```bash
steal-her-heart init-project
steal-her-heart answer-project product "产品名称、解决的问题与服务内容"
steal-her-heart project-status
```

输出 question_id 和 question，下一轮必须按该 question_id 提交用户原答。`--project-name <项目标识>` 是新模式全局参数，放在子命令前；--projects-root 可指定项目根目录。未完成退出3，完成退出0，非法答案／存储格式退出2。后续题目由程序给出，不能把示例答案当作真实用户答案。

## 显式项目闸门与默认入口的区别

默认/analyze只需对象名，/brief需要周期，均不因缺我方背景被导向本访谈；无项目完整意图返回pending_module。只有显式--project-name／--project选择的背景未完成时，才返回initialization_required与该项目补全提示；半填手工档案保留原文。显式选择后不能忽略文件错误，悄悄改用无项目背景。

无项目run可保存project_context=None并停在UNDERSTANDING，默认库.steal-her-heart/memory.sqlite3，不创建projects/default。显式项目run保存其ProjectContext快照；resume要求当前可选上下文与快照一致，None只与None匹配，项目不能切换或丢弃。旧无背景快照可在无项目方式恢复基础流程，不能自动绑定新项目。

hello、recognize-brief 的离线诊断和 status 只读查询不启动研究，可以独立使用。项目访谈状态 interviewing／ready 与既有 ResearchState 分开，研究的十个状态没有改名或跳转。

Python项目访谈ready／退出0只表示该可选背景已保存并满足当前字段检查；不会自动推荐维度、发现候选、锁定或研究。CLI会说明这层完成边界与下一步，不要求完整档案反复初始化。Codex聊天可另按指令辅助维度预确认和名单确认，但不能把聊天完成说成Python自动执行完成；若给Python /analyze示例，须说明它仍返回缺口指引。预确认不是最终采集锁，名单与维度须在采集前有效绑定，范围变化重审。现有review API迁移缺口见 [运行流程](research-workflow.md)，不能伪造锁。阶段0不另加通用“是否继续”确认，也不授权新增来源或预算。

## 验收

未知核心信息保持未就绪；优势短板未知显式保留；多行业原文和拆分值均保留；价格、竞品和特别说明允许留空；读者三列缺项追问且角色开放；Markdown 手工填写可读、空模板未就绪；旧9题及单 JSON 档案读取而不覆盖，缺项不冒充回答；错题与重复答案拒绝；中断续接；损坏或未知版本存储失败关闭；仅显式项目入口检查本背景；默认单对象不拦截；任务保存可空上下文并恢复一致。当前不声称实现跨段自然语言答案自动抽取、交互背景编辑、自动行业规划、来源过滤或真正研究执行。
