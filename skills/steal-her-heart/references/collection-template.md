# 全行业统一采集框架

版本：4；日期：2026-11-04。Agent 面向所有系统品类和各行各业；本次在通用契约之上增加显式选择的 SaaS 推荐配置及评价样本覆盖检查，不改变默认核心字段，也不把配置检查当作 Research／Validator。

## 通用骨架与专项维度

默认只需竞品名，无需我方产品或 profile；Agent 根据实际检索识别对象与行业，选择适合维度。默认模板 ID 为 universal。统一的是结构、证据口径与比较方法；专项字段由研究目标、行业和系统品类共同配置，不固定为某一行业的功能清单。行业与系统品类是两个独立、开放的文本维度，不设支持名单。软件、硬件、品牌、实体商品和线下服务可使用同一数据契约。

| 通用模块 | 采集方向 |
|---|---|
| 基本盘 | 定位、目标客户／用户及场景、规模、主体背景／发展历程、代表客户／典型使用者 |
| 产品与服务 | 核心产品／能力／服务、交付／使用／服务方式，加上本次研究的专项维度 |
| 价格与商业模式 | 产品／服务／版本划分、价格／报价、计费／交易模式、试用／体验／售后政策 |
| 竞争与市场表现 | 价值主张、公开传播表述、局限及适用边界 |
| 用户口碑 | 好评、差评、高频抱怨，按该行业可访问的评价渠道取证 |
| 近期动态 | 产品／服务／经营变化、资本动态、合作、营销活动 |
| 每条信息的元信息 | 来源链接、获取日期、置信度及其理由、关联证据 ID |

底层共享骨架不会要求所有竞品具备线索、商机、合同、AI、移动端或 API。这些只能在研究需要时成为专项维度。不会强迫消费品填写软件版本，也不会把餐饮体验当作软件功能。

以下仅展示如何配置维度，不是内置行业白名单，也不代表已实现在线研究：

| 行业／系统品类示例 | 可配置的专项维度示例 |
|---|---|
| 制造／ERP | 生产排程、成本核算、供应链协同 |
| 物流／WMS | 库位、出入库、盘点与追溯 |
| 企业管理／HR | 招聘、考勤、薪酬与人才发展 |
| 医疗／信息系统 | 业务流程、互操作、权限审计 |
| 教育／教学平台 | 课程、教学互动、学习评估 |
| 消费电子／硬件 | 性能、续航、可靠性、维修 |
| 餐饮／品牌及服务 | 菜品、服务体验、门店覆盖、客单价 |
| 未预置行业／新品类 | 接受用户定义的维度，不回退到某个垂直领域 |

## 模板与横向可比性

CollectionTemplate 保存 id/version/industry/system_category/core_field_ids/fields。build_collection_template 将所选核心字段与 extra_fields 组合；不要求每次收集全部通用字段。新增字段不修改采集内核，也不要求注册行业名称。核心／扩展 ID 不能冲突，所选字段的证据约束不能削弱。

CompetitorCollection 保存完整模板快照。每个竞品的字段必须与其选定模板恰好一致，不能漏项、重复或混入其他模板字段。同一研究比较使用相同模板、时间窗口、术语和衡量单位。默认单对象常规维度无需用户逐项批准；实质扩大范围需询问，可选项目已批准维度变更仍按其评审规则处理。

可配置模板已实现；根据自然语言自动设计专项维度、确认可比口径和生成研究任务属于后续 Planner，当前不能声称已完成。

## 可选 SaaS／工具推荐配置

用户明确选择该交付方式，或本次实际资料确认适用时，可采用 [SaaS 采集指南](../../../codex-skills/steal-her-heart/references/saas.md) 及其推荐 JSON。Python 的 [research_presets.py](../../../src/steal_her_heart/research_presets.py) 显式加载包内 `saas` 配置；不会把行业名称当白名单，也不会自动为未知对象套用此配置。

预设在现有 CollectionTemplate 外附加每字段的 P0／P1／P2 优先级、采集问题、比较条件、最低证据要求和源提示，另给评价采样策略。所选核心定义保持不变，每个模板字段恰有一份采集定义；源 ID 必须存在。Python 包内 JSON 为维护单源，运行技能携带同字节副本，以便独立安装使用；两端一致性单独校验。

推荐组合覆盖功能广度与任务深度、API／生态、免费／升级路径、迁移／锁定、版本迭代和评价采样。优先级不等于可信度，源提示不等于来源已访问，最低证据要求也不证明事实已被支持。`preset saas` 只返回建议，不写项目、名单、维度或锁；现有项目若采用字段，仍需走正式提案与评审。附加采集元信息当前不会自动绑定进原有维度锁。

`--review-sample FILE --as-of YYYY-MM-DD` 对提供的评论元信息执行有界检查，标出日期／窗口、重复、缺失字段、平台或评分分层覆盖问题；它不能证明评论已从评价站取得、原文支持主张或样本具有统计代表性。不可得的角色、规模或标签显式记未知，不补造；访问受限不当成没有评价。结果仍为 `facts_validated=false`，不能转换为 Validator PASS。

## 填写与缺口

每条信息独立记录来源 URL、获取日期、0–1置信度、理由和 evidence_ids。置信度不是校准正确率，不能给整张表共用一个分数。

| 内部状态 | 展示 | 使用条件 |
|---|---|---|
| pending | 未采集 | 尚未完成，或仍缺必要上下文 |
| found | 已采集内容 | 有逐条来源和元信息，仍待实质验证 |
| not_found | 未找到 | 已查找，保留查询、检查链接、日期和范围说明 |
| not_applicable | 不适用 | 字段定义允许，且写明为何不适用于当前研究 |

“未找到”保留用户要求的原文，只描述本次查找结果，不等于不支持或不存在。只有网络失败不能标未找到。确实不适用时记录理由，不伪造成资料缺失；不能用“不适用”跳过核心字段或掩盖未知。状态填齐不代表事实覆盖达标。

## 语义口径

- 规模必须注明指标、单位和时间；不同产业使用各自有意义的口径。
- 定价按真实商业模式记录：订阅、席位、用量、一次购买、交易佣金、项目报价、客单价或其他模式，不默认 SaaS 席位制。
- 宣传与实际效果区分；未证明典型性的传播文案只称公开示例。
- 局限属于证据支持的推断，不从未提及推导缺陷。
- 我方赢输不是所有研究的必填项。只有用户指定我方产品并要求对照时才添加相应字段及上下文依赖。
- 口碑渠道随行业选择。声称高频须给采样范围、样本数、去重与重复次数，不把个别体验推广为普遍事实。
- 近期动态须明确起止时间，并核对事件／发布日期；获取日期不能代替事件日期。

## 实现边界与兼容性

契约代码在 [collection_template.py](../../../src/steal_her_heart/collection_template.py)。采集对象 schema_version=2，不再接受旧的垂直模板顶层 template_id/template_version；旧对象必须显式重建模板与字段映射，不能静默改名升级。已有任务数据库未接入此契约，因此没有更改数据库 schema。

此采集模块提供配置、对象及结构校验，另有独立的评论元信息／采样覆盖检查；并不执行自动填表、语义核查、分析或报告。仓库已有独立搜索、抓取和摘录诊断，但没有串成 Research 执行链。URL、证据ID、适用性理由及检索记录仍需与实际工具结果和来源逐项对账，结构合法、散列一致或样本数达标都不能证明语义真实。
