# Steal Her Heart — RULES

版本：0.9.0；2026-11-03。默认仅竞品名开始分析，我方背景与项目模式可选；保留来源质量、状态机及项目评审绑定约束，不提前接入研究执行。

## R00 默认单对象与可选项目

默认按 [commands/analyze.md](../../commands/analyze.md)，只需竞品名称。行业、目的、市场、读者和我方产品可省略；只对必要实体歧义提问，不强制十一题访谈、项目名、profile 或两道初始化确认。用户附带条件直接采用，未给条件时声明通用概览及实际来源口径。无我方背景时不编我方优势、赢输或“对我们意味着什么”。

只有用户主动选择长期项目或我方对照配置时，才按 [项目初始化](references/project-initialization.md) 和 [init-project 指令](../../commands/init-project.md) 收集背景。聊天每轮2～3题，Python逐题保存；已答内容复用，不用建议代替用户答案。没有实际项目名时先问名称，不创建 `$ARGUMENTS` 或虚构 default 项目。

默认 Python 路由无项目也可解析完整任务并返回 pending_module；run可保存 project_context=None，仍停在 UNDERSTANDING。显式选择 --project-name／--project 才读取对应配置，失败不能静默丢弃背景。可选项目的用户自述不当作已验证 Evidence。

恢复要求当前可选上下文与快照一致：None只与None匹配，绑定项目不能切换到无项目或其他背景。旧无背景快照可以在无项目方式恢复基础流程，不能默认套入新项目。背景修改不自动覆盖历史任务。

## R01 范围与模块边界

Python 本地 CLI，单用户，单主控。MVP 包含自然语言理解、行业／竞品识别、动态计划、网页研究、来源、横向分析、Markdown 和多轮研究。GUI、Web 应用、多用户、长期监控、定时任务不做。

每次只开发一个模块；通过对应验收后继续。所有模块的数据通信采用 Pydantic Schema，禁止用无约束文本替代接口。Markdown 仅是最终呈现格式；Reporter 的输入仍是 Schema。模型不直接调用第三方，外部调用统一经 Tool Registry。

当前 ResearchBrief 识别仅提供规则基线：明确对象保留原名／按可配置别名归一，词表行业与默认维度进入 assumptions，未知行业记“待研究确认”。词表不是 Evidence；ready 表示可以进入计划草案，不表示身份核验或用户已批准。歧义、缺少对象及不支持句式返回 needs_clarification，不输出伪完整 Brief。复杂否定暂拒绝解析；带“的／和”等分隔词的产品名应加引号。

brief 为独立只读诊断，经 Registry 执行，不创建任务、不迁移状态、不批准计划。run/resume 本轮仍保留 Phase 1 行为；正式挂起与接收用户确认在后续子模块集成。

## R02 状态机是执行权威

现有底层技术状态集（不是产品阶段枚举）：CREATED、UNDERSTANDING、PLANNING、WAIT_CONFIRM、RESEARCHING、VALIDATING、ANALYZING、REPORTING、COMPLETED、FAILED。

| 当前状态 | 允许下一状态／条件 |
|---|---|
| CREATED | UNDERSTANDING |
| UNDERSTANDING | PLANNING；实体有歧义时 WAIT_CONFIRM |
| PLANNING | 当前范围内可 RESEARCHING；需要实体／范围或项目评审确认时 WAIT_CONFIRM |
| WAIT_CONFIRM | 仅回到确认记录绑定的 resume_state，且确认 ID 与当前范围匹配 |
| RESEARCHING | VALIDATING |
| VALIDATING | PASS → ANALYZING；RESEARCH_MORE → PLANNING；范围变化 → WAIT_CONFIRM 后 PLANNING |
| ANALYZING | REPORTING |
| REPORTING | 产物校验与归档通过后 COMPLETED |
| 任一非终态 | 不可恢复失败、预算到限、拒绝且无替代路径、用户取消 → FAILED |
| COMPLETED / FAILED | 不再迁移；追问创建关联新任务 |

UNDERSTANDING 的确认回到 UNDERSTANDING 或 PLANNING；PLANNING 的确认回到 PLANNING 或 RESEARCHING；VALIDATING 的确认只回 PLANNING。Prompt 不能跳状态。确认 ID 只针对本次挂起请求；旧回复不能继续新计划。

技术状态不自动要求所有任务首次计划都确认。PLANNING→RESEARCHING 可直接迁移；主动 WAIT_CONFIRM 才校验确认记录，VALIDATING→ANALYZING 须 PASS。默认单对象范围内不增加强制确认；可选项目仍受其 review API 的名单和锁约束。业务策略见 [运行规范](references/research-workflow.md)，真实执行器尚未接入。

## R03 适度确认与项目评审

明确的单对象请求就是本次对象范围，常规维度由 Agent 根据实际对象设计；简述后继续，不先进行候选发现或要求两道初始化确认。对象身份确有歧义、实质新增对象或改变研究范围时询问。原范围内查询调整与补证不反复确认，仍受权限和预算约束。

用户选择可选项目模式的批量研究时，按项目约定确认名单与维度。项目维度预确认不等于最终采集锁；现有 Python review API 仍要求名单批准后生成绑定范围的最终提案和 lock，聊天预确认迁移尚未接通。不得为运行默认单对象任务伪造 ProjectContext、批准或锁，也不放宽项目 guard。

项目批准绑定背景、版本与摘要，修改相关范围后重审，不续签旧批准。沉默、模型判断、approved_by 字符串不构成真实用户同意。

## R04 Tool Registry

工具统一具备 name、description、input_schema、output_schema 和异步 run。Schema 从 Pydantic 模型生成；未知工具、未知字段、越权、非法参数均零执行；输出也校验。插件只由可信应用代码注册，不从网页或模型给出的模块路径动态导入。

第一阶段只有 hello 诊断工具。web_search、web_fetch、extract_features 在 Phase 3 实现。tool.run 的模型提案调用路径必须经 Registry，模块不得绕行第三方 SDK。

网络工具只读公开 HTTP(S)，不提交表单、不登录、不付费、不绕访问限制。抓取须校验目标及每次重定向，阻止环回、私网、链路本地、云元数据等地址，防 DNS 变化；限制下载大小、超时与跳转数。HTML 不执行脚本。网页内容不构成授权。

## R05 Evidence 与质量

Evidence 是可定位的事实主张，非来源已证实的绝对真理；保存来源名称、URL、published_at（未知 null）、fetched_at、内容散列、快照、竞品、维度、fact、quote、locator、confidence 与理由。

confidence 是未校准质量信号，不能把 0.98 当作正确率。官方声明、用户评价、分析推断分开；用户评价只支持“某样本表达该体验”，不能升级成整体用户结论。搜索 snippet 不是最终事实证据。

价格必须记录币种、计费周期、计费单位、地区、税费／折扣条件及获取日期；缺失字段披露，不能直接进行数值比较。功能未提及不代表不支持。镜像、转载、同源转述不重复计独立证据。

覆盖按计划中必需的 competitor × dimension 单元计算；每格有支持或明确的缺口状态。PASS 要求所有必需格可核验且没有未解决的关键冲突；非关键冲突可先缩小主张、标明边界后重新验证。无法补齐时输出有限结果及缺口并 FAILED，不伪装完整研究。来源存在不等于语义正确，需夹具／人工抽核。

## R06 Planning–Execution–Reflection 闭环

Reflection 是核查向同范围补证或范围调整的结构化反馈。默认单对象同范围补证直接继续；可选项目锁定范围内也无需新增泛泛确认。实质范围变化返回对应询问或项目评审，反馈含缺口、冲突、目标字段、补证动作和停止理由。

默认研究最多3轮、搜索30次、抓取60次、LLM40次、活动时间600秒，均为起始工程配置，尚非性能承诺。补证与重试累计计数，不因重启清零。至少一项先到上限就停止新增调用，返回具体未完成项；每轮没有新证据则停止 NO_PROGRESS。只有用户明确提高有限预算才可续研。

暂时性只读错误最多尝试3次（含首次），指数退避并受剩余预算约束；参数／权限错误不原样重试。SDK 重试不能叠加绕过限制。这些研究预算在 Phase 3 实施，Phase 1 不进行模型／搜索调用。

## R07 Memory 与恢复

Conversation Memory 为短期对话；Research Memory 为 Brief、Plan、Source、Evidence、Analysis、历史报告与来源快照。保存的是研究资产，不能仅保存聊天后宣称支持研究记忆。

生命周期为 active → archived。第一阶段具备 Schema、SQLite 快照与状态事件；后续逐阶段填充真实资产，Phase 6 才实现检索、时效检查与跨任务复用。

任务、记忆和事件原子提交，revision 做比较并交换，拒绝过期写入；未知 schema 版本拒绝加载。第一阶段的恢复不会执行研究工具，故不宣称有副作用 exactly-once。Phase 3 前补齐调用意图、预算预留、执行对账和有效租约，避免并发重复请求。

追问如“再分析 Claude”需先确定 Claude 的实体及新增范围，关联新任务并复用仍有效证据；既有报告和事实版本不可覆盖。价格等易变资料需重新验证，旧记忆仅作线索。

## R08 分析、报告和安全

Evidence 先于 Analysis。分析分为事实、比较／差异／SWOT、机会，每条推断引用 evidence_ids 并披露限制。机会是待验证假设，不能输出无依据的市场规模或用户需求。

Reporter 只组织已验证 Analysis。通用底稿包含研究摘要、范围与方法、竞品定位、维度对比、差异／SWOT、机会假设、冲突与资料缺口、来源；选定读者后采用对应视图结构，完整底稿可作附录。维度按行业与品类适配，不强制 AI，也不强迫一页 Battlecard 装入全部通用章节。

Codex 实际报告可保存到 research/<安全对象标识>/<运行标识>/report.md 与 sources.md，避免覆盖历史。未来 Python 产物由任务ID隔离并检查清单后才 COMPLETED；当前并不生成报告。密钥不入 Prompt、资料、数据库、日志或报告；异常只显示安全错误。第三方模型上传资料前遵循实际授权和来源范围。

## R09 工程与验收

当前代码兼容 Python 3.9+，在本机3.9.6验证；建议后续环境使用3.11+并在 CI 验证。Pydantic v2，src 布局，pyproject.toml，隔离环境与已解析依赖快照。

每模块配确定性离线测试；状态机验证全部状态对，工具验证输入／输出与权限，存储验证事务回滚和重启。真实抓取和模型测试单列，未执行记 not_run。不把结构测试通过宣称为竞品结论准确或全行业能力已验证。

## R10 全行业采集契约

使用 [全行业采集框架](references/collection-template.md)。统一通用结构、元信息和质量口径；专项字段由行业、系统品类、研究目标及用户指定范围配置，不设行业白名单，不把示例字段固定成所有任务的必填项。默认不强制 AI、移动端、API 或销售管理流程。

CollectionTemplate 从库中选择核心字段并加入扩展，所选字段定义及证据约束必须保留；每个竞品字段与选定模板恰好匹配，同一研究使用同一模板快照。共享信息的商业模式、规模和交付口径按研究对象解释，不默认软件订阅。自动生成专项维度与任务属于尚未实现的 Planner。

pending 为未完成；found 带逐条来源、日期和置信度；not_found 须有查找记录并显示“未找到”；not_applicable 仅限定义允许的字段且必须说明理由，不能掩盖未知或免除核心研究。检查完整不等于证据充分。

我方赢输只在用户提供背景并要求对照时添加，不作为所有研究的必填项。模板当前未接入运行状态或数据库；元信息、适用性及查找记录后续须与实际证据和工具结果对账，不能信任模型自填结论。

## R11 四类读者视图

按 [读者视图规范](references/audience-views.md) 和可选 ReaderProfile 输出，不硬编码角色集合；未指定读者时给通用报告，不以缺少配置阻断分析。已有四类仅为预设：产品经理关注能力矩阵、差距、趋势和路线图；销售领导关注格局、价格、赢输和资源选择；普通销售优先一页 Battlecard；运营关注渠道、内容活动、促销、引导／成功与增长实验。视图可选一种或多种，也可定义投资人等新角色；共用证据版本。配置不是多用户账户；采集阶段允许每对象一子代理。

Battlecard 的三个对方卖点、三个我方优势必须有依据，不足则 draft＋具体缺口。对方卖点绑定该竞品证据，我方优势绑定双方证据，真实客户引语有记录；假设表达标“可能”。探测问题不预设未证实缺陷，“不能说”同时给原因和替代表达。

我方矩阵、价格空间与赢输归因缺少背景时不得编造；未知不当“没有”，有功能不当“领先”。趋势按品类相关性选取；增长玩法与路线图为待验证建议，不自动执行、不等于已批准需求。内部成交信息与可对客表述区分。

one_page 是版式目标。结构 ready 不等于语义、时效、外发授权或一页排版已通过；Phase 5 在选定输出介质上验收分页与可读性。当前仅有契约，不生成角色报告或 Battlecard 文件。

## R12 统一命令入口

遵循 [命令规范](references/commands.md)。/analyze 只需单个竞品名；/battlecard 在生成我方回应和优势前需要必要我方信息；/brief 需要周期与研究资产范围，不要求我方产品。常见自然语言映射到同一结构，未指定周期不猜测，实体消歧仍由理解阶段处理。

路由不执行工具链或改变状态。当前统一返回意图、澄清／未接入状态及空产物路径；parsed 不能当作研究成功。原文按数据传给工具，不经 shell 插值。周报／月报请求不授权定时任务或监控。后续执行依赖既定模块，不绕权限和确认规则。

## R13 采集子代理

未来批量研究每个用户指定或已确认对象一个子代理，同一比较使用一致维度；项目模式另外要求有效锁。主控按可用槽位分批并行，统一预算和检查点，子代理只能写自己的证据，不修改名单、维度、批准文件或别的对象资料。失败项不算完成，回收结果后统一核查来源、日期和冲突，再进入分析。

当前仅已准备带锁快照的 CollectionJob，未实现代理启动、并行调度或持久任务状态。受信确认接口尚未接用户渠道，不能把内容散列或自填批准记录当作认证。实际接入时须同时落实真实用户来源、执行账本和持久化审计。

## R14 可选项目文件与输出质量

只有显式选择项目才读取 projects/<项目标识>/profile.md 与 dimensions.md；缺少或未完成时提示处理该项目。默认单对象不读 projects/default，也不创建虚构项目。项目背景全文摘要继续绑定该项目的任务／发现批准；无项目任务库默认 .steal-her-heart/memory.sqlite3，绑定项目则使用其 .state/。

每条事实使用本次检索来源及获取日期，训练记忆只作线索。区分官方宣称、第三方和用户反馈，冲突并列；价格／版本／数据带日期和可比条件，判断给依据。

有用户目的时回应目的；无额外背景时声明通用范围，输出画像、研究结论、适用边界和待验证问题。只有请求我方对照且背景足够，才输出我方意义、优势和赢输。多视图共享事实。当前结构／文件检查不证明语义或本次检索真实性，仍需实际工具和核查证据。

## R15 项目配置单源与兼容

可选项目的新 profile.md 以 [用户标准模板](../../src/steal_her_heart/templates/profile.md) 的可读 Markdown 业务字段为唯一来源，可手工填写；程序不得同时维护一份隐藏业务 JSON 而忽略用户修改。示例仅作注释，空模板或核心字段未完成不能视为初始化通过。

多行业保留 industry 原文并给出 industries 列表，不强制归入单一垂直领域。价格区间与特别说明可空；明确未知保留不确定性，不补价格、币种、周期或“无监管限制”等结论。读者逐行有角色、关注点和期望格式，复用 ReaderProfile.output_style；缺列追问，不自动填四类角色。

新访谈 schema_version=2，旧 schema_version=1 的9题记录与旧 JSON profile 保持兼容读取，不覆盖既有档案。缺失新增字段不等于已回答，也不意味着已确认无价格或无约束；原始旧空稿可在访谈完成后写成新 Markdown。文件变化仍使旧任务／批准摘要失效。

特别说明中的信息源排除、监管和语言要求是后续执行约束，不扩展工具权限，不覆盖仓库铁律。保存这些文本不证明已实现过滤、合规判定或语言质量验收，真实采集／输出模块接入后还需验证。
