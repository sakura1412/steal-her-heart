## R00 默认单对象与可选项目

首次使用先简短说明开发预览及所用路径，随后复用已有名称继续，不新增通用“是否继续”确认。Codex宿主辅助研究依赖实际联网、页面读取和逐条核查，证据不足时只给有限结果／提纲，不保证报告；它不会自动同步Python任务、名单、维度或最终锁。Python CLI的ready／退出0只证明当前操作成功；项目访谈ready仅表示档案保存，不自动推荐维度、发现候选或开始采集。

默认调用 [运行时技能](../../codex-skills/steal-her-heart/SKILL.md)，只需产品名称。无名称只问名称，已有名称不重问；后续可按需进行简短且可跳过的重点问答，必要时消歧。行业、目的、市场、读者和我方产品可省略，不强制十一题访谈、项目名、profile 或两道初始化确认。用户附带条件直接采用，未给条件时声明通用概览及实际来源口径。无我方背景时不编我方优势、赢输或“对我们意味着什么”。

只有用户主动选择长期项目或我方对照配置时，才按 [项目初始化](references/project-initialization.md) 和 [init-project 指令](../../commands/init-project.md) 收集背景。聊天每轮2～3题，Python逐题保存；已答内容复用，不用建议代替用户答案。没有实际项目名时先问名称，不创建 `$ARGUMENTS` 或虚构 default 项目。

默认 Python 路由无项目也可解析完整任务并返回 pending_module；run可保存 project_context=None，仍停在 UNDERSTANDING。显式选择 --project-name／--project 才读取对应配置，失败不能静默丢弃背景。可选项目的用户自述不当作已验证 Evidence。

恢复要求当前可选上下文与快照一致：None只与None匹配，绑定项目不能切换到无项目或其他背景。旧无背景快照可以在无项目方式恢复基础流程，不能默认套入新项目。背景修改不自动覆盖历史任务。

### R00a 研究模式（待实现）

模式为 quick_scan／standard_research／deep_research，默认 Standard，显式快速或深度要求优先；不要求用户先选择模式。具体七维策略和参考预算以 [研究模式设计](../../docs/research-modes.md) 为准。模式与对象数量、行业、项目、读者和报告格式独立，Deep 不自动授权扩大名单，Quick 不截断明确问题。

策略快照绑定确切预设版本、问题范围、证据／交叉验证／时效标准、资源分配和报告要求。Planner 拆解，Orchestrator 校验与调度，所有模块及 QA 收据绑定同一 policy_hash。维度数是参考，来源数量不证明支持；共同事实底线、完整 Research QA 和九项 Report QA 在全部模式适用。

首次与补研共享总额，预留不重复发放；发现、并行子任务、Adapter 内部调用与报告返工统一记账。搜索／抓取之外仍须有限模型和时间预算，工具／用户硬限制优先，页面受限不因 Deep 绕行。任务恢复、换模式、重试与新修订不清空已用额度。

模式变更采用新策略与修订，按影响重核／补采，保留历史与原日期，不复制旧全局 PASS。降级不取消用户已明确的必需问题；不可行时说明冲突，不能静默减范围或放宽标准。当前 Schema、CLI 与运行链尚未实现模式，不能将自然语言原文被接受当成执行成功。

## R01 范围与模块边界

Python 本地 CLI，单用户，单主控。MVP 包含自然语言理解、行业／竞品识别、动态计划、网页研究、来源、横向分析、Markdown 和多轮研究。GUI、Web 应用、多用户、长期监控、定时任务不做。

每次只开发一个模块；通过对应验收后继续。所有模块的数据通信采用 Pydantic Schema，禁止用无约束文本替代接口。Markdown 仅是最终呈现格式；Reporter 的输入仍是 Schema。模型不直接调用第三方，外部调用统一经 Tool Registry。

Planner 独占业务任务拆分、优先级与修订计划的生成；Orchestrator 调用它并核对范围、依赖和剩余额度，拥有调度、恢复与终止决策权。主控不能把规划逻辑复制一份，也不能成为只按固定顺序转发的流程壳。Research 管采集与来源；Validator 管主张支持、交叉验证和可比口径；Analysis 管引用证据的比较与机会；Reporter 管可读交付及内容和引用质量。目标行为及当前接口缺口见模块契约，文档不替代实现。

Competitor Discovery 是独立发现能力：在 Planner 规定的目的与范围、Orchestrator 分配的预算内，按定位、客群、场景和功能查找候选并解释竞争关系。它复用 Registry 检索与来源工具，负责实体消歧、去重、分类和匹配分项，不批准名单、不扩大正式研究范围，也不承担后续竞争结论。候选纳入核查不等于完整研究 QA，通过名单筛选仍须按选定维度研究和验证。

当前 ResearchBrief 识别仅提供规则基线：明确对象保留原名／按可配置别名归一，词表行业与默认维度进入 assumptions，未知行业记“待研究确认”。词表不是 Evidence；ready 表示可以进入计划草案，不表示身份核验或用户已批准。歧义、缺少对象及不支持句式返回 needs_clarification，不输出伪完整 Brief。复杂否定暂拒绝解析；带“的／和”等分隔词的产品名应加引号。

brief 为独立只读诊断，经 Registry 执行，不创建任务、不迁移状态、不批准计划。run/resume 本轮仍保留 Phase 1 行为；正式挂起与接收用户确认在后续子模块集成。

### R01a Agent 标准契约（待实现）

[标准契约](../../docs/agent-contracts.md) 与 [YAML 目录](../../docs/agent-contracts.yaml) 定义八个 Agent 的 name、objective、input、output、tools、rules、decision、restrictions、failure_handling、completion_criteria。目录为开发单源、design_only；不自动注册 Agent、导入代码或授予权限。目标类型需逐模块落成 Pydantic／守卫并验收，当前 Protocol 不冒充完整执行契约。

共同调用／结果绑定 invocation、角色、契约版本、研究／计划／策略／资产指纹、预算与可信授权；理解阶段可尚无计划，采集等阶段须完整准入。模型输出不能自行提供可信身份、预算或工具权限。输入只读，产物追加版本，消费者另验证当前依赖和接纳条件。

Tools 分已注册工具、待实现能力、内部服务与模型角色；有效权限取宿主／用户授权、注册实现、Agent 上限、工作项与资源条件交集，未列出默认拒绝。只有主控有调度、状态、恢复及发布控制；Research 子代理仅获分配范围，不继承父级权限。

模块调用完成、资料找到、证据充分与报告交付分开。Research evidence_records 是 unvalidated 候选；Validator 的 RESEARCH_MORE 与 Report QA 的 REVISE 可以是正常评估输出，但不批准下游。Reporter 草稿仍需独立完整 Report QA 和工件／发布检查。Prompt 必须服从这些契约，不增工具或任意回边。

## R02 状态机是执行权威

现有底层技术状态集（不是产品阶段枚举）：CREATED、UNDERSTANDING、PLANNING、WAIT_CONFIRM、RESEARCHING、VALIDATING、ANALYZING、REPORTING、COMPLETED、FAILED。

| 当前状态 | 允许下一状态／条件 |
|---|---|
| CREATED | UNDERSTANDING |
| UNDERSTANDING | PLANNING；实体有歧义时 WAIT_CONFIRM |
| PLANNING | 当前范围内可 RESEARCHING；需要实体／范围或项目评审确认时 WAIT_CONFIRM |
| WAIT_CONFIRM | 仅回到确认记录绑定的 resume_state，且确认 ID 与当前范围匹配 |
| RESEARCHING | VALIDATING |
| VALIDATING | PASS → ANALYZING；RESEARCH_MORE → PLANNING；范围变化 → WAIT_CONFIRM 后 PLANNING |
| ANALYZING | REPORTING |
| REPORTING | COMPLETED（当前代码尚无报告质量或产物读回守卫） |
| 任一非终态 | 不可恢复失败、预算到限、拒绝且无替代路径、用户取消 → FAILED |
| COMPLETED / FAILED | 不再迁移；追问创建关联新任务 |

UNDERSTANDING 的确认回到 UNDERSTANDING 或 PLANNING；PLANNING 的确认回到 PLANNING 或 RESEARCHING；VALIDATING 的确认只回 PLANNING。Prompt 不能跳状态。确认 ID 只针对本次挂起请求；旧回复不能继续新计划。

技术状态不自动要求所有任务首次计划都确认。PLANNING→RESEARCHING 可直接迁移；主动 WAIT_CONFIRM 才校验确认记录，VALIDATING→ANALYZING 须 PASS。默认单对象范围内不增加强制确认；可选项目仍受其 review API 的名单和锁约束。业务策略见 [运行规范](references/research-workflow.md)，真实执行器尚未接入。

本表仅为 v1 当前代码边界；REPORTING→COMPLETED 尚无质量／读回守卫。下节 v2 采用独立 GAP_ANALYSIS、SUPPLEMENTING、GENERATING_REPORT、REPORT_QA、两个确认等待及 CANCELLED，替代旧目标内部阶段安排；迁移、恢复和守卫验收前不得调用新边。当前晚期失败限制仍适用于未升级运行时。

### R02a 分层状态机 v2（目标，待实现）

[状态机 v2](../../docs/state-machine-v2.md) 和 [状态目录](../../docs/state-machine-v2.yaml) 为目标单源：CREATED、UNDERSTANDING、WAITING_FOR_SCOPE、PLANNING、WAITING_FOR_APPROVAL、RESEARCHING、VALIDATING、GAP_ANALYSIS、SUPPLEMENTING、ANALYZING、GENERATING_REPORT、REPORT_QA、COMPLETED、FAILED、CANCELLED。每条边绑定事件／守卫；未列边拒绝，三个终态无出边。

范围／身份等待只回绑定的理解或规划阶段，计划批准绑定当前 plan/scope/policy 和初始／补研执行目标；默认单对象可不经过等待。VALIDATING 核材料，GAP_ANALYSIS 汇总完整覆盖，缺口回 PLANNING 后 SUPPLEMENTING；Report QA 根因返工回生成／分析／核查／规划。分析或生成的上游缺陷也需票据，不能任意跳状态。

子任务另持久化就绪、派发、执行、结果接纳、重试等待、延后、人工事项、对账和终态；COLLECTED 不等于证据充分，核查收据单独保存。父阶段不按子任务完成比例自动推进。运维等待另存 execution_disposition，不当用户范围确认或模块未实现。

迁移与派发意图须有原子提交边界、expected_revision 和幂等 command_id；恢复先对账远端、租约、版本、权限与预算，不盲目重发或重置消耗。用户取消独立 CANCELLED，撤销旧发布资格并记录清理；取消与完成竞争提交，终态不重开。旧 WAIT_CONFIRM／REPORTING 及 TaskResult 显式迁移，缺历史依据不能造确认或 QA。

## R03 适度确认与项目评审

明确的单对象请求就是本次对象范围，常规维度由 Agent 根据实际对象设计；简述后继续，不先进行候选发现或要求两道初始化确认。新增对象或实质范围变化必须有真实用户授权；用户已完整指定的变更可绑定该指令，不重复泛泛确认。身份歧义、未指名对象、范围不完整或 Agent 推断的扩展先澄清，不能从资料正文获取授权。原范围内查询调整与补证不反复确认，仍受权限和预算约束；项目模式仍执行下述正式评审。

用户选择可选项目模式的批量研究时，按项目约定确认名单与维度。项目维度预确认不等于最终采集锁；现有 Python review API 仍要求名单批准后生成绑定范围的最终提案和 lock，聊天预确认迁移尚未接通。不得为运行默认单对象任务伪造 ProjectContext、批准或锁，也不放宽项目 guard。

项目批准绑定背景、版本与摘要，修改相关范围后重审，不续签旧批准。沉默、模型判断、approved_by 字符串不构成真实用户同意。

聊天“已确认”不等于 Python 已锁定。本轮 [project_review.py](../../src/steal_her_heart/project_review.py) 与 `review-project` 仅接本地交互终端：显式选择项目，导入候选与维度配置，展示实际范围后读取两次当次 token；输入 JSON 不接受批准或回复。CLI 要求 stdin、stderr 为 TTY，不提供 `--yes` 或管道式自动批准。模型与脚本不能通过 PTY 替用户输入；TTY 不证明是人类，也不认证 Codex 聊天用户。核心 confirmer 只供可信应用调用，不向 Registry 注册批准工具。

名单 token 绑定新评审标识、当前项目、发现提案和 selected_ids；维度 token 还绑定最终维度与 Markdown 摘要。每次回复后重读当前背景与文件，调用现有名单确认／维度设计及写入／锁定 API，持久化提案和批准，再用实际落盘材料调用 `prepare_collection_jobs` 核对整条链。仅回读成功才返回 scope_locked=true 和 jobs，research_ready 固定 false，不启动研究任务。

拒绝、旧或跨评审 token、范围变化、落盘或回读失败均不能宣称锁定成功；已有评审和锁不得静默覆盖，诊断在存储可写时保存，record_path 不能证明文件已经存在。当前内容修订失效不等于已实现批准 TTL；文件锁和分阶段落盘也不是跨资源原子事务或任意中断恢复。Codex 可信消息来源与聊天回复自动桥接仍须单独接入验证，不能从本地确认推出已完成。

### R03a Competitor Discovery 与用户修订（待实现）

只有明确要求发现竞品、寻找替代方案、分析市场格局，或选择包含发现的项目流程时才启动。产品名即可作为种子，不强制我方 profile；先用本次来源确认种子身份与定位／客群／场景／功能，未知保留缺口，不能用训练记忆或第三方猜测补成事实。发现授权允许有限候选页面核验；完整多对象采集须等待用户选定当前名单。

四路发现分别记录查询、命中候选、来源与覆盖缺口。直接竞品看同一客群与任务的竞争，替代品看同一任务的不同解法并包含非品牌方案；潜在进入者的事实判断须有实际进入动作依据，标杆须对应具体学习问题。每条纳入／排除／待核实理由引用依据，四类未找到、未执行和受限分别说明，不能为凑齐类别编造对象。

实体归一使用可核验的主体、官网、产品线和地区等组合信息。同名不等于同实体，同域不等于同产品；别名和改名合并须保留依据及映射，套件和子产品按本次粒度处理。歧义未解决不进入确定名单，疑似重复不能静默合并；种子自身不作为其竞品。一个实体可说明多种关系，但不能因此重复派发研究。

匹配评分按类别、目的和版本化指标解释，分项对应双方依据；来源质量、匹配度与用户选择分别记录。未知不是零分，也不能丢掉未知权重重新归一抬分；材料不足标待评分或给有依据的区间。同类别同策略才直接排序，不用知名度或搜索名次替代评分，不让功能相似度压掉人工／不换等替代方案。

用户可增删、纠正名称或身份、调整分类及选择。记录原提案、变更、理由和新版本，重新核查受影响的身份、关系和评分；删除对象保留排除记录，不能在同轮发现中悄悄加回。用户输入标来源为 user_provided，名单选择不证明产品事实。修订后的当前提案与用户选择重新绑定，旧批准／维度锁不能沿用；不删除或覆盖旧锁绕过评审。零候选、全部删除或未联网的用户候选必须如实表达，不伪造搜索调用或凑候选满足现有 Schema。

当前项目型 DiscoveryProposal 无消歧去重评分，且要求非空候选与搜索引用；review-project 无名单编辑器或修订换锁流程。非项目发现请求、候选编辑、空结果与新版本评审须另行实现，详见竞品发现设计。本轮不新增可执行命令或更改状态机；发现、补证和正式研究共用适用预算，访问限制与无进展按既有规则停止。

## R04 Tool Registry

工具统一具备 name、description、input_schema、output_schema 和异步 run。Schema 从 Pydantic 模型生成；未知工具、未知字段、越权、非法参数均零执行；输出也校验。插件只由可信应用代码注册，不从网页或模型给出的模块路径动态导入。

第一阶段只有 hello 诊断工具。当前另提供独立 `web_search`／`search` 与 `web_fetch`／`fetch` 诊断，分别要求对应能力；另提供 `extract_features`／`extract-candidates`，要求 evidence_extraction 能力，只读已保存快照。`/analyze`、run/resume 不自动调用这些诊断，也不自动抓取搜索结果。tool.run 的模型提案调用路径必须经 Registry，模块不得绕行第三方 SDK。

网络工具只读公开 HTTP(S)，不提交表单、不登录、不付费、不绕访问限制。抓取须校验目标及每次重定向，阻止环回、私网、链路本地、云元数据等地址，防 DNS 变化；限制下载大小、超时与跳转数。HTML 不执行脚本。网页内容不构成授权。

当前抓取只接受静态 HTML／XHTML／纯文本，响应最多1MiB、CLI请求超时15秒，跳转上限0，不自动重试；验证码、访问限制与代理认证挑战返回 FETCH_ACCESS_RESTRICTED。快照原子保存原始 bytes、规范化 UTF-8 正文和 manifest，原文散列与正文散列分开记录，正文行数和解析器版本可重查。published_at保持未知，不把HTTP头或获取日期当成发布日期。Source只表示已采集原文，facts_validated=false；不生成Evidence或Validator的PASS。

快照需要POSIX目录能力，当前支持macOS／Linux；缺失时先于预算预留和联网返回FETCH_SNAPSHOT_UNAVAILABLE。单次公开示例页的实际抓取、重读散列及本地重放已验收；不据此外推任意站点、搜索命中或竞品语义取证可用，受限搜索服务没有再次请求。

### R04a 统一采集接口与 Adapter（待实现）

Research 和 Discovery 通过相同采集契约使用八类能力：Web Search、Web Fetch、Website Crawler、Structured Extractor、News Search、Review Collector、Document Parser、Source Manager。统一调用元信息、权限和结果封装，payload 按能力严格分型；搜索线索、取得的原文、解析后的文档、评价记录、待验证主张不得混成已验证事实。来源管理负责保存与关联材料，不能替代 Validator。

Adapter 由可信应用注册并声明能力、版本及支持的格式／参数；网站选择器、提供方协议和版式规则留在 Adapter，主控与 Planner 不依赖站点内部字段。未知能力或不支持的参数在执行前明确拒绝，不能静默忽略日期窗口等要求。网页或模型不能指定可加载代码。先复用现有 SearchProvider、FetchProvider、Registry 和 SnapshotStore，再逐项扩展；新增站点须通过共享契约验收，不以配置文件存在表示可采集。

每个请求及结果绑定本次任务、范围、计划、研究单元与 Adapter 版本，关联 Registry call_id 和持久 request_id，两者不可混为同一标识。Crawler 的每页、新闻／评价的每次分页和提取模型调用都记录父子关系并计入实际预算；外层一次调用不使内部请求免费。未知完成状态不盲目重发，切 Adapter 不重置额度。受限依既有策略停止，不自动切入口或提供方绕过；格式变化须报解析／结构错误，不能当成功空结果。

Crawler 从明确种子与允许范围做有限遍历，设置有界页数、深度、时间、速率和总预算；先支持公开静态官网。外链、跳转与 canonical 声明不能自行扩大范围，URL 去重不得丢弃影响地区／版本／内容的参数。现有 Fetch 的无 JS、无重定向和静态格式限制继续有效；缺少对应能力时报告不支持，不借循环 Fetch 宣称已实现全站采集。

Document Parser 只解析已取得且获准处理的文档引用，下载走受控入口；保留原始文件散列、页／块／表格定位及解析版本。扫描件依赖另验 OCR，空抽取或缺页不伪装完整正文。Structured Extractor 从完整正文或解析工件提取候选，保留 quote、locator 与条件；自动语义提取需真实模型及验收，显式 spans 绑定和解析成功均不能代替它。

News 保留发布日期、事件发生时间、更新时间与获取日期的区别，未知不补成当前日期；转载不增加独立证据。Review 保留原文、来源、日期、评分尺度、抽样窗口及重复／激励等已知或未知状态；受限不等于零评论，样本检查不等于采集或语义通过。Source Manager 保存从调用到原文、解析工件、候选和验证结果的关联与版本，重放保留原获取时间；相同文本不代表独立来源，同 URL 新内容不覆盖旧版。最小来源关联不提前实现跨任务资产复用。

结果须区分成功、明确无结果、部分完成、不支持、受限和失败，并保留逐项实际结果与缺口；这些是未来采集语义，不是现有枚举。批次部分完成不等于任务成功，TaskResult 仍无 partial 成功状态。工具成功、字段 found 与 QA 通过各自判断；Adapter 不能把404判为业务不适用，也不能把缺少数据或分页未完成判为已完整查找。

### R04a 外部故障与恢复（待实现）

统一语义见 [失败恢复设计](../../docs/failure-recovery.md)：AttemptRecord、OperationResult 的执行与发现结果、FailureRecord、RecoveryDecision、ExecutionCheckpoint 分层。失败／延后／取消／结果不明不能变成 empty；真正无结果必须有成功查找及明确覆盖。资料不足、未研究、不适用和执行错误分别保留。

只有 Orchestrator 决定重试、替代、跳可选、延后、请求具体协助或停止。现有公开搜索／抓取不增加自动重试；访问限制不得轮询或换入口绕过。其他服务未来须按可信错误分类、幂等性、剩余额度、截止时间与已实现策略有界恢复，SDK／Adapter／子代理不叠加隐藏尝试。模型结构修复与传输重试共享恢复额度，拒绝不通过改写绕过。

方法降级须满足同一证据与权限要求，不能用搜索摘要、旧缓存或模型记忆替代本次核验；可选工作可记录跳过，必需问题不能删分母或改可选。人工事项绑定具体缺口及版本，用户原件仍需核查，沉默不批准，配置秘密不写入消息或日志。

目标延后／人工事项作为独立执行处置持久化，新增对外结果须显式迁移；不把运维等待塞入 WAIT_CONFIRM，不把未实现能力的 pending_module 当临时故障。上线前不承诺自动恢复。恢复核对范围／策略、预算、工件、操作与远端收据、租约；超时不明不盲目重发，终态不可重开。子 Agent 只重派受影响且安全可重做的工作，旧成果和故障历史保留。

必须问题未完成不进入假成功，Research QA／Report QA 不豁免；独立可继续工作由主控判断，受限路径及全局故障按实际影响停止。错误与恢复决策均可追溯，持久化失败时不声称已保存检查点。

## R05 Evidence 与质量

已实现显式摘录候选绑定：调用者给出快照引用、正文散列、对象／维度与1～20段Unicode码点范围，每段最多4000字符，start从0包含、end不包含，行号从1起。先校验快照及正文版本，再生成精确quote、fact=quote和带散列的locator，保留原空白与获取日期；纯空白、重复／越界范围和不匹配版本拒绝。候选固定support_status=unvalidated，无confidence分数，不构造现有Evidence，不判断主张语义支持、时效、覆盖或冲突。

独立CLI只读，无网络、模型、账本或文件写入，不迁移状态、不写ResearchMemory、不作跨任务复用决定。自动挑选片段或改写主张仍需后续语义提取与实质Validator；机械一致性通过不能成为PASS。

Evidence 是可定位的事实主张，非来源已证实的绝对真理。当前 Evidence 嵌套 Source，来源名称、URL、published_at（未知 null）、fetched_at、内容散列与快照在 Source 内；Evidence 另有竞品文本、维度、fact、quote、字符串 locator、confidence 与理由。它尚无独立 competitor_id、source_id、valid_until 或 verification_status，不能把目标设计当成现有 API。

confidence 是未校准质量信号，不能把 0.98 当作正确率。官方声明、用户评价、分析推断分开；用户评价只支持“某样本表达该体验”，不能升级成整体用户结论。搜索 snippet 不是最终事实证据。

价格必须记录币种、计费周期、计费单位、地区、税费／折扣条件及获取日期；缺失字段披露，不能直接进行数值比较。功能未提及不代表不支持。镜像、转载、同源转述不重复计独立证据。

Research QA 是进入 Analysis 前的强制机制，由 Validator 在 VALIDATING 内顺序执行 Evidence Validation → Coverage Assessment → Gap Analysis；最后一步是证据缺口诊断，不是竞争分析。先判断原文是否支持主张、时效和比较条件是否合格，再逐格评估足不足以回答研究问题，不能以 Research 返回成功或字段非空放行。

覆盖分母来自采集前版本化的必需且适用 competitor × dimension／field 单元及各自验收条件，不按页面数、Evidence 数或实际生成的任务数倒推。适用性待定的必需单元保留在预期集合并作为未决缺口，不能暂时排除来提高覆盖。一个维度的多个必需子问题全部满足才算整维充分；采集情况与合格证据覆盖分别记录。官方标签、来源数量、模型 confidence 或加权总分都不能代替逐格判断。来源类型应适配主张：官方定位可支持“官方定位为”，用户体验需相应样本，第三方猜测不能证明实际目标客户。

未找到、受限、失败和未核实推测不增加必需事实的合格覆盖；不适用须有可核查的适用性依据、规则与版本记录，不能因难查而删分母。适用单元为零不自动视为100%。PASS 仍须 coverage=1 且 gaps/conflicts 为空；仅三维合格的四维任务是3/4，必须补证或停止。非关键冲突可先缩小主张、标明边界后重新验证，不能缩小用户问题来消除缺口。无法补齐时保留研究诊断和缺口并 FAILED，不交付最终 report_path。具体标准与示例见模块契约；当前代码未执行这些语义评估。

### R05a 独立证据管理（待实现）

Source、Evidence、Claim 分别保存来源、原子事实主张、分析结论；稳定身份与不可变内容版本分开，关系引用具体版本。Source Manager 负责获取／处理记录，证据服务保存统一来源数据及证据／结论关系，不维护第二套相互冲突的来源元数据。字段、日期、空值和迁移以证据管理设计为准；现有 ID 及原始快照保留，不给旧数据补 verified、推测官方身份或未来有效期。

Evidence 必须带原文 quote、可核对 locator、来源版本、对象身份与维度定义／范围；content 与原文分开，单条 Evidence 绑定一个来源版本。ClaimEvidenceLink 支持多对多，区分支持、反驳、背景及关系限制；引用存在不等于语义支持，重复转载不增加独立支持。专业版年付只能证明存在这种订阅版本，不能证明全部版本仅订阅。

核验状态、时效状态、生命周期与冲突分别存储。支持判定绑定对象／口径、输入版本、策略、as_of、判定者及理由；核验通过不等于永远有效。valid_until 说明是来源明示期限还是版本化刷新策略，未知不代表永久有效；collected_at 保留原文获取时间，不能改成导入或当前时间。confidence 不是正确率；source_type 不是可信度，评级要记录身份、第一手性、方法、独立性及适用问题，访问限制不等于来源不可信。

冲突须记录具体版本、可比条件、差异与处理历史；月付／年付选项和不同生效时间不自动判矛盾，不按高评级、新日期或多数票静默选边。过期、撤回或来源变化可使当前结论待复核；传播时沿反向关系查询报告片段，保留原报告与旧判断，不删除证据或改写历史。剩余一条有效引用不自动证明结论仍成立。

报告段落、列表项、表格单元有 report_version、segment_id、文本摘要、位置和 Claim 版本映射，可向前追到原文，也可从来源／证据反查结论与报告。改写、拆分或新增语义后重新核对，页脚链接或行号不能独自代替映射。这些是后续验收要求，本轮不改变存储或生产状态。

## R06 Planning–Execution–Reflection 闭环

Reflection 是核查向同范围补证或范围调整的结构化反馈。默认单对象同范围补证直接继续；可选项目锁定范围内也无需新增泛泛确认。实质范围变化返回对应询问或项目评审，反馈含缺口、冲突、目标字段、补证动作和停止理由。

Planner 可在采集前识别完成目标所需的信息；Validator 在采集后给出实际证据缺口。补证反馈须可定位对象、维度、受影响证据、原因和验收条件，Planner 据此提出修订计划，Orchestrator 核对计划版本及预算后执行。计划版本不能被子代理改写；恢复保留原任务与调用标识，不因新计划或关联任务自动重置耗尽额度。

Gap Analysis 区分缺失、仅推测、支持不足、时效失效、口径不齐及未解冲突，保留已尝试来源、建议补证动作、优先级与完成条件。需要补证不等于允许无限补证：Orchestrator 结合剩余预算、访问限制和有效进展决定继续或停止；Planner 只为相关缺口修订任务，同范围无需再确认。补证返回后用当前合并材料重新执行 QA，并绑定范围、计划、证据、核查策略和核查时点；不能绕过质量关卡或沿用旧 PASS。首次已经满足全部条件时直接准入 Analysis，无须为流程形式再搜索。

目标研究预算为最多3轮、搜索30次、抓取60次、LLM40次、活动时间600秒，均为起始工程配置，尚非性能承诺。目前独立搜索／抓取账本分别实施每任务30／60次上限，其他全局预算和无进展终止尚未接入。联网前持久预留，失败也消耗额度；不能靠重启或另建工具实例重置同一任务计数，搜索与抓取数据库标识不同，不能混用。其余执行器接入时，补证与重试也须累计，至少一项先到上限就停止新增调用并披露未完成项；每轮没有新证据则停止 NO_PROGRESS。只有用户明确提高有限预算才可续研。

当前公开搜索最多尝试1次，无隐式重试。验证码、HTTP 403／429、限流及访问限制立即返回 SEARCH_ACCESS_RESTRICTED 并停止，不尝试其他入口、代理或验证绕过，不把限制当作零结果。参数／权限错误零网络执行。未来其他只读工具若设置重试，须显式定义有限次数并受剩余预算约束，SDK 重试不得叠加；搜索的当前停止策略不能被通用重试覆盖。

## R07 Memory 与恢复

Conversation Memory 为短期对话；Research Memory 为 Brief、Plan、Source、Evidence、Analysis、历史报告与来源快照。保存的是研究资产，不能仅保存聊天后宣称支持研究记忆。

目标生命周期为 active → archived；当前只保留字段。MemoryStore实际保存同任务的最新snapshot与状态events，revision用于并发检查；commit覆盖当前snapshot，events仅含task/revision/state/time，不能重建旧Evidence版本，memory_reference也未形成检索。ResearchMemory.sources/evidence字段与独立Source文件不构成跨任务资产目录。Phase 6 的检索、版本历史、时效检查与增量更新尚未实现。

当前任务的 Source／Evidence／Claim 版本、关系与判定记录可先按 R05a 实现，为研究链提供数据基础；这不等于替换 MemoryStore 或完成跨任务自动检索与复用。数据库采用规范化表、外键和反向索引即可，当前无需引入独立图数据库。

任务、记忆和事件原子提交，revision 做比较并交换，拒绝过期写入；未知 schema 版本拒绝加载。第一阶段的恢复不会执行研究工具，故不宣称有副作用 exactly-once。独立搜索／抓取使用分开的调用账本保存任务额度、调用意图与完成结果：请求标识绑定任务及参数，已完成调用重放本地结果或安全错误；已预留但未完成的调用不自动重发，避免进程中断和并发造成不明重复请求。抓取成功重放还须重新加载并核验快照，丢失、篡改或未知版本时停止，不自动补抓。账本与任务 MemoryStore 分开，不据此声称全局工具恢复、业务状态协调或分布式租约已经实现。

后续追问关联新任务，先对齐实体、维度、地区、产品版本、时间与计费等可比口径，再检索候选资产。资产需保留origin_task、原Source/Evidence、原文／正文散列、提取器／Schema版本、fetched_at与更新链；口径或版本不兼容不能直接复用。价格等易变维度按策略过期后刷新，来源内容变化产生新Source/Evidence版本及supersedes，历史报告仍引用旧版，不覆盖历史。

TTL内也不能把旧证据直接标为本次检索已核验。保留原fetched_at，另存revalidated_at、核验动作与依据；不能给旧Evidence重贴本次日期或沿用旧PASS。刷新受限、失败或预算不足时保留旧版与“未更新”缺口，停止新增调用；项目之间隔离，不能混入背景、范围或不兼容批准。上述是后续验收要求，本轮未实现资产目录、自动复用或增量更新。

### R07a 多轮研究与增量修订（待实现）

逻辑研究、业务修订和执行任务分开：research_id 聚合同一研究，业务修订绑定基线／变更／范围与资产清单，task_id 标识一次执行，plan.version 标识计划，Memory revision 只作 CAS。研究会话不强制对应 projects/ 项目。现有 TaskRequest 只有 user_input，resume 不接新输入，新 run 不关联前任务，report_refs 字符串不是版本库；这些能力须单独实现和迁移。

变更记录保留用户原话、可信消息引用、请求 ID、base_revision、预期当前版、明确的对象／维度／时间／背景／呈现差异及授权。对象消歧、维度定义和对象范围须明确；“重点看 C 私有化部署”不能自动变成所有对象全部维度重采，也不能把专属租户当成已支持私有化。项目新范围须新版名单与维度锁，现有一次性评审拒覆盖，不能删旧锁或复用旧 token。

影响集合按依赖传播到研究单元、比较、Claim、决策和报告片段，包含新增对象对排名／总体摘要以及新证据对已有冲突的影响。依赖未知时扩大相关核查并说明原因，不能假定无影响；扩大分析检查也不自动授权扩大联网范围。删除对象只移出当前版，不删除历史证据与报告。

每个单元明确保留、复核、重提取、刷新、新采集或不在本轮范围，每个分析／片段明确重算或重排及原因。保留旧成果须核对实体、维度定义、口径、原文、提取／策略版本和适用时间，记录本轮采用及核验依据，原获取日期不变。旧 not_found 不是永久不存在，TTL 也不等于本轮核验。全体新增维度只补该维度缺口，局部加深保留显式对象范围；不能为少采而将缺口标不适用。

差量执行后按当前完整范围重算必需分母、覆盖及跨来源冲突，绑定新修订／计划／输入。兼容且仍有效的逐条核查可经采用检查复用，不原样复制旧全局 PASS。相关分析重算后新 Claim 仍须核查，不能只在旧报告末尾追加新对象就宣称更新完成。

运行中变更先登记并在安全边界协调，不原地改正在执行的计划。当前 v1 的 RESEARCHING 无直接回 PLANNING／WAIT_CONFIRM 的边，ANALYZING／REPORTING 无回退；v2 按 R02a 的范围等待和票据边执行，终态不重开。无法合法衔接则保留实际成果、按未来停止协议经现有 FAILED 出口结束旧执行，再建关联任务；不能伪造完成或验证判定。迟到结果保留原修订／调用归属，采用到新版需重新核对。

同一变更请求幂等，改参不可复用请求 ID；业务基线与当前版分别做并发检查，防止两次修改相互覆盖。新 task_id 或修订号不重置已消耗预算、失败记录、访问限制和无进展约束；有用户依据的新增工作可以记录有限增量预算，不默认无限重开。

工作中修订与已发布报告引用分开。报告、资产清单和更新说明写新版本，核查／回读／当前基线检查成功才更新发布引用；失败保留旧版、原时点和本次未更新诊断，不把旧报告伪装成新成果。更新说明列新增、变更、移除、复用、未刷新及原因和受影响结论；纯格式／读者变更保留事实 as_of，不重贴来源日期或暗示本次重新取证。具体存储、状态边界和验收以多轮研究设计为准，本轮不新增执行能力。

## R08 分析、报告和安全

Evidence 先于 Analysis。分析分为事实、比较／差异／SWOT、机会，每条推断引用 evidence_ids 并披露限制。机会是待验证假设，不能输出无依据的市场规模或用户需求。

Research QA 只核验 Analysis 输入，不能自动证明后生成的 Claim。Analysis 交付前需用 Validator 语义能力核对具体 Claim／Evidence 版本的支持关系，Reporter 再检查片段措辞；由 Orchestrator 安排当前模块内的有界检查，不隐式添加状态回退。无法消除的语义缺口沿现有 FAILED 出口处理，不能以关系外键完整替代支持判定。

Analysis 按当前目的选择定位、功能、定价、客户、商业模式、优势、劣势、机会、威胁与差异化能力，输入与完成标准见分析引擎设计。十类是能力集合，不强制每次输出十章；用户明确要求的必需目标不得静默删除。产物必须体现证据如何支持比较、解释及决策影响，不能只把采集表改成段落。SWOT 是可选组织方式，空标签不算分析。

定位区分官方目标与实际客户；功能比较保留场景、深度及支持条件，未提及不判不支持；价格归一保留地区、版本、周期、席位／用量、税费和折扣，公式与全部输入可复验，价格区间限定为已核验版本及口径，不能冒充全产品区间或总成本。客户案例不证明总体行业分布，公开收费方式不证明收入占比或盈利；优势劣势需明确相对于谁、针对什么任务和评价标准。

市场空白、竞品短板和少量抱怨只可能提供机会线索；未满足需求与付费意愿需要相应证据。威胁须说明竞争动作、暴露的客户／场景、影响机制、时间窗、触发信号、反证及应对条件；不把热度、融资、匹配分或功能数量直接换成威胁等级或概率。没有数据就保留影响大小和发生概率未知，不能虚构流失／收入预测。

差异化建议须对应明确决策，保留证据／反证、推理、适用前提、可选行动（包括暂不行动）、价值假设、成本／风险／依赖、优先级理由、最小验证及反转条件。目标指标和阈值注明来自用户、基线或待确认的实验建议，不能冒充实测；未知投入不编估算，未知权重不重算成确定排名。核查建议依据与逻辑不等于证明未来效果，不自动批准执行路线图、降价或实验。

默认无我方背景时可以给对象画像、条件性市场影响及待验证决策问题，不编我方产品或优势。只有用户要求我方建议才使用已有背景并按需每轮补 2～3 题，不强制 profile／初始化；我方目标、能力和约束标 user_provided、时间及版本，可作为明确前提，但实际领先或赢输仍需双方依据。缺必需背景时说明该建议不能成立，不以通用结论冒充完成。背景变化重评受影响建议，未变事实不自动作废；项目背景变更仍遵守锁规则。

Reporter 只组织已验证 Analysis。通用底稿包含研究摘要、范围与方法、竞品定位、维度对比、差异／SWOT、机会假设、冲突与资料缺口、来源；选定读者后采用对应视图结构，完整底稿可作附录。维度按行业与品类适配，不强制 AI，也不强迫一页 Battlecard 装入全部通用章节。

Reporter 生成草稿并修复属于呈现层的问题，独立 Report QA 负责交付质量评估，Orchestrator 决定返工及准入。格式或缺引用标记可在当前模块内有界修复；新增事实问题不能靠改措辞消除。现有 ANALYZING／REPORTING 无上游回边，未升级前仍停止未解决问题；R08a 明确报告阶段未来的受控返工，部分成功报告不在本次扩展中。

Codex 实际报告可保存到 research/<安全对象标识>/<运行标识>/report.md 与 sources.md，避免覆盖历史。未来 Python 产物由任务ID隔离并检查清单后才 COMPLETED；当前生产CLI不生成业务报告。测试替身生成的参考报告须标SIMULATION／合成场景，仅写tmp_path，不进入业务research/projects，也不能据此宣布Reporter已实现。密钥不入 Prompt、资料、数据库、日志或报告；异常只显示安全错误。第三方模型上传资料前遵循实际授权和来源范围。

### R08a Report QA 与受控返工（待实现）

Report QA 独立于 Reporter 的生成调用，可复用 Validator 语义能力；Reporter 自评、完整 Research QA 或 Claim 引用合法均不能替代报告检查。代码负责完整性、版本、计算与准入，语义评估须保留依据并用独立参考案例验收；换一次模型调用不保证判断正确。

九项检查必须覆盖当前报告全文、摘要、表格和脚注：有效维度是否回答、重要事实是否有证据、事实与推断是否混淆、是否不当重复、是否同口径前后矛盾、时效是否符合问题、数字是否有来源或可复算依据、是否回应初始目的及有效修订、语气是否超出支持程度。不能只遍历已有 Claim 而遗漏新增无映射主张。默认单对象沿用已授权范围内的明确计划，不新增维度确认手续。

覆盖以用户目的／有效修订→问题／维度→Claim→报告片段的映射核对，空标题不算回答；缺必需证据不能仅写“未找到”就宣称研究完整。官方宣称、用户反馈、自述前提、事实、计算和假设分别表达；有来源不等于支持原文外的绝对结论。缩小措辞可修复转述越界，但不能把用户必需问题悄悄缩小以消除缺口。

重复检查保留有明确用途且忠实的摘要／视图重述，实际冗余按质量要求修复；冲突先对齐对象、地区、版本、时间和单位，不能删除反证。历史问题按既定 as_of 核时效，报告生成日不改事实日期。事实数字要有支持，派生数字要有公式和输入，实验目标与假设要有明确标签及来源；条目编号不是事实数字。不能靠关键词黑名单判定矛盾、重复或过度确定。

ReportQARequest／Result 和 ReworkTicket 是未来契约。收据绑定目的／维度／研究修订／scope／plan、草稿版本与散列、片段映射、Analysis／Claim／Evidence／Source、已有核查、读者要求、策略和 as_of。问题逐条记录规则、位置、引用、实际／期望、原因、责任与修复验收条件。检查未运行、不确定、输入过期或实际违规未解决均不得 PASS；严重程度只安排修复顺序，不能用平均分或低严重度豁免必需质量要求。

按根因定向处理：已有正确内容漏写、重复或误抄交 Reporter；证据足够但计算／推断错误交 Analysis；原材料需重核交 Validator；缺证据、需刷新或目的映射漏项交 Planner 安排 Research。多问题先修上游依赖，未解决项保持开放，不能修完格式就关闭证据问题。缺陷关闭须有新版本和复检依据，不接受模型自报“已修复”。

v2 从独立 REPORT_QA 返回 GENERATING_REPORT／ANALYZING／VALIDATING／PLANNING，由 Orchestrator 核对当前失败收据、票据、路由理由、输入版本、授权范围、剩余预算和返工轮次后持久化。Analysis 路由须当前 Research QA 仍有效且材料足够；Validator 路由只先复核已有材料；补证由 Planner 形成任务后经 Research 与完整 QA。呈现返工经 GENERATING_REPORT 产生新稿后再 REPORT_QA；不新增直接回采集捷径。

修复生成新草稿／分析／核查或计划版本，失效依赖重新核对。所有路径最终重渲染并完整 Report QA，不能只复测上次失败项；纯格式变更可沿用匹配的研究依据，但必须检查新报告。新回边不授权 ANALYZING 任意回退，不扩大范围；超出已有授权仍按范围修订／项目锁处理。升级前不直接执行这些边，终态保持不可重开。

返工上限在运行前明确配置，返工轮数与研究补证轮数分开但共用全局搜索／抓取／模型／时间预算及访问限制；不因重试、新版本或关联任务重置计数。实际缺陷被消除或获得必要依据才算有效进展，换措辞与分数上涨不单独算进展；无法修复、预算到限或持续无进展时 FAILED，保留问题与诊断，不交付不合格报告。

完成守卫须核对当前完整 Report QA 合格、未解决违规为零、草稿及依赖未变、实际文件读回匹配并通过发布基线检查。写入后内容改变使原质量收据失效，文件存在或退出0不能代替这些条件。候选稿和旧报告保持独立版本，新版失败不覆盖已发布报告，也不能把旧报告登记为本次成功路径；历史状态迁移不补默认 PASS。

## R09 工程与验收

当前代码兼容 Python 3.9+，在本机3.9.6验证；建议后续环境使用3.11+并在 CI 验证。Pydantic v2，src 布局，pyproject.toml，隔离环境与已解析依赖快照。

每模块配确定性离线测试；状态机验证全部状态对，工具验证输入／输出与权限，存储验证事务回滚和重启。真实抓取和模型测试单列，未执行记 not_run。不把结构测试通过宣称为竞品结论准确或全行业能力已验证。

验收按 [分层说明与场景矩阵](../../docs/acceptance.md) 区分真实组件集成、测试专用参考工作流和真实生产端到端。参考工作流可以从brief连接到受控临时报告，但未实现模块必须显式列为测试替身，网络与事实采用合成夹具，不调用真实模型。HTTP I/O替换与已知socket／subprocess入口的monkeypatch guard用于阻止误联网，是Python层测试检查，不是操作系统沙箱或所有旁路的拦截保证。替身PASS只表示选定场景按oracle通过，不能替代来源支持、时效、自动冲突识别或报告语义质量验收。

参考报告采用临时文件完整写入后独占发布，拒绝覆盖已有工件；对部分写入失败和最终Memory提交失败做故障注入，检查清理本次半成品／已发布报告及引用、内存状态不先于成功提交进入COMPLETED。这里只验证测试协调器的所测异常，不声明生产交付、跨资源原子事务或任意崩溃恢复已实现。

“未找到／不适用／冲突”边界优先直接验证生产Schema与状态guard：只访问失败不算查找后未找到，不适用不能绕过字段许可与理由，显式冲突／缺口不能被构造成PASS或推进分析。测试给定冲突不是自动发现矛盾；理由和查找记录结构合规也不证明它们真实、充分。系统验收须同时保留生产入口仍未就绪的回归，不通过测试文件暗接生产执行器、修改状态或伪造批准。

SaaS／工具类可显式选用 [推荐配置与采集指南](../../codex-skills/steal-her-heart/references/saas.md)。只有用户选择或实际资料确认适用时才采用，不把产品名称、本地词表或“工具”字样自动当作行业事实；未知品类仍沿用通用选择。预设的核心子集、专项字段、P0／P1／P2、采集问题和源提示是建议，不要求每个SaaS都有API、免费版或认证。

包内JSON为预设维护单源，运行技能的同字节副本须校验一致。加载时检查字段、源ID引用和优先级完整性；每个模板字段恰一份采集定义，核心字段约束不可削弱。`preset saas`不创建业务项目、不锁范围、不执行采集；已有项目采用字段时仍经正式名单／维度提案与锁定，附加采集元信息没有自动绑定进旧锁。推荐配置或其散列都不构成用户批准。

评价样本检查仅处理调用者提供的URL、日期、评分、公开角色／规模、激励／验证标签、原文等元信息，检查时间窗、重复和平台／评分分层覆盖。来源无法访问、字段未知和采样不足均保留缺口；相同链接去重，跨平台相同文本标疑似重复，两个域名不自动独立。默认365天、每平台每评分段目标3条是工程建议，不具统计代表性；不能用主动分层样本估总体评分、投诉率或赢输。检查保持facts_validated=false，不发PASS、不自动抓取／刷新，也不证明链接原文支持主张。Research／实质Validator仍需独立实现。

## R11 四类读者视图

按 [读者视图规范](references/audience-views.md) 和可选 ReaderProfile 输出，不硬编码角色集合；未指定读者时给通用报告，不以缺少配置阻断分析。已有四类仅为预设：产品经理关注能力矩阵、差距、趋势和路线图；销售领导关注格局、价格、赢输和资源选择；普通销售优先一页 Battlecard；运营关注渠道、内容活动、促销、引导／成功与增长实验。视图可选一种或多种，也可定义投资人等新角色；共用证据版本。配置不是多用户账户；采集阶段允许每对象一子代理。

Battlecard 的三个对方卖点、三个我方优势必须有依据，不足则 draft＋具体缺口。对方卖点绑定该竞品证据，我方优势绑定双方证据，真实客户引语有记录；假设表达标“可能”。探测问题不预设未证实缺陷，“不能说”同时给原因和替代表达。

我方矩阵、价格空间与赢输归因缺少背景时不得编造；未知不当“没有”，有功能不当“领先”。趋势按品类相关性选取；增长玩法与路线图为待验证建议，不自动执行、不等于已批准需求。内部成交信息与可对客表述区分。

one_page 是版式目标。结构 ready 不等于语义、时效、外发授权或一页排版已通过；Phase 5 在选定输出介质上验收分页与可读性。当前仅有契约，不生成角色报告或 Battlecard 文件。

## R12 统一命令入口

遵循 [命令规范](references/commands.md)。/analyze 只需单个竞品名；/battlecard 在生成我方回应和优势前需要必要我方信息；当前 /brief 需要周期与研究资产范围，不要求我方产品；目标即时简报语义见产品规则修订，尚未迁移。常见自然语言映射到同一结构，当前未指定周期不猜测，实体消歧仍由理解阶段处理。

路由不执行工具链或改变状态。当前统一返回意图、澄清／未接入状态及空产物路径；parsed 不能当作研究成功。原文按数据传给工具，不经 shell 插值。周报／月报请求不授权定时任务或监控。后续执行依赖既定模块，不绕权限和确认规则。

pending_module必须说明当前完成的只是解析／任务保存，并附guidance：具体缺失能力、当前可执行的下一步及适用时的Codex提示。对analyze、battlecard和brief分别说明所需材料，不把重新初始化或重试说成补齐执行链的方法。人类提示写stderr，stdout保持单份JSON；保留原状态、退出码、空产物和恢复行为，guidance不得制造报告或批准。

## R13 采集子代理

按 [任务调度设计](../../docs/task-scheduling.md) 由 Planner 生成独立 ResearchTaskSpec，主控分配 WorkerAssignment，Worker 返回逐任务结果，接纳后交 Validator。任务须明确对象、问题、输入、允许动作、依赖、预算及完成条件，不仅按竞品名称启动。Worker 使用 ResearchAgent 契约，一对象可拆多任务，一个 Worker 可先后处理不同对象；对象分组只是可选调度偏好。

主控核能力、权限、版本、依赖和预算后，从有界就绪队列派发，原子认领及租约防重复分配。Worker 上下文与写入位置每次隔离，只追加任务工件，不改总档案、名单、维度或批准。结果核任务／分配／epoch、工件与实际调用后汇总；结构接纳不是语义验证。v2 在 RESEARCHING／SUPPLEMENTING 汇集本轮状态后进入 VALIDATING→GAP_ANALYSIS，局部 PASS 不准入全局分析；需要已核验事实的后续采集交合法后续批次，不在本批形成等待死锁。

不同重点不取消已确认的共同维度；专项请求可非对称，但报告须说明未研究范围。项目仍使用同一锁定模板，Worker 仅返回分配问题子集，由汇总层构造完整对象结果。失败只影响本任务和依赖，重派先核旧调用和租约，保留其他成果和已用预算；换 Worker 不绕过访问限制。

当前可通过本地终端桥接准备带锁快照的 CollectionJob，未实现代理启动、并行调度或持久任务状态。该终端渠道不认证 Codex 聊天回复，不能把内容散列或自填批准记录当作认证。后续宿主接入仍须落实可信用户来源、执行账本和持久化审计。

## R14 可选项目文件与输出质量

只有显式选择项目才读取 projects/<项目标识>/profile.md 与 dimensions.md；缺少或未完成时提示处理该项目。默认单对象不读 projects/default，也不创建虚构项目。项目背景全文摘要继续绑定该项目的任务／发现批准；无项目任务库默认 .steal-her-heart/memory.sqlite3，绑定项目则使用其 .state/。

每条事实使用本次检索来源及获取日期，训练记忆只作线索。区分官方宣称、第三方和用户反馈，冲突并列；价格／版本／数据带日期和可比条件，判断给依据。

有用户目的时回应目的；无额外背景时声明通用范围，输出画像、研究结论、适用边界和待验证问题。只有请求我方对照且背景足够，才输出我方意义、优势和赢输。多视图共享事实。当前结构／文件检查不证明语义或本次检索真实性，仍需实际工具和核查证据。

## R15 项目配置单源与兼容

可选项目的新 profile.md 以 [用户标准模板](../../src/steal_her_heart/templates/profile.md) 的可读 Markdown 业务字段为唯一来源，可手工填写；程序不得同时维护一份隐藏业务 JSON 而忽略用户修改。示例仅作注释，空模板或核心字段未完成不能视为初始化通过。

多行业保留 industry 原文并给出 industries 列表，不强制归入单一垂直领域。价格区间与特别说明可空；明确未知保留不确定性，不补价格、币种、周期或“无监管限制”等结论。读者逐行有角色、关注点和期望格式，复用 ReaderProfile.output_style；缺列追问，不自动填四类角色。

新访谈 schema_version=2，旧 schema_version=1 的9题记录与旧 JSON profile 保持兼容读取，不覆盖既有档案。缺失新增字段不等于已回答，也不意味着已确认无价格或无约束；原始旧空稿可在访谈完成后写成新 Markdown。文件变化仍使旧任务／批准摘要失效。

特别说明中的信息源排除、监管和语言要求是后续执行约束，不扩展工具权限，不覆盖仓库铁律。保存这些文本不证明已实现过滤、合规判定或语言质量验收，真实采集／输出模块接入后还需验证。
