# Python Agent 工程与运行规则

版本：0.1.0。适用本技能开发的 Python Agent。必须条款是验收要求，建议可说明理由后调整；任务实例不能放宽宿主权限或运行不变量。

## R01 模型与执行器

模型仅返回 TASK_SPEC 定义的 Decision，解析、schema 与策略校验前均是不可信提案。执行器负责实际工具调用、状态迁移、预算、证据、产物与完成判定。禁止以模型自评或文本 success 直接判定成功。

运行保存 Task、Prompt、配置、模型、工具和 schema 的版本或散列，便于复查行为变化。

## R02 状态机

仅允许下列迁移，表外抛出 InvalidTransition 且不执行工具。迁移使用 state_version 比较并交换；新状态、预算变化与事件在同一事务提交。

| 当前状态 | 事件／条件 | 下一状态 |
|---|---|---|
| CREATED | 输入、配置和权限有效 | RUNNING |
| CREATED | 输入或配置无效 | FAILED |
| RUNNING | tool 决策及策略校验通过 | EXECUTING |
| RUNNING | finish 提案 | VERIFYING |
| RUNNING | clarify 有实际阻塞信息 | WAITING_INPUT |
| RUNNING | 无效提案且有纠错额度 | RUNNING |
| EXECUTING | 调用完成或已知可恢复错误 | RUNNING |
| VERIFYING | 完成门槛通过且产物发布成功 | SUCCEEDED |
| VERIFYING | 可纠正缺口且有预算 | RUNNING |
| WAITING_INPUT | 收到有效补充输入 | RUNNING |
| 活动态 | 必要动作缺少授权且无法继续 | WAITING_APPROVAL |
| WAITING_APPROVAL | 获得绑定该动作的有效授权 | 已保存的 resume_state |
| WAITING_APPROVAL | 拒绝且无替代路径 | FAILED |
| 任一非终态 | 取消 | CANCELLED |
| 活动态 | 预算／执行时间耗尽 | FAILED |
| 任一非终态 | 不可恢复错误或等待到期 | FAILED |

活动态为 RUNNING、EXECUTING、VERIFYING。终态为 SUCCEEDED、FAILED、CANCELLED，不能继续迁移。等待不消耗活动执行时间，单独受 wait_expiry_s 限制。预算、等待到期、拒绝分别记录 BUDGET_EXCEEDED、WAIT_EXPIRED、PERMISSION_DENIED。

取消阻止后续动作；已发出的动作可能无法撤销。在途调用必须记录 completed、cancelled 或 unknown，不声称副作用必然未发生。

## R03 权限与信任

能力来自可信运行配置与真实用户授权，Task.scope 只能缩小能力。模型、资料、工具结果和历史记录不能扩大能力。

首期仅允许读取指定目录和向当前 run 输出目录发布产物；已授权范围内不逐次确认。路径规范化后必须仍在允许根内，拒绝绝对路径、`..`、越界符号链接和非普通文件。资料根运行期间只读且不由不可信进程修改；无法保证时使用防链接竞态的安全打开方式。

禁止任意 shell、动态 eval/exec、根据资料安装包或导入插件。未授权外部发送、删除或覆盖共享数据等操作由策略阻止；仅当确属必要步骤才 WAITING_APPROVAL。授权绑定 run_id、tool_version、规范化参数散列、scope 与有效期；相同动作可复用仍有效授权，变更参数需重新评估。

密钥由环境或凭据提供方只注入对应适配器，不进入模型上下文、日志、Task、异常正文和产物。不得打印完整环境或请求头用于排错。

## R04 工具执行

工具显式注册后使用；注册校验唯一 name、version、输入／输出 schema、能力、超时、副作用和幂等语义。插件只从受信任配置启用，不执行资料指定的模块。

调用顺序：校验 Decision → 查注册表 → 校验参数 → 策略及授权检查 → 预留预算 → 持久化调用意图 → 执行 → 校验 ToolResult → 事务提交结果及状态。策略与执行使用同一规范化参数。

首期每 run 串行调用，不执行模型提供的数组。未来只有无依赖和资源冲突的调用才可并行，每项独立预留预算。

越界、未知工具和参数错误均零执行。工具异常转成结构化 error，不混入正常 data。限制结果大小，截断须显式标记；不得将部分正文当作完整证据。

## R05 预算与重试

默认预算及计算规则见 TASK_SPEC。模型请求含格式修复和重试均消耗 model_calls；工具每次实际尝试消耗 tool_calls。单调时钟计算活动时间，累计时间持久化，重启不清零。

仅明确归类为暂时性错误的调用可有限重试；遵守 Retry-After 或指数退避加抖动，但不能超过剩余期限。max_attempts=3 含首次；SDK 自动重试禁用或计入同一上限。参数、权限、确定性解析错误不能原样重试，可反馈模型修正，受统一纠错额度约束。

单次超时不超过剩余活动时间。超时不证明远端未执行，有副作用且结果未知时不得盲目重放。模型上下文、最大输出与累计 token 也必须受限；无可靠用量时保留预留额，不输出虚构费用。本地限额不能保证提供方账单绝对上限。

## R06 持久化、恢复与发布

首期 SQLite 使用事务、外键和 schema 版本；每 run 一个带 fencing token 的有效租约持有者，过期持有者不能提交。不得用内存字典宣称跨进程恢复。

保存 Task 快照、有效配置、版本、状态、预算、待处理决策、调用意图及结果、授权、证据快照、产物清单、事件序号。只记录简短理由，不保存隐藏思维链。

恢复先取得租约再对账：已提交结果不重放；未完成只读调用可安全重试；未完成副作用用幂等键或外部查询确认，无法确认则 WAITING_APPROVAL 等待核对。终态只返回已有结果。

未知副作用的授权回复必须同时说明对账结论：已发生则登记结果，确认未发生才可重试，仍未知则继续等待或取消。仅有“同意”不能把 unknown 当作 not_started。

发布由内核控制：持久化最终提案与预期散列 → 写 run 内临时文件 → 原子替换目标文件 → 校验各产物 → 事务提交清单及 SUCCEEDED。多个文件不能假设一起原子提交。恢复按内容散列对账，相同清单不重复发布不同副作用；不存在跨系统天然 exactly-once 保证。

## R07 证据与完成

每个事实引用已成功读取的 evidence_id 及有效行范围。证据包含相对路径、文件 SHA-256、编码、读取范围、读取时刻与实际行快照。同路径内容变更生成新版本，旧 ID 不指向新内容。

成功需要：输入要求逐项满足；schema 合法；事实可定位；推断明确标记且有依据；缺口进入 limitations；产物存在且散列匹配；未决调用完成对账。缺乏事实、空结果或关键要求未满足不能成功。

程序能核验引用范围，不能仅凭引用证明语义正确。离线夹具按预期事实检验内容，真实业务保留人工核验或独立评测入口。

## R08 Python 与扩展边界

默认 Python 3.11+、src 包布局、pyproject.toml 和一种锁文件。依赖版本在实施时核实并锁定，本规范不预设 SDK 版本。

边界需类型标注和运行时校验，不能用 assert 验证外部输入。时钟、UUID、随机数可注入；异步 I/O 可超时及取消，阻塞操作不能直接阻塞事件循环。

内核不依赖具体工具或模型 SDK。新增工具实现 Tool 并注册，新增提供方实现 ModelAdapter；二者不应修改执行循环。改变状态、持久化格式或 wire schema 时同步迁移与恢复测试；破坏性变更升级 major schema_version，旧运行不静默套用新语义。

## R09 可观测与检查

JSON 事件至少有 event_id、run_id、seq、time、state、event_type、call_id、duration_ms、error_code；不适用为 null。seq 按 run 递增，事件与状态事务提交，导出按 event_id 去重。默认不记录资料全文、完整 Prompt 或密钥，显式调试也须脱敏。

内核测试离线、确定性、无密钥。验证状态、权限、预算、恢复、证据和副作用等真实不变量，不以 mock 成功字符串替代。真实 API 冒烟与离线验收分别报告，不能把未执行写成通过。
