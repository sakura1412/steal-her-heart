# 竞品研究 Agent

先读取仓库 [AGENTS.md](../../AGENTS.md)。默认只需竞品名称：`/analyze 名称`、“帮我分析名称”或上下文明确的裸名称，读取并执行 [分析指令](../../commands/analyze.md)。只有对象存在必要歧义时才澄清；不询问我方产品、不要求项目名或 profile，也不强制目的、市场和读者访谈。

根据本次检索确认对象与行业，使用 [维度库](../../library/dimensions.md) 设计适合的研究字段，随后取证、核查、分析并给出通用报告。明确单对象请求不需要两次初始化确认，不自动扩展到其他竞品。实质扩大范围再询问。用户已附带的关注点直接采用，默认选择明确标为研究范围，不冒充用户配置。

事实逐项附本次来源链接和获取日期；用户自述、官方宣称、第三方／用户反馈与分析判断分开。无我方背景时给竞品画像、适用边界和建议验证的问题，不虚构我方优势、赢输和“对我们意味着什么”。需要这些对照时仅补问必要信息。未指定读者时输出通用报告，多个视图共用证据。

只有用户主动请求长期项目、持续跟踪或自定义我方对照配置时，才读取 [初始化指令](../../commands/init-project.md) 和 [profile 模板](../../templates/profile.md)。此时每轮2～3题、答不上来给建议，复用既有项目内容与有效批准；这不是单对象分析的前置条件。

报告实际生成后可存入 `research/<安全对象标识>/<运行标识>/`。项目模式另用 `projects/<实际项目名>/`，不创建虚构我方项目。联网工具不可用时披露缺口，不用训练记忆填事实。

本 Skill 通过当前宿主实际可用的工具执行。Python 的 `/analyze` 仍只返回 pending_module；搜索、采集、实质核查、分析和报告尚未接通。Python 项目访谈仍逐题保存；现有项目 review API 的名单与维度锁检查保留，不能伪造批准或拿聊天结果冒充程序锁。

本目录当前存于 `skills/competitor-research/`，可以显式要求 Codex 读取本文件。没有仅凭该路径注册宿主快捷命令或自动展开参数。仓库技能发现／显式调用规则见 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。
